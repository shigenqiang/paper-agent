### 2.2 写作工作流完整链路 (核心路径)

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                        写作工作流 (Writing Workflow)                             │
└─────────────────────────────────────────────────────────────────────────────────┘

[1] memory_recall ──────────────────────────────────────────────────────────────┐
    功能: 检索前召回历史记忆                                                      │
    输入: user_id, query                                                         │
    处理: EnhancedMemorySystem.recall(top_k=3)                                  │
    输出: 增强查询 (原始query + 历史记忆上下文)                                    │
    │                                                                            │
    ▼                                                                            │
[2] crawler ───────────────────────────────────────────────────────────────────┐
    功能: 多源论文检索                                                            │
    数据源: arXiv, PubMed, Semantic Scholar, OpenAlex                           │
    处理: 并行搜索, 结果合并                                                     │
    输出: 原始论文列表 (papers[])                                                │
    │                                                                            │
    ▼                                                                            │
[3] selector ──────────────────────────────────────────────────────────────────┐
    功能: 论文质量筛选                                                           │
    处理: LLM评分 (相关性 + 质量 + 新颖性)                                       │
    输出: 高质量论文列表 (selected_papers[], top_k=20)                          │
    │                                                                            │
    ▼                                                                            │
[4] multimodal (可选) ─────────────────────────────────────────────────────────┐
    功能: 多模态分析 (论文图表理解)                                               │
    处理: 图表提取, 内容分析                                                     │
    输出: 多模态特征                                                             │
    │                                                                            │
    ▼                                                                            │
[5] kg (可选) ─────────────────────────────────────────────────────────────────┐
    功能: 知识图谱构建                                                           │
    处理: 实体关系提取, 图谱构建                                                 │
    输出: 知识图谱数据                                                           │
    │                                                                            │
    ▼                                                                            │
[6] outline ───────────────────────────────────────────────────────────────────┐
    功能: 大纲生成 (LLM调用)                                                     │
    处理: 基于 selected_papers 生成论文大纲                                      │
    输出: outline (章节结构, 每节要点)                                            │
    │                                                                            │
    ▼                                                                            │
[7] writing ───────────────────────────────────────────────────────────────────┐
    功能: 内容写作 (LLM调用)                                                     │
    处理: 逐节生成, 引用标注                                                     │
    输出: draft (完整初稿)                                                       │
    │                                                                            │
    ▼                                                                            │
[8] review ────────────────────────────────────────────────────────────────────┐
    功能: 论文评审 (LLM调用)                                                     │
    处理: 质量评估, 问题反馈                                                     │
    输出: feedback (问题列表, 改进建议)                                           │
    │                                                                            │
    ▼                                                                            │
[9] evaluator ─────────────────────────────────────────────────────────────────┐
    功能: 自动评估                                                               │
    处理: 多维度评分 (逻辑性/完整性/创新性/格式)                                  │
    决策: 通过 → END, 不通过 → 返回 [7] writing 重写                             │
    │                                                                            │
    ▼                                                                            │
[10] memory_remember ──────────────────────────────────────────────────────────┐
    功能: 存储本次任务结果                                                        │
    处理: 记住 selected_papers, 任务类型, 用户偏好                                │
    输出: 持久化到记忆系统                                                        │
    │                                                                            │
    ▼                                                                            │
[END] 返回最终状态                                                                │
    包含: draft, selected_papers, trace_id, 性能统计                              │
    └────────────────────────────────────────────────────────────────────────────┘
```

```
│    短期记忆           │  │    会话记忆           │  │    长期记忆           │
│  (ShortTermMemory)    │  │  (SessionMemory)      │  │  (LongTermMemory)     │
│                       │  │                       │  │                       │
│ 范围: 当前任务         │  │ 范围: 任务内跨Agent    │  │ 范围: 跨任务持久化     │
│ 存储: 内存             │  │ 存储: Redis            │  │ 存储: PostgreSQL      │
│ 容量: 500条目          │  │ 容量: 500条目          │  │ 容量: 无限制          │
│ 特性: 任务结束清除     │  │ 特性: 自动摘要生成     │  │ 特性: 向量检索        │
└───────────────────────┘  └───────────────────────┘  └───────────────────────┘
         │                          │                          │
         └──────────────────────────┼──────────────────────────┘
                                    ▼
                    ┌───────────────────────────────┐
                    │    情景记忆 (EpisodicMemory)   │
                    │                               │
                    │ 范围: 执行轨迹记录             │
                    │ 存储: PostgreSQL + Neo4j       │
                    │ 特性: 时间线, 因果关系         │
                    └───────────────────────────────┘
                                    │
                                    ▼
                    ┌───────────────────────────────┐
                    │    统一记忆管理器              │
                    │  (UnifiedMemoryManager)        │
                    │                               │
                    │ 核心服务:                      │
                    │ - MemoryExtractor (LLM驱动)    │
                    │ - SummaryGenerator (自动摘要)  │
                    │ - EnhancedRetrievalEngine      │
                    │ - ForgettingController         │
                    └───────────────────────────────┘

记忆节点在 Workflow 中的集成点:

写作意图路由:
  router → memory_recall → crawler → selector → ... → memory_remember → END
                    │                                    │
                    ▼                                    ▼
            召回历史记忆 (Top 3)                  存储 Top 5 论文
            增强用户查询                        记录任务结果
            提供上下文                          积累用户知识
```

## 2. 核心服务详细分析

### 2.1 Redis (缓存服务)

```
当前内存: 3.4MB / 512MB (0.67%)
配置内存: 512MB
```

| 维度 | 分析 |
|------|------|
| **重要性** | ⭐⭐⭐⭐⭐ 核心必需 |
| **功能** | 会话缓存、向量缓存、限流、任务队列 |
| **依赖方** | paper-agent, 所有需要缓存的组件 |
| **故障影响** | 高 - 缓存失效，性能严重下降 |
| **替代方案** | 无（必须） |

**为什么必须**：
- LLM响应缓存，减少API调用成本
- 会话状态存储
- 限流器状态
- 任务队列（Celery等）

**内存估算**：
```yaml
# docker-compose.yml 配置
maxmemory: 512mb
maxmemory-policy: allkeys-lru
```
实际使用远低于配置，512MB足够。

---

### 2.2 Neo4j (图数据库)

```
当前内存: 475.6MB / 7.4GB (6.24%)
配置内存: 512MB heap + 256MB pagecache
```

| 维度 | 分析 |
|------|------|
| **重要性** | ⭐⭐⭐⭐⭐ 核心必需 |
| **功能** | 知识图谱、论文关系存储、GraphRAG |
| **依赖方** | paper-agent, literature_agent |
| **故障影响** | 高 - 知识图谱功能不可用 |
| **替代方案** | PostgreSQL + JSON (性能下降) |

**为什么必须**：
- 论文引用关系图构建
- 知识图谱增强检索（GraphRAG）
- 多跳推理查询
- 实体关系管理

**内存优化配置**：
```yaml
# 生产环境推荐配置
NEO4J_PLUGINS: ["apoc"]  # 插件
server.memory.heap.initial_size: 256m  # 堆内存
server.memory.heap.max_size: 512m      # 最大堆
server.memory.pagecache.size: 256m     # 页缓存
```

**当前问题**：原始配置要求2G堆内存，超出大多数开发机内存，已调整为512M。

---

## 8. 结论与建议

### 核心结论

1. **Redis 和 Neo4j 是核心必需服务**
   - 无替代方案
   - 必须首先启动

2. **PostgreSQL 是重要但可暂缓的服务**
   - 开发阶段可用SQLite替代
   - 生产环境必须

3. **监控服务是可选的**
   - 开发环境可跳过
   - 生产环境建议启用

### 最低启动要求

| 优先级 | 服务 | 原因 |
|--------|------|------|
| P0 | Redis | 缓存、会话、限流 |
| P0 | Neo4j | 知识图谱、GraphRAG |
| P1 | PostgreSQL | 持久化存储 |
| P2 | Prometheus/Grafana | 监控 |

**最小内存需求：~1.5GB（Redis 512MB + Neo4j 512MB + 系统 500MB）**
