## 1. 概述与背景

### 1.1 什么是意图识别

意图识别（Intent Recognition / Intent Classification）是指从用户的自然语言输入中，自动判断用户想要执行的操作或达成的目标。在 LLM Agent 系统中，意图识别是**路由层（Routing Layer）** 的核心组件，直接决定了用户请求被分发到哪个 Agent、哪条工作流、乃至哪个模型。

### 1.2 LLM 时代意图识别的新特征

| 维度 | 传统 NLP 时代（2018-2022） | LLM 时代（2023-至今） |
|------|-------------------------|---------------------|
| **核心方法** | 预训练分类模型（BERT、RoBERTa） | LLM 推理 / 语义向量匹配 / 级联混合 |
| **意图数量** | 10-50 个固定类别 | 开放域，可动态扩展至数百个 |
| **多意图** | 需多标签分类器，实现复杂 | LLM 原生支持多意图并行检测 |
| **冷启动** | 需要数百条标注数据 | 零样本 / Few-shot 即可启动 |
| **典型延迟** | 5-20ms | 1ms - 2s（取决于层级） |
| **准确率** | 领域内 90%+ | 通用场景 85-95%，细分领域可达 95%+ |
| **中英混合** | 需分别建模 | LLM 原生多语言支持 |
| **可解释性** | 注意力权重（弱） | 自然语言推理链（强） |
| **运维成本** | 模型训练 + 持续标注 | Prompt 维护 + 阈值调优 |

### 1.3 核心评价维度

1. **准确率（Accuracy）**：错路由的代价 >> 慢路由的代价
2. **召回率（Recall）**：能否识别所有有效意图
3. **延迟（Latency）**：意图识别本身不能成为用户体验瓶颈（建议 < 500ms）
4. **成本（Cost）**：每次路由的 Token 消耗 / API 调用费用
5. **鲁棒性（Robustness）**：对拼写错误、口语化、中英混杂、长短句的容忍度
6. **可扩展性（Scalability）**：新增意图类型是否需要重新训练或大幅修改 Prompt
7. **可观测性（Observability）**：能否追踪和评估每一次路由决策

## 2. 意图识别技术路线总览

当前工业界和学术界的主流方案可归纳为**五大技术路线**：

### 2.1 路线一：关键词/规则匹配

```
用户输入 → 正则/关键词库匹配 → 意图类型 + 置信度
```

| 维度 | 评价 |
|------|------|
| **延迟** | < 1ms |
| **成本** | 零 |
| **准确率** | 60-75%（高度依赖词库质量） |
| **优势** | 极快、免费、可解释、确定性强 |
| **劣势** | 无语义泛化能力，"找论文"和"搜文章"需要分别配置 |
| **代表实现** | Rasa `KeywordIntentClassifier`、本项目 `intent_classifier.py` |

**适用场景**：明确的命令式交互、快捷指令、内部工具调用。

### 2.2 路线二：传统 NLU 分类器

```
用户输入 → 分词/特征提取 → 机器学习分类器(SVM/DIET) → 意图类型
```

| 维度 | 评价 |
|------|------|
| **延迟** | 5-20ms |
| **成本** | 低（本地推理） |
| **准确率** | 85-93%（需标注数据） |
| **优势** | 成熟稳定、可私有化部署、社区支持好 |
| **劣势** | 需要标注数据、意图变更需重新训练、多语言支持弱 |
| **代表实现** | Rasa NLU（DIET 分类器）、Dialogflow ES、Amazon Lex |

**DIET（Dual Intent and Entity Transformer）** 是 Rasa 3.x 的核心分类器，基于 Transformer 架构同时完成意图分类和实体识别。在标注数据充足的情况下表现优异。

### 2.3 路线三：语义向量路由（Semantic Router）

```
用户输入 → Embedding 模型 → 向量 → 与预定义意图向量余弦相似度 → 意图类型
```

| 维度 | 评价 |
|------|------|
| **延迟** | 10-50ms |
| **成本** | 低（仅 Embedding 推理，本地免费） |
| **准确率** | 80-92% |
| **优势** | 语义泛化好、低成本、可离线 |
| **劣势** | 需为每种意图准备 utterance 样例、复杂意图识别差 |
| **代表实现** | Semantic Router (Aurelio AI)、vLLM Semantic Router |

**核心技术原理**：
1. 为每种意图类型准备 3-20 条代表性话语（utterances）
2. 用 Embedding 模型将所有 utterance 编码为高维向量
3. 用户输入同样编码为向量
4. 计算余弦相似度，选择距离最近的意图
5. 低于设定阈值时降级到 LLM 分类

### 2.4 路线四：LLM 直接分类

```
用户输入 → LLM + System Prompt → 结构化输出（意图类型 + 置信度 + 理由）
```

| 维度 | 评价 |
|------|------|
| **延迟** | 500ms - 3s |
| **成本** | 中-高（每次 ~500-2000 Token） |
| **准确率** | 90-96% |
| **优势** | 语义理解最强、零样本、多意图原生支持、可解释 |
| **劣势** | 延迟高、成本高、输出格式偶有波动 |
| **代表实现** | 本项目 `unified/intent_router.py`、LangChain `RunnableBranch` + LLM |

**关键优化手段**：
- **小模型分类**：使用 GPT-4o-mini / DeepSeek-V3 / MiniMax-M2 等低成本模型做分类
- **Structured Outputs**（OpenAI）/ JSON Mode：强制模型输出合法 JSON
- **Instructor / PydanticAI**：Pydantic 验证 + 自动重试，保证输出可靠性
- **Prompt Cache**：缓存在 System Prompt 中的意图定义，减少重复 Token 消耗

### 2.5 路线五：级联混合路由（Cascaded Hybrid）

```
用户输入
  → Layer 1: 关键词快速匹配（<1ms, acc 60-75%）
    → 置信度不足 ↓
  → Layer 2: 语义向量路由（10-50ms, acc 80-92%）
    → 置信度不足 ↓
  → Layer 3: LLM 深度分类（500ms-2s, acc 90-96%）
    → Layer 4: 降级兜底（默认意图 / 人工确认）
```

| 维度 | 评价 |
|------|------|
| **延迟** | P50 ~5ms, P95 ~800ms |
| **成本** | 70-85% 请求在 Layer 1/2 处理，成本极低 |
| **准确率** | 综合 92-96% |
| **优势** | 兼顾速度、成本与准确率，生产环境最佳实践 |
| **劣势** | 架构复杂，三层一致性维护，阈值需数据驱动调优 |

这是当前 **Anthropic、OpenAI、LangChain** 官方博客共同推荐的生产级方案。

## 3. 主流开源工具详解与对比

### 3.1 Semantic Router（Aurelio AI）

| 属性 | 详情 |
|------|------|
| **GitHub** | [aurelio-labs/semantic-router](https://github.com/aurelio-labs/semantic-router) |
| **Stars** | 10,000+ |
| **维护方** | Aurelio AI（LangChain 官方专家团队） |
| **语言** | Python 3.9+ |
| **许可** | MIT |
| **核心原理** | 语义向量相似度 + 阈值决策 |
| **Embedding 支持** | OpenAI、Cohere、HuggingFace、FastEmbed（本地免费）、Google、Azure、Bedrock |
| **路由模式** | 单意图路由、多意图路由、动态路由（Dynamic Routes）、层叠路由（Cascade） |
| **同步/异步** | 均原生支持 |
| **企业特性** | 支持混合路由（语义 + LLM 兜底）、配置热加载、Dashboard 监控 |

**核心代码示例**：

```python
from semantic_router import Route, RouteLayer
from semantic_router.encoders import FastEmbedEncoder  # 本地免费

# 1. 定义路由（每种意图需要 3-10 条 utterance）
search = Route(
    name="literature_search",
    utterances=[
        "帮我找关于深度学习的论文",
        "搜索transformer架构的最新研究",
        "找几篇NLP相关的文献",
        "最近有哪些大模型相关的论文",
        "帮我查一下联邦学习的资料",
    ],
)
write = Route(
    name="draft_write",
    utterances=[
        "帮我写论文第二章",
        "生成初稿内容",
        "起草引言部分",
        "写一下方法论部分",
        "帮我完成文献综述章节",
    ],
)

# 2. 创建路由层（使用本地 Encoder，零 API 费用）
encoder = FastEmbedEncoder(model_name="BAAI/bge-small-zh-v1.5")
layer = RouteLayer(encoder=encoder, routes=[search, write])

# 3. 同步路由
result = layer("我想找一些关于大语言模型的论文")
print(result.name)        # "literature_search"
print(result.score)       # 0.87（余弦相似度）

# 4. 阈值控制：低于阈值返回 None，触发 LLM 兜底
result2 = layer("帮我比较一下BERT和GPT的区别")
if result2 is None:
    # 降级到 LLM 分类
    intent = await llm_classify("帮我比较一下BERT和GPT的区别")
```

**与本项目的适配度：★★★★★**
- 可直接复用项目现有的 `INTENT_KEYWORDS` 字典作为 utterance 源
- `FastEmbed` 支持中文模型（`BAAI/bge-small-zh-v1.5`），本地免费
- MIT 许可，无商用限制

### 3.5 LlamaIndex 路由能力

| 组件 | 功能 |
|------|------|
| `RouterQueryEngine` | 在多个查询引擎间路由，支持 LLM/Embedding/Keyword 三种选择器 |
| `PydanticSingleSelector` | 基于 Pydantic 模式的 LLM 选择器（需 OpenAI） |
| `PydanticMultiSelector` | 多选模式 |
| `LLMSingleSelector` / `LLMMultiSelector` | 通用 LLM 选择器 |

**使用示例**：

```python
from llama_index.core.query_engine import RouterQueryEngine
from llama_index.core.selectors import LLMSingleSelector
from llama_index.core.tools import QueryEngineTool

# 定义多个查询引擎
search_tool = QueryEngineTool.from_defaults(
    query_engine=search_engine,
    description="用于搜索学术论文和文献"
)
write_tool = QueryEngineTool.from_defaults(
    query_engine=write_engine,
    description="用于撰写和生成论文内容"
)

# 创建路由器
router = RouterQueryEngine(
    selector=LLMSingleSelector.from_defaults(),
    query_engine_tools=[search_tool, write_tool],
)
result = router.query("帮我搜索深度学习的论文")
```

**与本项目的相关度：★★★☆☆**
- 功能与 Semantic Router 重叠但偏重检索场景
- 选择性器依赖 LLM 调用（延迟 > 1s），不适用于低延迟路由场景

### 3.6 Instructor（结构化输出增强）

| 属性 | 详情 |
|------|------|
| **GitHub** | [567-labs/instructor](https://github.com/567-labs/instructor) |
| **语言** | Python |
| **核心功能** | 基于 Pydantic 的 LLM 结构化输出，自动验证 + 重试 + 修复 |
| **适用场景** | Layer 3 LLM 分类输出可靠性保障 |

**使用示例**：

```python
import instructor
from pydantic import BaseModel, Field
from openai import OpenAI

class IntentClassification(BaseModel):
    primary_intent: str = Field(description="主意图类型")
    confidence: float = Field(ge=0.0, le=1.0, description="置信度")
    secondary_intents: list[str] = Field(default_factory=list)
    reasoning: str = Field(description="分类理由")

client = instructor.from_openai(OpenAI())

# 自动验证 + 重试（最多3次），保证输出符合 Schema
result = client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=IntentClassification,
    messages=[
        {"role": "system", "content": "你是一个意图分类专家"},
        {"role": "user", "content": "帮我搜索深度学习的论文然后写一份综述"},
    ],
)
```

**与本项目的相关度：★★★★☆**
- 可直接替换 `IntentRouter._llm_multi_intent_route()` 中的 `json.loads()` 解析
- Pydantic 模式与项目现有的 `LLMConfig` 风格一致

## 4. 商业/企业级方案

### 4.1 Google Dialogflow CX

| 属性 | 详情 |
|------|------|
| **定位** | 企业级对话 AI 平台（NLU + 对话管理 + 多渠道集成） |
| **核心 NLU** | BERT-based，支持流程型意图设计（Flows & Pages） |
| **定价** | 按请求计费（$0.002-0.007/请求） |
| **适用场景** | 大型企业客服、IVR 系统、复杂多轮对话 |
| **与本项目关系** | 过重，不适合嵌入 Python Agent 系统 |

### 4.2 Amazon Lex / Microsoft LUIS

- **Amazon Lex**：AWS 托管的对话 AI 服务，使用与 Alexa 相同的 NLU 引擎
- **Microsoft LUIS**：已合并至 Azure AI Language 服务，2025 年逐步淘汰独立产品
- **结论**：均不适合本项目，运维成本高且与 Python Agent 生态割裂

### 4.3 OpenAI Structured Outputs / Assistants API Routing

OpenAI 在 2024 年推出的 Structured Outputs 功能（`response_format` + `strict: true`），让 LLM 分类器有了更强的可靠性保证。2025 年 7 月发布的 **ChatGPT Agent** 包含了内置的 Tool Selection / Routing 能力，但目前仍处于 Beta 阶段。

**与本项目相关度**：可作为 Layer 3 LLM 分类的底层能力依赖。

## 5. 多 Agent 框架中的意图路由

### 5.1 CrewAI

CrewAI 是 2024 年增长最快的多 Agent 框架。其路由机制是**基于角色的任务分配**（Role-based Task Assignment），而非显式的意图分类器：

- Agent 定义 `role` + `goal` + `backstory`
- Task 定义 `description` + `expected_output` + `agent`
- Crew 通过 `Process.sequential` 或 `Process.hierarchical` 编排

CrewAI 更适合"预定义流水线"场景，而非"动态意图驱动路由"场景。与本项目的 `MasterSupervisor` 编排模式有相似之处，但其缺少独立的意图识别层。

### 5.2 Microsoft AutoGen

AutoGen 使用基于对话的多 Agent 协作模式，核心是 `GroupChatManager` 协调 Agent 间的消息传递。其意图路由隐含在 Agent 之间的自然语言对话中，而非显式的分类器。

### 5.3 LangGraph Supervisor Pattern

与本项目的 `MasterSupervisor` + `PhaseSupervisor` 架构最相似。LangGraph 的推荐做法是使用 `add_conditional_edges` + 路由函数实现意图分发，本项目已采用此模式。

### 6.2 工业界最佳实践共识

综合 Anthropic、OpenAI、LangChain、Google 等 2025 年的官方指南，关于意图路由的共识如下：

1. **能不快就别快，能不贵就别贵**：高频简单请求用 Embedding/关键词，复杂请求才走 LLM
2. **路由层要保持简洁**：不要引入复杂依赖，路由层崩溃 = 整个系统不可用
3. **LLM 路由用 Structured Outputs 而不是裸 JSON Mode**：Instructor > JSON Mode > 裸字符串解析
4. **Prompt Caching 是免费午餐**：System Prompt 中的意图定义应开启缓存
5. **每个路由决策都要有日志**：没有可观测性的路由是盲盒
6. **降级路径必须存在**：LLM 不可用时，路由系统不能崩溃

### 8.3 推荐的集成代码

```python
# src/agents_v2/intent/cascade_router.py (新文件)

from semantic_router import Route, RouteLayer
from semantic_router.encoders import FastEmbedEncoder
from .keyword_classifier import KeywordIntentClassifier
from .llm_classifier import LLMIntentClassifier
from .types import IntentType, IntentResult


class CascadeIntentRouter:
    """三级级联意图路由器"""

    def __init__(self, llm_config=None):
        # Layer 1: 关键词分类器（复用现有）
        self.keyword_classifier = KeywordIntentClassifier()

        # Layer 2: 语义向量路由（新增）
        self.encoder = FastEmbedEncoder(
            model_name="BAAI/bge-small-zh-v1.5"  # 中文优化
        )
        self.semantic_layer = self._build_semantic_layer()

        # Layer 3: LLM 分类器（复用并增强）
        self.llm_classifier = LLMIntentClassifier(
            llm_config=llm_config,
            use_instructor=True,    # 增强：结构化输出
            use_prompt_cache=True,  # 增强：Prompt Caching
        )

    def _build_semantic_layer(self) -> RouteLayer:
        """从现有 INTENT_KEYWORDS 构建语义路由层"""
        routes = []
        for intent_type, keywords in INTENT_KEYWORDS.items():
            utterances = self._keywords_to_utterances(intent_type, keywords)
            routes.append(Route(
                name=intent_type.value,
                utterances=utterances,
            ))
        return RouteLayer(encoder=self.encoder, routes=routes)

    async def route(self, query: str) -> IntentResult:
        """三级级联路由"""
        # Layer 1: 关键词匹配
        kw_result = self.keyword_classifier.classify(query)
        if kw_result.confidence >= 0.7:
            return self._enrich_result(kw_result, layer="keyword")

        # Layer 2: 语义向量路由
        try:
            result = self.semantic_layer(query)
            if result is not None and result.score >= 0.6:
                return self._enrich_result(
                    IntentResult(intent=result.name, confidence=result.score),
                    layer="semantic"
                )
        except Exception:
            pass  # 语义路由失败，降级到 LLM

        # Layer 3: LLM 深度分类
        llm_result = await self.llm_classifier.classify(query)
        if llm_result.confidence >= 0.5:
            return self._enrich_result(llm_result, layer="llm")

        # Layer 4: 降级兜底
        return self._fallback(query)
```
