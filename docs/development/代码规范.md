# 代码规范

更新日期：2026-05-28

本文档定义 PaperAgent 的 Python 代码规范。目标是让代码可读、可测、可维护、可审计，尤其适用于 LLM、Agent、RAG、API、论文写作和知识库分析场景。

## 1. 基础约定

- Python 版本：`>=3.11`。
- 格式化：Ruff format，行宽 `88`。
- Lint：Ruff check。
- 类型检查：mypy。
- 测试：pytest + pytest-asyncio。
- 字符集：UTF-8。
- 缩进：4 个空格。
- 新增公共接口必须写类型注解。
- 业务代码禁止调试 `print`，使用日志。
- 不在代码、日志、测试和文档中写真实密钥。

## 2. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 模块文件 | `snake_case.py` | `project_service.py` |
| 包目录 | `snake_case` | `research_workspace` |
| 变量 | `snake_case` | `paper_id` |
| 函数 | `snake_case` | `load_project` |
| 类 | `PascalCase` | `ResearchProject` |
| 异常 | `PascalCase` + `Error` | `ProjectNotFoundError` |
| 常量 | `UPPER_SNAKE_CASE` | `MAX_RETRY_COUNT` |
| 私有成员 | `_snake_case` | `_validate_path` |
| 布尔变量 | `is_`、`has_`、`can_`、`should_` | `is_archived` |
| 测试函数 | `test_<行为>_<预期>` | `test_save_project_creates_file` |

命名要求：

- 名称必须表达业务含义，不使用单独的 `data`、`obj`、`tmp`、`val`。
- 同一概念使用同一词，不混用 `paper`、`article`、`document` 表示同一对象。
- 函数名用动词开头，如 `create_`、`load_`、`save_`、`validate_`、`parse_`。
- 类名用名词或名词短语，如 `ProjectStorage`、`CitationTracker`。

## 3. 导入规范

导入顺序：

1. `from __future__ import annotations`
2. 标准库
3. 第三方库
4. 项目内模块
5. `TYPE_CHECKING` 专用导入

示例：

```python
from __future__ import annotations

from pathlib import Path
from typing import TYPE_CHECKING

from pydantic import BaseModel, Field

from loguru import logger
from src.agents_v3.research_workspace.models import ResearchProject

if TYPE_CHECKING:
    from src.models.state import AgentContext
```

规则：

- 不使用 `from module import *`。
- 避免循环导入；类型专用依赖放到 `TYPE_CHECKING`。
- 只在确有必要时使用函数内导入，例如可选依赖或避免启动成本。
- 不从测试代码导入生产代码中的私有实现，除非测试目标就是该私有逻辑。

## 4. 类型规范

公共函数、类方法、数据模型必须有类型注解。

推荐写法：

```python
def normalize_title(title: str) -> str:
    return " ".join(title.strip().lower().split())
```

现代类型写法：

```python
def find_project(project_id: str) -> ResearchProject | None:
    ...
```

优先使用：

- `list[str]`、`dict[str, int]`，不使用旧式 `List[str]`。
- `X | None`，不使用 `Optional[X]`，除非与旧代码保持一致。
- `Protocol` 表达可替换接口。
- `TypedDict` 表达固定字段字典。
- `Literal` 或 `StrEnum` 表达受限字符串。
- Pydantic `BaseModel` 表达 API、工具、LLM 结构化输入输出。

避免：

- 公共接口返回 `dict[str, Any]`。
- 用 `Any` 穿透多个模块。
- 一个函数根据分支返回多种无关类型。
- 为了压住类型报错随意 `cast` 或 `# type: ignore`。

## 5. 数据模型规范

Pydantic 模型适用于 API 请求响应、Agent 输入输出、工具 schema、LLM 结构化结果。

示例：

```python
from pydantic import BaseModel, Field, field_validator


class ProjectCreateRequest(BaseModel):
    name: str = Field(min_length=1, max_length=120)
    description: str = Field(default="", max_length=2000)

    @field_validator("name")
    @classmethod
    def strip_name(cls, value: str) -> str:
        return value.strip()
```

模型规则：

- 字段名使用 `snake_case`。
- 用户输入必须有长度、范围或枚举约束。
- 外部 API 和 LLM 返回值必须校验后再进入业务逻辑。
- 模型序列化时不要输出内部路径、密钥或调试字段。
- 数据模型变更必须同步测试和相关文档。

## 6. 函数规范

函数应满足：

- 单一职责。
- 参数清晰，通常不超过 5 个。
- 返回类型稳定。
- 不隐式修改传入的可变对象。
- I/O、网络、LLM 调用和纯计算分开。

推荐：

```python
def deduplicate_papers(papers: list[Paper]) -> list[Paper]:
    seen: set[str] = set()
    result: list[Paper] = []

    for paper in papers:
        key = paper.doi or paper.normalized_title
        if key in seen:
            continue
        seen.add(key)
        result.append(paper)

    return result
```

避免：

- 函数里同时读文件、调模型、写数据库、返回 API 响应。
- 通过返回 `None`、`False`、空字符串混合表示失败。
- 静默吞掉异常。

## 7. 类规范

类应该代表清晰职责：

- 数据模型。
- 服务对象。
- 存储适配器。
- Agent。
- 工具或工具注册表。
- 协议/抽象接口。

构造函数要求：

- 不做长时间 I/O。
- 不启动后台任务。
- 不调用真实 LLM 或外部 API。
- 只保存依赖、配置和轻量状态。

依赖注入优先：

```python
class ProjectService:
    def __init__(self, storage: ProjectStorage) -> None:
        self._storage = storage
```

## 8. 异步规范

适用于 API、LLM、搜索、工具和工作流：

- I/O 密集操作使用 `async def`。
- async 函数中禁止 `time.sleep`，使用 `await asyncio.sleep`。
- 外部请求必须设置 timeout。
- 并发必须有上限，不做无界 `gather`。
- 长任务要支持取消、状态查询或检查点。

示例：

```python
import asyncio


async def run_with_limit(tasks: list[Awaitable[Result]]) -> list[Result]:
    semaphore = asyncio.Semaphore(5)

    async def run(task: Awaitable[Result]) -> Result:
        async with semaphore:
            return await asyncio.wait_for(task, timeout=30)

    return await asyncio.gather(*(run(task) for task in tasks))
```

注意：

- 使用 `return_exceptions=True` 时必须显式处理异常对象。
- 不要在事件循环中执行耗时 CPU 任务。
- SSE 或 streaming 接口要处理客户端断开。

## 9. 异常规范

异常原则：

- 抛具体异常，不用裸 `Exception` 表示业务错误。
- 捕获异常时保留上下文。
- 用 `raise NewError(...) from exc` 保留原始原因。
- 外部 SDK 异常要转换为项目异常或服务错误。
- API 层不向用户暴露内部堆栈。

示例：

```python
try:
    project = storage.load(project_id)
except FileNotFoundError as exc:
    raise ProjectNotFoundError(project_id) from exc
```

禁止：

```python
try:
    risky_operation()
except Exception:
    pass
```

## 10. 日志规范

使用项目日志封装：

```python
from loguru import logger

logger = get_logging_logger(__name__)
```

日志要求：

- 记录业务事件，不记录无意义噪声。
- 带上下文字段，如 `project_id`、`request_id`、`agent_name`、`tool_name`。
- 记录耗时、状态、错误类型、重试次数。
- 大文本只记录长度、hash 或摘要。
- 不记录 API Key、token、Cookie、完整 prompt、私有论文全文。

示例：

```python
logger.info(
    "Project saved",
    project_id=project.project_id,
    path=str(project_path),
)
```

## 11. 安全编码规范

输入安全：

- 用户输入必须校验长度、格式和允许值。
- 文件路径用 `Path.resolve()` 后检查是否在允许根目录内。
- URL 只允许 `http`/`https`，并设置 timeout 和最大响应大小。
- HTML/Markdown 输出前要考虑转义和注入风险。

LLM/Agent 安全：

- Prompt 中明确区分系统指令、用户输入、检索材料和工具结果。
- 不让 PDF、网页、检索结果覆盖系统指令。
- LLM 输出不能直接作为文件路径、命令、SQL、URL 或工具参数使用。
- Agent 工具必须有 schema、权限边界、超时和审计。
- 高风险动作需要人工确认或白名单。

密钥安全：

- 密钥只从环境变量读取。
- 测试用假 key，如 `test-api-key`。
- 日志和异常信息必须脱敏。

## 12. LLM 调用规范

LLM 调用必须集中封装，不在业务代码中散落 SDK 调用。

每次调用应明确：

- provider。
- model_name。
- temperature。
- max_tokens。
- timeout。
- retry policy。
- prompt 版本或模板来源。

结构化输出要求：

- 优先让模型输出 JSON。
- 用 Pydantic 或 schema 校验。
- 解析失败要有明确错误路径。
- 不信任模型生成的引用、分数、文件路径和外部链接。

## 13. Agent 规范

Agent 实现要求：

- 输入输出结构化。
- 声明能力和可处理任务类型。
- 工具通过注入或注册表获得。
- 执行过程可追踪。
- 失败返回明确错误，不伪装成功。

典型流程：

1. 校验输入。
2. 加载上下文。
3. 选择工具或模型。
4. 执行任务。
5. 校验输出。
6. 写入日志/审计元数据。
7. 返回结果。

Agent 不应：

- 在内部硬编码 API Key。
- 无上限循环调用 LLM。
- 无约束读写任意文件。
- 把工具错误直接暴露给最终用户。

## 14. 工具规范

工具必须具备：

- 名称。
- 描述。
- 输入模型。
- 输出模型。
- 权限边界。
- 超时。
- 错误类型。
- 日志和审计字段。

示例：

```python
class LoadProjectInput(BaseModel):
    project_id: str = Field(min_length=1, max_length=80)


class LoadProjectOutput(BaseModel):
    project_id: str
    name: str
    updated_at: str
```

工具返回值应结构化，不返回难以解析的大段自然语言。

## 15. RAG 和学术内容规范

论文、检索和知识库相关代码必须保留来源。

检索结果字段建议：

- `source`
- `title`
- `authors`
- `year`
- `doi`
- `url`
- `abstract`
- `score`
- `retrieved_at`

生成内容要求：

- 事实结论要能追溯到来源。
- 不确定结论要标记为不确定。
- 引用格式化和引用校验分离。
- 不编造 DOI、作者、期刊、年份。
- 重要生成结果保留模型、prompt 版本、输入摘要和引用列表。

## 16. API 代码规范

Handler 结构：

```python
async def handle_create_project(request: web.Request) -> web.Response:
    payload = await request.json()
    create_request = ProjectCreateRequest.model_validate(payload)

    project = await project_service.create_project(create_request)

    return web.json_response(
        {
            "success": True,
            "data": project.model_dump(),
            "metadata": {"request_id": request["request_id"]},
        }
    )
```

规则：

- Handler 不写复杂业务逻辑。
- 请求数据先校验再使用。
- 错误统一转换为 JSON 响应。
- 不返回内部异常栈。
- 长任务返回 task_id，并提供状态查询。

## 17. 测试规范

测试命名：

```text
tests/agents_v3/research_workspace/test_storage.py
```

测试结构：

```python
def test_save_project_creates_project_file(tmp_path: Path) -> None:
    storage = ProjectStorage(root=tmp_path)
    project = ResearchProject(name="demo")

    storage.save(project)

    assert storage.exists(project.project_id)
```

要求：

- 使用 AAA：Arrange、Act、Assert。
- 单元测试不调用真实 LLM、网络和外部数据库。
- 文件测试使用 `tmp_path`。
- 时间测试注入 clock 或断言范围。
- 随机逻辑设置 seed。
- mock 外部边界，不 mock 被测核心逻辑。
- 修 bug 时补回归测试。

## 18. 注释和文档字符串

注释解释“为什么”，不是复述代码。

公共函数或复杂逻辑使用 Google 风格 docstring：

```python
def load_project(project_id: str) -> ResearchProject:
    """Load a research project by id.

    Args:
        project_id: Stable project identifier.

    Returns:
        Loaded research project.

    Raises:
        ProjectNotFoundError: If the project does not exist.
    """
```

TODO 格式：

```python
# TODO(owner): explain what remains and when it can be removed.
# FIXME(owner): explain the bug and expected behavior.
```

## 19. 常见反模式

| 反模式 | 替代 |
| --- | --- |
| API handler 里直接调 LLM | 封装 service 或 Agent |
| 到处传 `dict[str, Any]` | 使用 Pydantic/TypedDict/dataclass |
| 捕获异常后返回空结果 | 抛具体异常或返回失败模型 |
| 无上限并发 | semaphore + timeout |
| 信任 LLM JSON | schema 校验 |
| 硬编码本地路径 | 配置项 + `Path` |
| 提交 pycache 和日志 | `.gitignore` + 清理 |
| 编造或丢失引用来源 | 保留 source metadata |
