# 容错架构改进记录

> 从线性链路到容错图：让研究Agent不再"一坏皆坏"

---

## 一、问题背景

### 1.1 线性架构的脆弱性

原有架构：
```
query → search → rank → read → analyse → critique → writing → report
         ↑
      任一节点失败，整条链路崩溃
```

**典型失败场景**：
1. **搜索无结果** → 后续全部空转
2. **阅读失败率高** → 分析基于不完整数据
3. **Critique不通过** → 迭代但没有结构化的回退机制
4. **写作卡壳** → 没有子任务重试

### 1.2 业界解决方案

| 框架 | 容错策略 |
|------|----------|
| LangGraph | 节点级别 error boundary + 状态回滚 |
| AutoGen | MaxRetry + human feedback 介入 |
| CrewAI | retry + fallback 策略 |
| PaperQA2 | RCS重排 + 引用图遍历（多路径） |

### 1.3 Planner-Orchestrated架构（新增）

详见 [planner_orchestrator.py](src/workflows/planner_orchestrator.py)

**核心思想**：用一个Planner作为中枢，动态调度各子Agent，而非固定线性流程。

**架构图**：
```
                    ┌─────────────────────────────────────────┐
                    │              Planner                    │
                    │  - 任务分解                            │
                    │  - 状态监控                            │
                    │  - 动态调度                            │
                    │  - 失败处理                            │
                    └──────────────────┬──────────────────────┘
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         │                             │                             │
         ▼                             ▼                             ▼
  ┌──────────────┐           ┌──────────────┐           ┌──────────────┐
  │    Search    │◄─────────►│    Read      │◄─────────►│   Analyse    │
  │   (并行)     │   增量     │   (增量)     │   增量     │   (增量)     │
  └──────┬───────┘           └──────┬───────┘           └──────┬───────┘
         │                           │                           │
         └───────────────────────────┼───────────────────────────┘
                                     │
                                     ▼
                            ┌──────────────┐
                            │   Critique   │
                            │   (多视角)   │
                            └──────┬───────┘
                                   │
                 ┌─────────────────┼─────────────────┐
                 │                 │                 │
                 ▼                 ▼                 ▼
          ┌────────────┐   ┌────────────┐   ┌────────────┐
          │   Write    │   │  Supplement │   │   Done     │
          │  (增量)    │   │  (补充)    │   │            │
          └────────────┘   └────────────┘   └────────────┘
```

**关键创新**：
- **Planner中枢**：统一调度，动态路由
- **边搜边读**：找到3篇就开始读，不用等全部搜完
- **边读边分析**：每读完1篇就分析1篇
- **增量写作**：有3篇分析就开始写草稿
- **Critique循环**：不通过就回到对应阶段补充

## 三、详细设计

### 3.1 错误边界 + Fallback

```python
@with_error_boundary(
    error_type="search_node",
    fallback_fn=fallback_search,
    default_value=[],
    store_checkpoint=True
)
async def safe_search_node(state):
    # 主逻辑
    papers = await search(state["query"])
    return {"papers": papers}
```

**降级策略**：

| 场景 | 降级函数 | 说明 |
|------|---------|------|
| 搜索失败 | `fallback_search_empty` | 返回空列表 |
| 搜索失败 | `fallback_search_from_memory` | 从记忆系统检索历史结果 |
| 搜索失败 | `fallback_search_broaden_query` | 扩大查询范围 |
| 阅读失败 | `fallback_reading_skip` | 跳过该论文 |
| 阅读失败 | `fallback_reading_abstract_only` | 仅使用摘要 |
| 分析失败 | `fallback_analysis_minimal` | 返回最小分析结果 |
| 分析失败 | `fallback_analysis_by_keyword` | 基于关键词简单分类 |
| 写作失败 | `fallback_writing_template` | 使用模板 |
| 写作失败 | `fallback_writing_outline_only` | 仅返回大纲 |
| Critique失败 | `fallback_critique_force_proceed` | 强制通过进入写作 |
| Critique失败 | `fallback_critique_reduce_requirements` | 降低要求重试 |

### 3.2 多路径冗余搜索

```python
class RedundantSearcher:
    """并行搜索多个引擎，合并结果"""
    async def parallel_search(self, query):
        # 多引擎并行
        results = await asyncio.gather(
            mcp_search(query),
            local_search(query),
            return_exceptions=True
        )
        # 合并去重
        return merge_results(results)
```

**引擎级联失败**：
```
MCP引擎搜索 → 失败 → 本地数据库搜索 → 失败 → 返回空列表（但不崩溃）
```

### 3.3 状态快照 + 回滚

```python
class PipelineState:
    """保存检查点，失败时回滚"""
    def save(self, name, state):
        self.manager.save(name, state)

    def restore(self, name=None):
        return self.controller.rollback()
```

**使用示例**：
```python
# 分析前保存快照
ps.save("before_analysis", state)

# 分析失败
if not quality_passed:
    restored = ps.restore("before_analysis")
    # 重新搜索或调整策略
```

### 3.4 隔离子图

```python
class ReadingSubgraph(IsolatedSubgraph):
    """单篇论文阅读失败不影响其他论文"""
    async def execute(self, papers):
        tasks = [self._read_paper(p) for p in papers]
        results = await asyncio.gather(*tasks, return_exceptions=True)

        # 收集成功的结果
        successful = [r for r in results if not isinstance(r, Exception)]
        return SubgraphResult(outputs=successful)
```

**状态枚举**：
- `COMPLETED` - 全部成功
- `PARTIAL_FAILED` - 部分失败（可容忍）
- `FAILED` - 失败过多（需要回滚）

### 3.5 质量门控

```python
gate = QualityGate()
gate.add_threshold("papers_count", min_val=5)      # 最少5篇论文
gate.add_threshold("analysis_score", min_val=0.6)  # 分析质量60%以上

result = gate.evaluate(state)
if result.should_rollback:
    controller.rollback("before_analysis")
```

## 四、新架构流程

### 4.1 容错状态机

```
[checkpoint] → search(多引擎+fallback)
                    ↓失败降级
               [checkpoint] → rank(RCS)
                    ↓失败使用原顺序
               [checkpoint] → reading(隔离子图)
                    ↓部分失败继续
               [checkpoint] → analyse
                    ↓失败可回滚
               critique → (迭代|写)
                    ↓失败回滚
               [checkpoint] → writing(隔离子图)
                    ↓部分失败继续
                    → report
```

### 4.2 关键节点检查点

| 节点 | 检查点名称 | 回滚触发条件 |
|------|-----------|-------------|
| search | checkpoint_before_search | 无搜索结果 |
| rank | checkpoint_before_rank | - |
| reading | checkpoint_before_reading | 失败率>50% |
| analyse | checkpoint_before_analyse | 质量门不通过 |
| critique | checkpoint_before_critique | 达到最大迭代 |
| writing | checkpoint_before_writing | 章节失败率>50% |

## 五、代码示例

### 5.1 容错搜索节点

```python
async def safe_search_node(state: ResearchState) -> ResearchState:
    """容错搜索节点 - 多引擎并行 + fallback"""
    try:
        searcher = RedundantSearcher()
        papers = await searcher.parallel_search(state["query"])
        state["papers"] = papers
    except Exception as e:
        state["_errors"].append({"node": "search", "error": str(e)})
        state["papers"] = []  # 空结果但不中断
    return state
```

### 5.2 容错阅读节点

```python
async def safe_reading_node(state: ResearchState) -> ResearchState:
    """容错阅读节点 - 子图隔离"""
    reading_subgraph = ReadingSubgraph(max_failures=5)
    result = await reading_subgraph.execute_sequential(papers, max_concurrent=3)

    state["paper_analyses"] = result.outputs
    state["failed_papers"] = result.failure_count
    state["reading_status"] = result.status.value
    return state
```

### 5.3 带回滚的Critique

```python
async def critique_with_rollback(state: ResearchState) -> ResearchState:
    ps = get_pipeline_state()
    ps.save("before_critique", dict(state))

    try:
        result = await critique_node(state)
        state["critique_passed"] = result.get("critique_passed", False)
    except Exception as e:
        state["_errors"].append({"node": "critique", "error": str(e)})
        restored = ps.restore("before_critique")
        if restored:
            state.update(restored)
            state["critique_passed"] = True  # 强制通过避免死循环

    return state
```
