## 一、背景调研

### 1.1 信息检索去重技术概述

在信息检索（IR）领域，搜索结果去重是一个核心问题。典型算法包括：

| 算法类别 | 原理 | 适用场景 |
|----------|------|----------|
| **向量空间模型** | 将查询和文档表示为向量，计算余弦相似度 | 语义相似度匹配 |
| **概率检索模型 (BM25)** | 基于词频和文档频率的相关性评分 | 文本检索排序 |
| **近似最近邻 (ANN)** | HNSW、IVF等索引算法加速向量搜索 | 大规模向量检索 |
| **TF-IDF** | 词频-逆文档频率计算词权重 | 关键词匹配 |

**关键发现**：
- ChromaDB 使用 **HNSW (Hierarchical NSW)** 算法进行近似最近邻搜索，可高效处理语义相似度匹配
- 语义搜索 vs 关键词搜索：ChromaDB 能理解"意思"而非仅"关键词"，比如搜索"人类在极端环境求生意志"能找到《荒野求生》即使标题无共同词

### 1.2 缓存策略研究

**主流缓存策略**：

| 策略 | 原理 | 优势 |
|------|------|------|
| **LRU (Least Recently Used)** | 最近最少使用的缓存项被淘汰 | 符合局部性原理 |
| **LFU (Least Frequently Used)** | 使用频率最低的项被淘汰 | 适合高频访问 |
| **TTL (Time To Live)** | 设置缓存有效期 | 简单易实现 |
| **Write-through** | 数据同时写缓存和数据库 | 数据一致性高 |

**相关技术**：
- **KV Cache**：LLM推理优化技术，用于存储注意力机制的键值对
- **增量搜索**：只获取新增内容，避免全量刷新

### 1.3 查询去重与融合

**Query Fusion 技术**：

1. **重排序 (Re-ranking)**：先用简单方法（如BM25）快速筛选，再用复杂模型（如BERT）精细排序

2. **结果融合**：
   - **RRF (Reciprocal Rank Fusion)**：多结果集排名融合
   - **Score-based Fusion**：多结果集分数加权

3. **查询扩展与消重**：
   - 使用 embedding 计算查询相似度
   - 合并高度相似的查询
   - 基于关键词重叠度去重

### 1.4 ChromaDB 向量数据库特性

**ChromaDB 在项目中的应用**：

```python
# 已初始化的ChromaDB配置
chroma_client = chromadb.PersistentClient(path=CHROMA_PERSIST_DIR)
_collection = self._chroma_client.get_or_create_collection(
    name="papers",
    metadata={"description": "论文向量存储"}
)

# 向量搜索
results = _collection.query(
    query_embeddings=[query_embedding],
    n_results=top_k,
    where={"source": source} if source else None
)
```

**特性**：
- 支持 HNSW 索引
- 支持元数据过滤
- 支持距离/相似度返回

### 1.5 问题分析

当前系统存在以下问题：

1. **重复搜索问题**：多个查询可能返回相同的论文，导致重复的 API 调用
2. **无本地缓存预检**：搜索前不检查本地数据库是否已有相关论文
3. **查询重叠**：生成的多个查询可能返回高度重叠的结果
4. **向量搜索未充分利用**：ChromaDB 已初始化但未在搜索前用于缓存命中检测

**根本原因**：
- 缺乏"先查本地，再查外部"的策略
- 查询生成时未进行去重和合并
- 没有增量搜索机制

## 三、技术方案设计

### 3.1 方案一：查询去重与合并 (Query Deduplication)

**目标**：减少因查询重叠导致的重复 API 调用

**技术原理**：
```
1. 使用 embedding 模型计算查询的语义向量
2. 计算查询对之间的余弦相似度
3. 相似度 > 0.8 的查询合并
4. 保留最具代表性的查询
```

**实现方式**：

```python
# 伪代码示例
def deduplicate_queries(queries: List[str], threshold: float = 0.8) -> List[str]:
    # 1. 计算每个查询的embedding
    embeddings = [compute_embedding(q) for q in queries]

    # 2. 构建相似度矩阵
    similarity_matrix = cosine_similarity(embeddings)

    # 3. 贪心合并相似查询
    merged = []
    used = set()
    for i, query in enumerate(queries):
        if i in used:
            continue
        group = [query]
        for j in range(i+1, len(queries)):
            if similarity_matrix[i][j] > threshold:
                group.append(queries[j])
                used.add(j)
        # 选择最长的查询作为代表（通常更具体）
        merged.append(max(group, key=len))
    return merged
```

**预期效果**：8个查询 → 5-6个查询，减少 25-37% API调用

### 3.2 方案二：本地缓存预检 (Cache Pre-check)

**目标**：搜索前先检查本地数据库是否已有相关论文

**技术原理**：
```
1. 使用 ChromaDB 向量搜索查询本地论文库
2. 获取 top_k 个语义相似的论文
3. 如果本地论文足够满足需求，直接返回
4. 否则继续外部搜索
```

**命中条件**：
- 向量相似度 > 0.9 的论文数量 >= max_results * 0.5

**实现位置**：
- PaperSearchAgent.execute() 开始时优先执行
- 优先于外部 API 调用

**预期效果**：在高频搜索场景下，减少 30-50% API调用

### 3.3 方案三：批量查重与延迟搜索 (Batch Deduplication)

**目标**：收集所有查询结果后统一去重，减少总 API 调用

**技术原理**：
```
1. 搜索阶段：
   - 不在每个 query 执行后立即处理结果
   - 将所有查询结果暂存到 Map<title_lower, paper>

2. 去重阶段：
   - 使用 Map 的 key 自动去重
   - 过滤掉已在本地数据库存在的论文

3. 仅对去重后的"真正新论文"调用 API
```

**实现方式**：

```python
# 伪代码示例
async def _multi_engine_search(self, queries):
    # 使用 Map 存储结果，自动去重
    local_papers_map = {}  # title_lower -> paper

    for query in queries:
        papers = await search_api(query)
        for p in papers:
            title_lower = p.title.lower().strip()
            if title_lower not in local_papers_map:
                local_papers_map[title_lower] = p

    return list(local_papers_map.values())
```

**预期效果**：减少 15-25% API调用（取决于查询重叠程度）

### 3.4 方案四：增量搜索模式 (Incremental Search)

**目标**：对已搜索过的主题，支持增量更新而非全量搜索

**技术原理**：
```
1. 记录已搜索的主题和对应论文集合
2. 下次搜索同一主题时：
   - 只搜索新增的论文（时间范围缩小）
   - 本地已有论文直接复用
```

**数据库设计**：

```sql
CREATE TABLE search_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    topic TEXT NOT NULL,
    paper_id TEXT NOT NULL,
    search_time TEXT NOT NULL,
    UNIQUE(topic, paper_id)
);

CREATE INDEX idx_topic ON search_history(topic);
CREATE INDEX idx_search_time ON search_history(search_time);
```

**API 调用优化**：

```python
# 时间范围参数传递
time_range = "6months"  # 只搜索近6个月的新论文
result = await search_agent.execute(query, {"time_range": time_range, ...})
```

**预期效果**：对重复主题搜索，减少 60-80% API调用

## 四、技术方案详解

### 4.1 查询去重与合并 (Query Deduplication)

#### 技术原理

使用 embedding 模型计算查询的语义向量，通过余弦相似度判断查询重叠程度，高相似度查询进行合并。

#### 核心算法

```
输入: queries = ["deep learning image segmentation", "CNN image segmentation", "neural network medical imaging"]
输出: merged_queries = ["deep learning image segmentation", "neural network medical imaging"]

步骤:
1. compute_embedding(query) → vector
2. similarity = cosine_similarity(vec1, vec2)
3. if similarity > threshold: 合并
```

#### 阈值选择

| 阈值 | 效果 |
|------|------|
| 0.7 | 宽松合并，可能丢失差异化查询 |
| **0.8** | **平衡选择（推荐）** |
| 0.9 | 严格合并，保留更多独立查询 |

### 4.2 本地缓存预检 (Cache Pre-check)

#### 技术原理

利用 ChromaDB 的向量相似度搜索，在调用外部 API 前先检查本地是否已有足够相关的论文。

#### 命中判断逻辑

```python
def should_use_cache(local_results, max_results):
    if not local_results:
        return False

    relevant_count = sum(1 for r in local_results if r.similarity > 0.9)
    # 命中条件：相似度>0.9的论文 >= max_results的50%
    return relevant_count >= max_results * 0.5
```

#### 缓存更新策略

- **写入时机**：每次外部搜索返回后，存入本地数据库
- **TTL 设置**：向量数据建议6个月更新一次
- **容量控制**：本地论文库上限 100,000 篇

### 4.3 批量查重 (Batch Deduplication)

#### 技术原理

使用 `Map<title_lower, paper>` 数据结构，在内存中自动完成去重，避免 `O(n²)` 的嵌套循环。

#### 实现对比

| 方式 | 时间复杂度 | 空间复杂度 |
|------|------------|------------|
| 双重循环 List | O(n²) | O(n) |
| **Map 去重** | **O(n)** | **O(n)** |

```python
# 旧: O(n²) 双重循环
for p1 in papers:
    for p2 in papers:
        if p1.title == p2.title:
            ...

# 新: O(n) Map去重
local_papers_map = {}
for p in papers:
    local_papers_map[p.title.lower()] = p
```

### 4.4 增量搜索 (Incremental Search)

#### 技术原理

记录每个主题的首次搜索时间，后续搜索只获取该时间之后的新论文。

#### 实现步骤

```
1. 首次搜索 "machine learning healthcare":
   → search_time = 2026-05-03, 返回100篇
   → 存入 search_history

2. 第二次搜索同一主题:
   → 获取 last_search_time = 2026-05-03
   → time_range = "0" 或只搜索 2026-05-03 之后的新论文
   → 返回20篇新论文 + 复用本地80篇
```

#### 数据库表结构

```sql
CREATE TABLE search_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    topic TEXT NOT NULL,
    paper_id TEXT NOT NULL,
    search_time TEXT NOT NULL,
    fingerprint TEXT NOT NULL,
    UNIQUE(topic, paper_id)
);

CREATE INDEX idx_topic ON search_history(topic);
CREATE INDEX idx_fingerprint ON search_history(fingerprint);
```

## 八、风险与注意事项

### 7.1 风险

1. **本地缓存过期**：本地论文可能不是最新，需要定期更新
2. **向量搜索精度**：相似度阈值设置不当可能导致误过滤
3. **内存占用**：大量论文对象可能导致内存占用增加

### 7.2 注意事项

1. 设置合理的向量相似度阈值（建议 0.85-0.9）
2. 定期清理过期的本地缓存
3. 监控缓存命中率和API调用次数
4. 对于需要最新论文的场景，跳过缓存直接搜索
