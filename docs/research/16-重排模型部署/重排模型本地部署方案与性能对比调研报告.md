## 一、核心概念与定义

### 1.1 什么是重排(Reranking)

重排是检索增强生成(RAG)流程中的关键第二阶段。在第一阶段通过向量检索或BM25等方法获取候选文档(通常top-50到top-100)后，重排模型对每个(query, document)对进行精细化打分，重新排序以提升最终返回结果的相关性。

### 1.2 Cross-Encoder vs Bi-Encoder

| 特性 | Bi-Encoder | Cross-Encoder |
|------|-----------|---------------|
| 编码方式 | query和document独立编码 | query和document拼接后联合编码 |
| 速度 | 快(可预计算document embedding) | 慢(每次都需要重新计算) |
| 精度 | 较低 | 显著更高 |
| 典型用途 | 初始检索(召回) | 重排(精排) |
| 延迟差异 | - | 比Bi-Encoder慢100-1000x |

### 1.3 重排在RAG中的位置

```
用户Query
  -> 向量检索/BM25 (召回top-50~100)
  -> Cross-Encoder重排 (精排top-5~10)
  -> LLM生成答案
```

## 三、部署框架深度对比

### 3.1 Sentence-Transformers CrossEncoder

**GitHub**: [UKPLab/sentence-transformers](https://github.com/UKPLab/sentence-transformers) (18,758 stars)

```python
from sentence_transformers import CrossEncoder

model = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')
scores = model.predict([('query', 'doc1'), ('query', 'doc2'), ...])
```

**优势**:
- 最成熟的Python生态，文档完善
- 支持所有主流cross-encoder模型
- 与Hugging Face Hub深度集成
- 支持GPU加速(FP16/BF16)
- 支持批量推理

**劣势**:
- 依赖PyTorch，包体积大(~2GB)
- 默认未优化，需要额外配置才能获得最佳性能
- 不适合serverless部署(冷启动慢)

**部署模式**:
```python
# 简单部署
from sentence_transformers import CrossEncoder
model = CrossEncoder('BAAI/bge-reranker-v2-m3', device='cuda')

# FastAPI服务
from fastapi import FastAPI
app = FastAPI()
model = CrossEncoder('BAAI/bge-reranker-v2-m3')

@app.post("/rerank")
def rerank(query: str, documents: list[str]):
    pairs = [(query, doc) for doc in documents]
    scores = model.predict(pairs)
    return sorted(zip(documents, scores), key=lambda x: x[1], reverse=True)
```

### 3.3 ONNX Runtime加速

**GitHub**: [microsoft/onnxruntime](https://github.com/microsoft/onnxruntime)

ONNX Runtime是跨平台推理加速器，可将PyTorch模型转换为ONNX格式后获得2-5x加速。

**Cross-Encoder ONNX优化**:
```python
from optimum.onnxruntime import ORTModelForSequenceClassification
from transformers import AutoTokenizer, pipeline

model = ORTModelForSequenceClassification.from_pretrained(
    "cross-encoder/ms-marco-MiniLM-L-6-v2",
    export=True
)
tokenizer = AutoTokenizer.from_pretrained("cross-encoder/ms-marco-MiniLM-L-6-v2")
classifier = pipeline("text-classification", model=model, tokenizer=tokenizer)
```

**性能优势**:
- CPU推理: 比PyTorch快2-5x
- 支持INT8量化: 进一步2x加速
- 支持GPU(CUDA/TensorRT)加速
- 内存占用更低

**FlashRank的ONNX实践**:
FlashRank (978 stars) 是ONNX优化reranking的最佳实践:
- 完全基于ONNX Runtime，无需PyTorch
- 最小模型仅4MB (TinyBERT-L-2)
- CPU推理速度极快

### 3.5 FlashRank (ONNX优化，CPU最快)

**GitHub**: [PrithivirajDamodaran/FlashRank](https://github.com/PrithivirajDamodaran/FlashRank) (978 stars)

FlashRank是Python生态中最快的reranking库，完全基于ONNX Runtime:

```python
from flashrank import Ranker, RerankRequest

# 默认模型 ~4MB
ranker = Ranker(max_length=128)

# 更精确的模型 ~34MB
ranker = Ranker(model_name="ms-marco-MiniLM-L-12-v2")

# 多语言模型 ~150MB
ranker = Ranker(model_name="ms-marco-MultiBERT-L-12")

# LLM-based listwise reranker ~4GB
ranker = Ranker(model_name="rank_zephyr_7b_v1_full", max_length=1024)
```

**支持模型**:

| 模型 | 大小 | 说明 |
|------|------|------|
| `ms-marco-TinyBERT-L-2-v2` | ~4MB | 默认，最快 |
| `ms-marco-MiniLM-L-12-v2` | ~34MB | 最佳cross-encoder |
| `rank-T5-flan` | ~110MB | 最佳非cross-encoder |
| `ms-marco-MultiBERT-L-12` | ~150MB | 100+语言 |
| `rank_zephyr_7b_v1_full` | ~4GB | 4-bit GGUF量化 |

**关键优势**:
- 无需PyTorch/Transformers
- 极小包体积
- 支持AWS Lambda等serverless
- 支持Pairwise和Listwise reranking

| 量化 | INT8+AVX-512极高效率 | FP16/FP32浪费精度 |
| 并行度 | N workers x M threads | 单模型实例 |

|------|---------|-------------|--------------|

- **Jina vs CPU自建**: ~30万次/月

**结论**: 月搜索量超过10万次时，自建CPU方案(FashRank)已具成本优势；超过40万次时，自建GPU方案更划算。

### 7.2 各级别推荐场景

| 级别 | 推荐模型 | 适用场景 | 部署建议 |
|------|---------|---------|---------|
| **极致速度** | TinyBERT/MiniLM-L-6 | 实时搜索、高QPS、边缘设备 | FlashRank/Flash-Rerank, CPU |

- 支持100+语言(中英文论文)
- ~568M参数，资源需求适中
- 精度/速度最佳平衡
- 可通过TEI部署获得高性能

**备选方案**:
- 开发/测试环境: `ms-marco-MiniLM-L-12-v2` (FlashRank, CPU)

**代码示例**:
```python
from flashrank import Ranker, RerankRequest

ranker = Ranker(model_name="ms-marco-MiniLM-L-12-v2")

    request = RerankRequest(query=query, passages=documents)
```

## 九、技术难点与解决方案

### 9.1 冷启动问题

**问题**: PyTorch模型加载慢(10-30秒)
**解决**:
- TEI: 无编译步骤，快速启动
- FlashRank: ONNX模型<1秒加载
- 预热: 启动时发送dummy请求

### 9.2 长文档处理

**问题**: Cross-encoder通常限制512 tokens
**解决**:
- 截断策略: 取文档前512 tokens
- 分段重排: 将长文档分段，取最高分
- 使用支持长上下文的模型: rank_zephyr (8192 tokens)

### 9.3 多语言支持

**问题**: 英文模型在中文上表现差
**解决**:
- 使用多语言模型: `bge-reranker-v2-m3` (100+语言)
- 或 `gte-multilingual-reranker-base`
- 或 `ms-marco-MultiBERT-L-12`

### 9.4 内存优化

**问题**: 大模型显存不足
**解决**:
- INT8量化: 显存减半
- INT4量化(GPTQ/AWQ): 显存减至1/4
- CPU offloading: 部分层在CPU计算
- 模型并行: 多GPU分片
