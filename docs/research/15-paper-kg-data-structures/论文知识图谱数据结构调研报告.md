## 1. SciERC/SciER 科学实体与关系体系

### 1.1 SciERC 实体类型（6种）

SciERC (Luan et al., 2018) 是最权威的科学信息抽取基准数据集，来自500篇AI领域论文摘要的标注。

| 实体类型 | 定义 | 示例 |
|---------|------|------|
| **Task** | 研究任务、问题、目标 | NER, machine translation, sentiment analysis |
| **Method** | 算法、模型、技术、系统 | BERT, LSTM, transformer, CRF |
| **Material** | 数据集、语料库、资源、输入 | CoNLL-2003, ImageNet, Wikipedia |
| **Metric** | 评估指标、分数、性能指标 | F1 score, BLEU, accuracy |
| **Other-ScientificTerm** | 不属于其他类别的科技术语 | features, embeddings, attention |
| **Generic** | 通用科学术语（仅在参与关系时标注） | approach, model, system |

**来源**: https://nlp.cs.washington.edu/sciIE/ (SciERC官方)
**来源**: https://aclanthology.org/D18-1360.pdf (原始论文)

### 1.2 SciERC 关系类型（7种）

| 关系类型 | 方向性 | 定义 | 三元组示例 |
|---------|--------|------|----------|
| **USED-FOR** | 非对称 | B用于A，B建模A，A基于B | (BERT, USED-FOR, NER) |
| **FEATURE-OF** | 非对称 | B是A的特征/属性 | (prior knowledge, FEATURE-OF, model) |
| **HYPONYM-OF** | 非对称 | B是A的子类型 | (LSTM, HYPONYM-OF, RNN) |
| **PART-OF** | 非对称 | B是A的组成部分 | (attention layer, PART-OF, transformer) |
| **EVALUATE-FOR** | 非对称 | A用于评估B | (F1, EVALUATE-FOR, NER model) |
| **COMPARE** | 对称 | A与B进行比较 | (BERT, COMPARE, RoBERTa) |
| **CONJUNCTION** | 对称 | A和B并列出现 | (NER, CONJUNCTION, POS tagging) |

**来源**: https://aclanthology.org/D18-1360.pdf (SciERC原始论文)

### 1.3 SciER 扩展关系类型（9种）

SciER (Zhang et al., 2024) 在SciERC基础上，聚焦Dataset/Method/Task三种实体，定义了更精细的关系：

| 关系类型 | 方向性 | 定义 |
|---------|--------|------|
| **USED-FOR** | 非对称 | 方法用于任务 |
| **TRAINED-WITH** | 非对称 | 模型用数据集训练 |
| **EVALUATED-WITH** | 非对称 | 用指标评估 |
| **EVALUATED-ON** | 非对称 | 在数据集上评估 |
| **BENCHMARK-FOR** | 非对称 | 数据集是任务的基准 |
| **SUBCLASS-OF** | 非对称 | 子类关系 |
| **SUBTASK-OF** | 非对称 | 子任务关系 |
| **PART-OF** | 非对称 | 组成关系 |
| **COMPARE-WITH** | 对称 | 比较关系 |
| **SYNONYM-OF** | 对称 | 同义关系 |

**来源**: https://arxiv.org/html/2410.21155v1 (SciER论文)

### 1.4 SciNLP 扩展关系类型（11种）

SciNLP (Duan et al., 2025) 在NLP领域定义了4种实体和11种关系：

**实体**: Model, Task, Dataset, Metric

**关系**: MeasuredBy, UsedFor, TrainedWith, EnhancedBy, SubclassOf, SubtaskOf, PartOf, EvaluatedBy, EvaluatedOn, SimilarWith, CompareWith

**来源**: https://arxiv.org/html/2509.07801v3 (SciNLP论文)

### 1.5 关键发现：SciERC关系统计

在SciERC的1575个关系标注中（仅Dataset/Method/Task实体）：

| 关系类型 | 数量 | 占比 |
|---------|------|------|
| USED-FOR | 876 | 55.6% |
| CONJUNCTION | 292 | 18.5% |
| HYPONYM-OF | 154 | 9.8% |
| COMPARE | 78 | 5.0% |
| PART-OF | 78 | 5.0% |
| EVALUATION-FOR | 69 | 4.4% |
| FEATURE-OF | 28 | 1.8% |

**核心发现**: USED-FOR是最重要的关系类型，占据了超过一半的关系。这意味着"方法用于任务"是科学文献中最核心的知识结构。

**来源**: https://arxiv.org/html/2410.21155v1 (SciER论文 Table 5/6)

### 2.2 Open Research Knowledge Graph (ORKG)

ORKG的核心理念是**结构化描述研究论文**，使科学知识可被人和机器操作。

**ORKG数据模型核心概念**:
- **Paper (Research Contribution)**: 论文的研究贡献描述
- **Comparison**: 多篇论文按属性并排比较
- **Review**: 社区维护的综述，保持最新且机器可读
- **Template**: 结构化属性模板，标准化内容添加方式
- **List**: 围绕主题的论文策展集合

**ORKG比较属性示例**（生态学模板）:
- research_field, approach, taxonomic_coverage
- geographic_coverage, temporal_coverage, habitat
- sample_size, treatment, study_design

**ORKG关键特点**:
- 每篇论文平均分配更少的标注，但保持高数量的不重复类别标签
- 比PwC/OpenAlex更保守，平均每篇论文不到1个错误标注
- 支持按研究领域定制模板

**来源**: https://orkg.org
**来源**: https://sci-k.github.io/2025/papers/paper03.pdf (SKG比较论文)

### 2.3 Tree-KG 框架 (ACL 2025)

Tree-KG采用树状层次图结构：

**节点属性**: name, description, relations

**垂直边（层次关系）**:
- `has_subsection`: 节-子节
- `has_entity`: 子节-实体
- `has_subordinate`: 核心-非核心实体

**水平边（语义关系）**:
- 类别: `section_related` 或 `entity_related`
- 具体关系: LLM预测（如obey, has等）

**来源**: https://aclanthology.org/2025.acl-long.907.pdf (Tree-KG论文)

### 2.4 OntoKG 框架 (2026)

基于Wikidata 100M实体，通过内在-关系路由方法：

- **56个内在模块**: 路由到节点属性（用于查找）
- **38个关系模块**: 路由到图边（用于遍历）
- **8个类别**
- **38种关系类型**
- **34.0M节点，61.2M边**

**来源**: https://arxiv.org/html/2604.02618v1 (OntoKG论文)

### 2.5 生物医学GraphRAG的Neo4j Schema

一个生产级生物医学GraphRAG系统的7种节点类型：

- **Paper**: 论文（含摘要、embedding）
- **Author**: 作者
- **Institution**: 机构
- **MeSHTerm**: MeSH主题词
- **Qualifier**: MeSH限定词（后合并为关系属性）
- **Journal**: 期刊
- **Gene**: 基因

**关系类型**:
- `(Author)-[:WROTE]->(Paper)`
- `(Gene)-[:MENTIONED_IN]->(Paper)`
- `(Paper)-[:HAS_MESH_TERM {qualifiers: [...]}]->(MeshTerm)`

**来源**: https://aiechoes.substack.com/p/building-a-biomedical-graphrag-when

## 3. IMRaD章节级数据结构

### 3.1 标准IMRaD结构

| 章节 | 功能 | 应抽取的核心内容 |
|------|------|----------------|
| **Abstract** | 全文摘要 | 研究动机、方法概要、关键结果、意义 |
| **Introduction** | 研究背景与问题 | 背景、研究空白、假设、研究问题 |
| **Methods** | 研究方法 | 设计、对象/样本、测量、分析方法 |
| **Results** | 研究发现 | 数据、图表、观察结果 |
| **Discussion** | 解释与讨论 | 解释、比较、局限性、意义、建议 |

**来源**: https://en.wikipedia.org/wiki/IMRAD
**来源**: https://writingcenter.gmu.edu/writing-resources/imrad/writing-an-imrad-report

### 3.2 章节级实体抽取映射

基于研究发现，不同章节应抽取的实体类型：

| 章节 | 应抽取的实体类型 | 应抽取的关系 |
|------|----------------|------------|
| **Introduction** | Task, Other-ScientificTerm | research_gap_of, extends, addresses |
| **Methods** | Method, Material, Metric | uses, trained_with, implemented_with |
| **Results** | Method, Metric, Task | evaluated_on, outperforms, achieves |
| **Discussion** | Finding, Limitation, Gap | supports, contradicts, suggests_gap |
| **Conclusion** | Finding, InnovationPoint | contributes, demonstrates |

## 4. 论文声明/发现的结构化表示

### 4.1 科学声明的知识图谱表示

"this paper found X using Y on Z" 可以表示为结构化三元组：

```
Subject: [Finding/Claim]
Predicate: extracted_by / supported_by / evaluated_on
Object: [Method / Dataset / Metric]
```

**增强四元组表示**（含上下文）:
```
{
  "subject": {"text": "BERT outperforms LSTM", "type": "Finding"},
  "predicate": {"text": "achieved on", "type": "EVALUATED_ON"},
  "object": {"text": "CoNLL-2003 NER", "type": "Task+Material"},
  "context": "Using fine-tuned BERT-base, we achieved 92.4 F1 on CoNLL-2003 NER"
}
```

**来源**: https://arxiv.org/pdf/2508.03438 (Enhanced Triple Extraction)

### 4.2 声明抽取的关键字段

基于VLDB 2025 TaDA workshop的研究：

**Claim结构**:
- **finding**: 发现内容（主要声明）
- **evidence_type**: 证据类型（实验/观察/理论/统计）
- **confidence**: 置信度
- **source_table**: 来源表格（表格是声明的主要来源）
- **source_text**: 来源文本（补充信息分散在表格标题和正文中）
- **population**: 研究对象
- **intervention**: 干预措施
- **comparator**: 比较对象
- **outcome**: 结果
- **effect_size**: 效果大小

**来源**: https://www.vldb.org/2025/Workshops/VLDB-Workshops-2025/TaDA/TaDA25_16.pdf

### 4.3 Claimify方法（ACL 2025）

Claimify方法的声明抽取流程：

1. **句子分类**: 检测是否包含可验证内容
2. **分解**: 将复杂句子分解为原子声明
3. **去上下文化**: 使声明脱离原始上下文仍可理解
4. **元素级覆盖评估**: 量化遗漏和错误包含

**关键评估维度**:
- implicit vs explicit coverage（隐式vs显式覆盖）
- unverifiable content penalization（不可验证内容惩罚）

**来源**: https://aclanthology.org/2025.acl-long.348.pdf

## 5. 论文贡献与创新点表示

### 5.1 ICLR 2025 Novelty评估框架

基于对ICLR 2025评审的分析，新颖性评估包含4个步骤：

1. **结构化抽取**: 从论文中抽取关键贡献点
2. **文献检索**: 找到相关已有工作
3. **比较分析**: 与已有工作的差异
4. **新颖性判定**: 是否有实质性创新

**来源**: https://aclanthology.org/2026.eacl-long.121.pdf

### 5.2 科学新颖性度量方法分类

| 方法类型 | 数据来源 | 代表方法 |
|---------|---------|---------|
| 引用基 | 引用数据 | Uzzi et al. (2013) 组合新颖性 |
| 文本基 | 关键词/实体 | Mishra & Torvik (2016) |
| 文本基 | 句子/贡献 | Wang et al. (2024) 主题建模 |
| 混合基 | 多源 | Zhao & Zhang (2025) |

**公理化基准**（2025）:
- **覆盖公理**: 如果论文的声明已存在于已有文献池中，则新颖性较低
- **重组新颖性**: 组合已有知识也是有效的新颖性形式

**来源**: https://arxiv.org/html/2604.15145v1

### 5.3 贡献声明的结构化字段

| 字段 | 描述 | 示例 |
|------|------|------|
| `contribution_type` | 贡献类型 | new_method, new_dataset, new_task, theoretical, empirical |
| `novelty_claim` | 新颖性声明 | "首次将X应用于Y" |
| `key_innovation` | 核心创新点 | "引入了Z机制" |
| `improvement_over` | 改进了什么 | "相比BERT提升了3%" |
| `improvement_metric` | 改进指标 | F1, accuracy, BLEU |
| `improvement_value` | 改进值 | 0.03 |
| `baseline_methods` | 基线方法 | ["BERT", "RoBERTa"] |
| `datasets_used` | 使用的数据集 | ["CoNLL-2003", "SQuAD"] |

## 6. 研究空白与局限性表示

### 6.1 研究空白的分类框架

基于NCBI Bookshelf的系统评价框架：

**空白分类维度**:
1. **空白特征** (What is missing):
   - Missing data (数据缺失)
   - Inadequate information (信息不足)
   - Inconsistent results (结果不一致)
   - Underexplored populations (未充分研究的人群)
   - Underutilized methods (未充分利用的方法)

2. **空白原因** (Why it exists):
   - Ethical constraints (伦理约束)
   - Technical limitations (技术限制)
   - Funding gaps (资金缺口)
   - Population access (人群可及性)

**来源**: https://www.ncbi.nlm.nih.gov/books/NBK126702

### 6.2 研究空白的结构化表示

| 字段 | 描述 | 示例 |
|------|------|------|
| `gap_type` | 空白类型 | methodological, population, temporal, geographic, theoretical |
| `description` | 空白描述 | "缺乏对X人群的验证研究" |
| `identified_from` | 识别来源 | limitations_section, future_work, comparison |
| `source_papers` | 来源论文 | [paper_id_1, paper_id_2] |
| `related_limitations` | 相关局限性 | ["样本量小", "单一中心"] |
| `potential_impact` | 潜在影响 | "可能影响结论的泛化性" |
| `feasibility` | 填补可行性 | high, medium, low |
| `priority` | 优先级 | high, medium, low |

### 6.3 局限性的结构化表示

| 字段 | 描述 |
|------|------|
| `limitation_type` | 方法论/数据/范围/技术/泛化性 |
| `description` | 局限性描述 |
| `impact_on_results` | 对结果的影响 |
| `acknowledged_by_authors` | 作者是否承认 |
| `source_section` | 来源章节（limitation/future_work/discussion） |

## 7. 论文比较的数据结构

### 7.1 ORKG比较模型

ORKG的比较功能是其核心价值——按属性并排显示多篇论文：

**比较维度**:
- Research question / Problem addressed
- Method / Approach
- Dataset / Materials
- Key results / Performance metrics
- Limitations
- Year / Venue

**来源**: https://orkg.org

### 7.2 SciTables (EMNLP 2025 Findings)

自动生成论文比较表格的Schema：

**输入**: 多篇论文的标题、摘要、表格意图
**输出**: JSON格式的比较Schema

```json
{
  "research_question": {"definition": "...", "values": {"paper1": "...", "paper2": "..."}},
  "methodology": {"definition": "...", "values": {"paper1": "...", "paper2": "..."}},
  "dataset": {"definition": "...", "values": {"paper1": "...", "paper2": "..."}},
  "main_finding": {"definition": "...", "values": {"paper1": "...", "paper2": "..."}}
}
```

**来源**: https://aclanthology.org/2025.findings-emnlp.1274.pdf

### 7.3 论文比较的最小可行字段集

| 字段 | 用途 | 必要性 |
|------|------|--------|
| `research_question` | 对齐研究目标 | 必要 |
| `method_approach` | 方法对比 | 必要 |
| `datasets` | 数据集对比 | 必要 |
| `key_results` | 结果对比 | 必要 |
| `metrics` | 指标对比 | 必要 |
| `limitations` | 局限性对比 | 推荐 |

## 8. 文献综述生成的输入结构

### 8.1 综述类型与输入需求

| 综述类型 | 描述 | 输入结构需求 |
|---------|------|------------|
| Narrative | 描述性综述 | 主题分组的论文列表 |
| Systematic | 系统综述 | 结构化数据提取表 |
| Meta-Analysis | 元分析 | 可比较的数值结果 |

## 10. 知识图谱构建Pipeline

### 10.1 端到端KG构建流程

基于多篇2025年论文的综合：

```
1. 文档预处理
   └─ PDF解析 → 章节识别 → 句子分割

2. 本体归纳（Ontology Induction）
   └─ LLM生成能力问题(CQs) → 定义实体类型 → 定义关系类型

3. 实体抽取（NER）
   └─ 章节感知NER → 实体标准化 → 实体消歧

4. 关系抽取（RE）
   └─ 实体对候选 → 关系分类 → 置信度过滤

5. 三元组组装
   └─ (Subject, Predicate, Object) + Context

6. 实体对齐与去重
   └─ 跨论文实体链接 → 同义实体合并

7. 图组装与验证
   └─ 写入图数据库 → LLM-as-Judge验证

8. 质量评估
   └─ 精度/召回/F1 → 语义质量评分
```

**来源**: https://arxiv.org/html/2510.20345v1 (LLM-empowered KG survey)
**来源**: https://openreview.net/forum?id=NiUl3EkvIW (Hybrid End-to-End KG)
