```
                              │

          ┌───────────────────┼───────────────────┐
```

**7角色多Agent系统**：

| 角色 | 主要职责 | 专业技能 |
|------|----------|----------|
| 浏览器代理 (Browser Agent) | 初步网络调研，收集相关资源 | 信息检索、快速筛选 |
| 编辑者代理 (Editor Agent) | 规划报告大纲和结构 | 结构化思维、内容规划 |
| 研究者代理 (Researcher Agent) | 深入分析每个子主题 | 领域知识、批判性思维 |
| 审核者代理 (Reviewer Agent) | 验证内容准确性和相关性 | 事实核查 |
| 修订者代理 (Revisor Agent) | 根据审阅结果对内容修订 | 内容优化、逻辑调整 |
| 撰写者代理 (Writer Agent) | 整合所有内容形成最终报告 | 报告撰写、文案组织 |
| 发布者代理 (Publisher Agent) | 将报告导出为多种格式 | PDF/Word/Markdown |

### 1.2 核心实现

**深度研究 (Deep Research) 核心实现**：

```python
# 来源：gpt_researcher/skills/deep_research.py
class DeepResearchSkill:
    def generate_search_queries(self, query):
        """生成多个搜索查询进行广度探索"""
        pass
    
    def process_query(self, query):
        """并行处理研究任务"""
        pass
    
    def deep_research(self, query, depth, breadth):
        """递归深度探索"""
        if depth > 1:
            new_breadth = max(2, breadth // 2)
            # 递归深入子主题
            for sub_query in sub_queries:
                self.deep_research(sub_query, depth-1, new_breadth)
```

**树状探索模式**：
- **广度 (Breadth)**：每层生成多个搜索查询探索主题不同方面
- **深度 (Depth)**：每个分支递归深入挖掘
- **并发处理**：异步/await模式同时运行多个研究路径
- **上下文聚合**：自动汇总并综合所有分支研究发现
- **进度追踪**：实时更新研究的广度和深度维度进展

### 1.3 数据流

```
输入: 用户研究主题
  │
  ▼
[任务规划] → 生成研究问题列表
  │
  ▼
[并行搜索] → 多源检索 (20+搜索引擎)
  │
  ▼
[信息提取] → 爬取网页内容、去重、过滤
  │
  ▼
[向量存储] → pgvector/HuggingFace嵌入
  │
  ▼
[上下文压缩] → 智能摘要与信息提取
  │
  ▼
[报告生成] → 整合多源信息生成最终报告
  │
  ▼
输出: Markdown/PDF/Word格式研究报告
```

**成本与性能**：
- 平均完成时间：约5分钟
- 研究成本：约0.1美元（使用o3-mini模型，"high"推理强度）
- 支持100+种LLM

### 1.4 优缺点

| 优点 | 缺点 |
|------|------|
| ✅ 多Agent协作，分工明确 | ❌ 需要较强计算资源 |
| ✅ 并行处理，速度快 | ❌ 需要配置LLM API |
| ✅ 多源信息聚合(20+来源) | ❌ 成本较高（深度研究模式） |
| ✅ 支持本地文档+在线研究 | ❌ arXiv国内不可访问 |
| ✅ 树状递归探索，研究深入 | ❌ 配置相对复杂 |
| ✅ LangGraph框架，可扩展 | ❌ 需要网络连接 |
| ✅ 100+LLM支持 | |

### 1.5 可借鉴设计

1. **Plan-and-Solve双代理架构**：规划代理生成问题，执行代理收集信息，分工明确
2. **深度研究树状探索**：广度×深度的递归研究策略

4. **7角色分工**：专业人做专业事

```
                              │
                              ▼
```

### 3.2 核心实现

**n8n节点流程**：

```
[Schedule Trigger] → 定时触发 (Cron: 0 8 * * *)
     │
     ▼
[RSS Feed Read] → 获取多个RSS源
     │
     ▼
[Merge] → 合并多源数据
     │
     ▼
[Remove Duplicates] → MD5去重
     │
     ▼

     │
     ▼

     │
     ▼

     │
     ▼
[HTTP Request] → 抓取正文内容
     │
     ▼
[Code] → 数据清洗
     │
     ▼

     │
     ▼

     │
     ▼
```

### 4.2 核心模块

### 4.3 学术日报五章结构

| 章节 | 内容 | Prompt要求 |
|------|------|------------|

| 二、核心论文分析 | 论文问题/方法/结果/局限 | 每篇论文深度分析 |
| 三、主要研究发现 | 跨论文发现聚合 | 创新点提炼 |

### 4.4 日期合规性检查

**核心约束**：被分析论文的发表日期必须早于报告日期

```python
def validate_paper_date(papers: list, report_date: str) -> list:
    """过滤掉year > 报告年份的论文"""
    report_year = int(report_date.split('-')[0])
    valid_papers = []
    for paper in papers:
        if paper.get('year', 0) <= report_year:
            valid_papers.append(paper)
        else:
            # 标注预印本/待发表状态
            paper['warning'] = "未来日期论文"
    return valid_papers
```

### 5.2 学术日报系统设计建议

**推荐架构**（融合三者优点）：

1. **多Agent协作**（借鉴GPT-Researcher）
   - 文献检索Agent：多源检索（arXiv/CrossRef/语义 Scholar）
   - 论文分析Agent：深度阅读+结构化提取
   - 审核Agent：事实核查+日期合规性验证
   - 写作Agent：五章结构报告生成

2. **工作流自动化**（借鉴n8n）
   - 定时触发：每日早8点自动执行
   - 三层架构：采集/处理/输出解耦
   - 向量检索：pgvector智能相关性匹配

3. **极简交互**（借鉴weekly_report）
   - 用户输入：主题 + 日期 + 论文列表
   - 一键生成：Markdown格式日报
   - 多格式导出：PDF/HTML/Word

### 5.3 技术选型建议

| 组件 | 推荐方案 | 理由 |
|------|----------|------|
| Agent框架 | LangGraph | 支持循环、条件分支、多Agent协作 |
| LLM | MiniMax/DeepSeek | 成本低，支持长上下文 |
| 向量数据库 | pgvector | 支持混合检索，开源稳定 |
| 搜索源 | CrossRef + Semantic Scholar | arXiv国内不可用 |
| Embedding | Qwen3-Embedding-0.6B | 本地运行，无需API |
| 前端 | Next.js + Tailwind | 快速开发，美观展示 |

### 5.4 关键实现要点

1. **日期合规性**：必须过滤year > 报告年份的论文
2. **多源检索**：arXiv不可用时fallback到CrossRef
3. **并行处理**：asyncio.gather实现章节并行生成
4. **快速降级**：Embedding不可用时使用关键词过滤（限制条件）
5. **迭代限制**：Polish阶段限制迭代次数，快速失败
6. **引用追踪**：citation_tracker实现引用图构建
