# 当前开发计划：论文知识库分析 Agent

更新日期：2026-05-28

本文档融合本目录下原有开发计划、详细执行计划和模块拆解，并结合当前代码状态，形成后续开发执行计划。

## 1. 当前开发原则

开发主线：

```text
论文入库
  -> 论文结构化
  -> 证据表
  -> 知识图谱
  -> 选择范围 QA
  -> 文献综述
  -> 创新点报告
```

三类中间层必须先建立：

```text
Paper Card
Evidence Record
Knowledge Graph
```

两个正式输出：

```text
Literature Review
Innovation Report
```

落地原则：

- 先打通最小闭环，再增强图谱和报告质量。
- 先用 JSON 文件存储，后续再迁移 SQLite、ChromaDB 或图数据库。
- 先复用现有搜索、PDF 解析、RAG、写作、引用模块，再考虑重构。
- 当前新能力落地在 `src/agents_v3/research_workspace`。
- 所有阶段都必须有测试和验收标准。

## 5. Phase 1：项目论文库与论文入库

目标：

```text
用户可以创建项目，添加论文元数据，上传 PDF，检索论文，导入 DOI/BibTeX/RIS，并管理纳入/排除状态。
```

后端模块：

```text
paper_library.py
```

核心能力：

```python
add_uploaded_paper()
add_search_results()
import_references()
list_papers()
get_paper()
update_paper()
mark_included()
mark_excluded()
get_library_stats()
```

数据要求：

- `Paper` 必须绑定 `project_id`。
- 论文可标记 `included` 和 `exclude_reason`。
- DOI、URL、title 应做基础去重。
- PDF 只保存路径和元数据，不把大文件写入 JSON。

API：

```text
POST /api/rw/projects
GET  /api/rw/projects
GET  /api/rw/projects/{project_id}
PUT  /api/rw/projects/{project_id}
DELETE /api/rw/projects/{project_id}

POST /api/rw/projects/{project_id}/papers/upload
POST /api/rw/projects/{project_id}/papers/search
POST /api/rw/projects/{project_id}/papers/import
GET  /api/rw/projects/{project_id}/papers
GET  /api/rw/papers/{paper_id}
PUT  /api/rw/papers/{paper_id}
POST /api/rw/papers/{paper_id}/include
POST /api/rw/papers/{paper_id}/exclude
```

测试：

```text

test_project_service.py
```

验收标准：

```text
能创建项目
能新增论文元数据
能列出项目论文
能 include/exclude
能基础去重
所有数据可从 JSON 恢复
```

## 6. Phase 2：论文解析、论文卡片、证据表

目标：

```text
将论文从“文件和元数据”转成 PaperChunk、PaperCard、EvidenceRecord。
```

后端模块：

```text
parser_service.py
paper_card.py
evidence_table.py
```

ParserService：

```python
parse_pdf(paper_id: str) -> list[PaperChunk]
parse_metadata(paper_id: str) -> Paper
split_text(paper_id: str, text: str) -> list[PaperChunk]
```

PaperCardGenerator：

```python
generate_card(paper_id: str) -> PaperCard
batch_generate_cards(project_id: str) -> list[PaperCard]
```

EvidenceTableService：

```python
generate_from_card(card_id: str) -> list[EvidenceRecord]
generate_project_evidence(project_id: str) -> list[EvidenceRecord]
list_evidence(project_id: str, filters: dict | None = None) -> list[EvidenceRecord]
```

质量要求：

- 找不到字段时写 `unknown`，不能编造。
- 关键字段尽量保留 `SourceSpan` 或 `source_quote`。
- EvidenceRecord 必须可追溯到 `paper_id` 和 chunk。

API：

```text
POST /api/rw/papers/{paper_id}/parse
POST /api/rw/projects/{project_id}/parse
POST /api/rw/papers/{paper_id}/card
POST /api/rw/projects/{project_id}/cards
POST /api/rw/projects/{project_id}/evidence
GET  /api/rw/projects/{project_id}/evidence
```

测试：

```text
test_parser_service.py
test_paper_card.py
test_evidence_table.py
```

验收标准：

```text
能生成 chunks
能生成 PaperCard
能生成 EvidenceRecord
EvidenceRecord 可按 project_id 和 paper_id 查询
卡片和证据均有来源字段
```

## 7. Phase 3：知识图谱与 Retrieval Scope

目标：

```text
基于论文卡片和证据表构建轻量知识图谱，并支持用户选择论文、主题、方法、年份、节点或子图作为 Scope。
```

后端模块：

```text
graph_service.py
scope.py
```

GraphService：

```python
build_graph(project_id: str) -> KnowledgeGraph
get_graph(project_id: str) -> KnowledgeGraph
get_node(project_id: str, node_id: str) -> GraphNode | None
get_subgraph(project_id: str, node_ids: list[str], hops: int = 1) -> KnowledgeGraph
find_gaps(project_id: str) -> list[GraphNode]
```

RetrievalScopeService：

```python
resolve_scope(project_id: str, scope: RetrievalScope) -> RetrievalScope
summarize_scope(scope: RetrievalScope) -> str
get_scope_context(scope: RetrievalScope) -> dict
```

图谱构建规则：

```text
Paper -> BELONGS_TO_TOPIC -> Topic
Paper -> USES_METHOD -> Method
Paper -> REPORTS_FINDING -> Finding
Paper -> HAS_LIMITATION -> Limitation
Limitation -> SUGGESTS_GAP -> Gap
```

API：

```text
POST /api/rw/projects/{project_id}/kg/build
GET  /api/rw/projects/{project_id}/kg
GET  /api/rw/projects/{project_id}/kg/nodes/{node_id}
POST /api/rw/projects/{project_id}/kg/subgraph
POST /api/rw/projects/{project_id}/scope/resolve
```

测试：

```text
test_graph_service.py
test_scope.py
```

验收标准：

```text
能生成图谱节点和边
能查询节点和子图
能解析 RetrievalScope
Scope summary 能清楚说明当前范围
```

## 8. Phase 4：Scope-based QA

目标：

```text
用户基于选定 Scope 提问，系统只在该范围内检索和回答，并返回证据来源。
```

后端模块：

```text
scope_qa.py
```

ScopeQAService：

```python
answer(project_id: str, request: QARequest) -> QAResponse
classify_intent(question: str) -> str
retrieve_context(scope: RetrievalScope, question: str) -> dict
format_answer(context: dict, question: str) -> QAResponse
```

QA 意图：

```text
summary
method_compare
limitation_analysis
gap_analysis
evidence_check
innovation_seed
review_material
```

回答要求：

- 必须声明回答范围。
- 必须返回 `supporting_papers`。
- 必须返回 `evidence_records`。
- 不确定时必须说明 uncertainty。
- 不允许引用 Scope 外论文。

API：

```text
POST /api/rw/projects/{project_id}/qa
GET  /api/rw/projects/{project_id}/qa/sessions
GET  /api/rw/projects/{project_id}/qa/sessions/{session_id}
```

测试：

```text
test_scope_qa.py
test_scope_guard.py
```

验收标准：

```text
能基于选中论文 QA
能基于主题或子图 QA
回答有范围声明
回答有证据来源
QA 不越界引用
```
