## 1. 当前开发原则

开发主线：

```text
论文入库
  -> 论文结构化
  -> 证据表
  -> 知识图谱
  -> 选择范围 QA
  -> 文献综述
  -> 创新点报告
```

三类中间层必须先建立：

```text
Paper Card
Evidence Record
Knowledge Graph
```

两个正式输出：

```text
Literature Review
Innovation Report
```

落地原则：

- 先打通最小闭环，再增强图谱和报告质量。
- 先用 JSON 文件存储，后续再迁移 SQLite、ChromaDB 或图数据库。
- 先复用现有搜索、PDF 解析、RAG、写作、引用模块，再考虑重构。
- 当前新能力落地在 `src/agents_v3/research_workspace`。
- 所有阶段都必须有测试和验收标准。

## 6. Phase 2：论文解析、论文卡片、证据表

目标：

```text
将论文从”文件和元数据”转成 PaperChunk、PaperCard、EvidenceRecord。
```

技术借鉴：

```text
PDF 解析与分块：RAGFlow Parent-Child Chunking + DeepDoc
  -> Parent chunk 保持上下文，Child chunk 用于精确检索
  -> 检索命中 child，返回 parent 给 LLM

检索增强：Anthropic Contextual Retrieval
  -> 每个 chunk prepend 上下文摘要（论文标题 + 章节 + 前后文概述）
  -> 同时维护 BM25 索引，混合检索减少 67% 失败

证据表增强：Consensus Claims & Evidence Table + Elicit 数据提取
  -> EvidenceRecord 增加 evidence_direction 和 consensus_level 字段
  -> 支持 Evidence Matrix（topic × method × year）和 Gap Matrix
```

后端模块：

```text
parser_service.py
paper_card.py
evidence_table.py
```

ParserService：

```python
parse_pdf(paper_id: str) -> list[PaperChunk]
parse_metadata(paper_id: str) -> Paper
split_text(paper_id: str, text: str) -> list[PaperChunk]
generate_context_summary(chunk: PaperChunk, paper: Paper) -> str  # 新增：上下文摘要
```

PaperCardGenerator：

```python
generate_card(paper_id: str) -> PaperCard
batch_generate_cards(project_id: str) -> list[PaperCard]
```

EvidenceTableService：

```python
generate_from_card(card_id: str) -> list[EvidenceRecord]
generate_project_evidence(project_id: str) -> list[EvidenceRecord]
list_evidence(project_id: str, filters: dict | None = None) -> list[EvidenceRecord]
```

质量要求：

- 找不到字段时写 `unknown`，不能编造。
- 关键字段尽量保留 `SourceSpan` 或 `source_quote`。
- EvidenceRecord 必须可追溯到 `paper_id` 和 chunk。

## 7. Phase 3：知识图谱与 Retrieval Scope

目标：

```text
基于论文卡片和证据表构建轻量知识图谱，并支持用户选择论文、主题、方法、年份、节点或子图作为 Scope。
```

技术借鉴：

```text
知识图谱节点/边设计：Literature Mapper（typed nodes/edges + ghost paper detection）
  -> 增加 GhostPaper 节点（被引用但不在库中的论文）
  -> 增加 CONTRADICTS / EXTENDS / SUPPORTS 关系类型

Gap Detection 增强：Literature Mapper + Inciteful
  -> 识别 GhostPaper：被引用但不在库中的论文
  -> 分析图谱稀疏区域：连接数低于阈值的节点/子图
  -> 聚合共同 Limitation 节点和 Future Work 交集
  -> 链接预测算法（Adamic-Adar、Jaccard）预测潜在连接

Scope-based QA 检索：Anthropic Contextual Retrieval
  -> 向量检索 + BM25 混合，metadata filtering 限定 Scope
```

```text

```

## 8. Phase 4：Scope-based QA

目标：

```text
用户基于选定 Scope 提问，系统只在该范围内检索和回答，并返回证据来源。
```

技术借鉴：

```text
检索方案：Anthropic Contextual Retrieval
  -> 上下文嵌入 + BM25 混合检索（减少 67% 失败检索）
  -> Metadata filtering 限定 Scope

幻觉检测：LettuceDetect
  -> Token-level 幻觉检测（ModernBERT，F1=79.22%，MIT 开源）
  -> 支持 8192 tokens，tiny variants 17-68M 参数适合生产部署
  -> 依赖：pip install lettucedetect

质量指标：Atlas H/V ratio
  -> H/V ratio = 幻觉断言数 / 总断言数（目标 < 0.1）
```

后端模块：

```text
scope_qa.py
quality_control.py  # 新增：幻觉检测模块
```

ScopeQAService：

```python
answer(project_id: str, request: QARequest) -> QAResponse
classify_intent(question: str) -> str
retrieve_context(scope: RetrievalScope, question: str) -> dict
format_answer(context: dict, question: str) -> QAResponse
check_hallucination(answer: QAResponse) -> QAResponse  # 新增：幻觉检测
```

QA 意图：

```text
summary
method_compare
limitation_analysis
gap_analysis
evidence_check
innovation_seed
review_material
```

回答要求：

- 必须声明回答范围。
- 必须返回 `supporting_papers`。
- 必须返回 `evidence_records`。
- 不确定时必须说明 uncertainty。
- 不允许引用 Scope 外论文。
- 必须返回 `hallucination_risk` 标记（LettuceDetect 检测结果）。

API：

```text
POST /api/rw/projects/{project_id}/qa
GET  /api/rw/projects/{project_id}/qa/sessions
GET  /api/rw/projects/{project_id}/qa/sessions/{session_id}
```

测试：


验收标准：

```text

回答有证据来源
```

## 9. Phase 5：文献综述与创新点报告

目标：

```text
基于 Scope、论文卡片、证据表和图谱生成两个正式成果物。
```

技术借鉴：

```text
综述生成：GPT-Researcher Review-Revise 循环
  -> WriterAgent 生成初稿 -> ReviewerAgent 审查 -> RevisorAgent 修订
  -> 上下文压缩：论文数 > 阈值时按主题分组摘要

创新点报告：GPT-Researcher 树状图谱探索 + PapersFlow 反证检测
  -> 递归遍历图谱找 gap（可配置 depth/breadth）
  -> Critic Agent 自动搜索反对证据
  -> Chain of Verification：提取声明 -> 逐一验证 -> 标记状态

质量控制：LettuceDetect + Atlas H/V ratio + PRISMA-trAIce
  -> Token-level 幻觉检测（F1=79.22%）
  -> H/V ratio 目标 < 0.1
  -> 报告透明元数据（论文列表、Scope、LLM 版本、人工操作记录）
```

后端模块：


### 17.2 具体实现方案

#### 17.2.1 检索模块增强（Phase 2-3）

借鉴来源：Anthropic Contextual Retrieval + RAGFlow

实现步骤：

```text
1. PDF 解析后，每个 chunk 生成上下文摘要（论文标题 + 章节名 + 前后文概述）
2. 将上下文摘要 prepend 到 chunk 文本前，再生成 embedding
3. 同时维护 BM25 索引（基于原始文本）
4. 检索时融合向量检索和 BM25 结果，用 RRF 或加权排序
5. 可选：增加 Reranking 步骤（用 cross-encoder）
```

效果预期：减少 49-67% 失败检索。

对应文件：

```text
src/agents_v3/research_workspace/parser_service.py  -> 增加上下文摘要生成
src/agents_v3/research_workspace/retrieval.py       -> 新增混合检索
```

#### 17.2.2 幻觉检测（Phase 4-5）

借鉴来源：LettuceDetect + Atlas H/V ratio

实现步骤：

```text
1. 在 QA 回答和报告生成后，对每个声明进行 token-level 幻觉检测
2. 使用 LettuceDetect（MIT 开源，17-68M 参数，支持 8192 tokens）
3. 计算 H/V ratio = 幻觉断言数 / 总断言数
4. 将 H/V ratio 作为报告质量指标（目标 < 0.1）
5. 对高幻觉风险的段落标记警告
```

对应文件：

```text
src/agents_v3/research_workspace/quality_control.py  -> 新增幻觉检测模块
```

依赖：

```text
pip install lettucedetect
```

#### 17.2.3 反证检测（Phase 5）

借鉴来源：PapersFlow Critic Agent + Chain of Verification

实现步骤：

```text
1. 综述和创新点生成后，提取所有关键声明
2. 对每个声明，在论文库中搜索支持证据和反对证据
3. 标记每个声明的验证状态：supported / contradicted / unverified
4. 在创新点报告中增加"限制或反对证据"字段
5. 在综述中标记"争议点"和"证据不足"的观点
```

对应文件：

```text
src/agents_v3/research_workspace/innovation_generator.py  -> 增加反证检测
src/agents_v3/research_workspace/review_generator.py      -> 增加声明验证
```

#### 17.2.4 知识图谱 Gap Detection（Phase 3）

借鉴来源：Literature Mapper + Inciteful

实现步骤：

```text
1. 构建知识图谱时，识别"ghost papers"（被引用但不在库中的论文）
2. 分析图谱稀疏区域：连接数低于阈值的节点/子图
3. 聚合多篇论文的共同 Limitation 节点
4. 聚合 Future Work 节点的交集
5. 使用链接预测算法（如 Adamic-Adar、Jaccard）预测潜在连接
6. 将发现的 gap 标记为 Gap 节点，关联到支撑的 Limitation 节点
```

对应文件：

```text
src/agents_v3/research_workspace/graph_service.py  -> 增加 find_gaps() 增强
```

#### 17.2.5 Review-Revise 循环（Phase 5）

借鉴来源：GPT-Researcher

实现步骤：

```text
1. 综述/创新点生成后，启动 Reviewer Agent 审查
2. Reviewer 检查：结构完整性、证据覆盖、引用准确性、逻辑连贯性
3. Reviewer 输出审查意见（结构化 JSON）
4. Revisor Agent 根据审查意见修订
5. 可配置迭代轮数（默认 1 轮）
```

对应文件：

```text
src/agents_v3/research_workspace/review_generator.py      -> 增加 review_revise()
src/agents_v3/research_workspace/innovation_generator.py  -> 增加 review_revise()
```

#### 17.2.6 报告透明元数据（Phase 5）

借鉴来源：PRISMA-trAIce

实现步骤：

```text
1. 每份报告记录：使用的论文列表、Scope、LLM 版本、生成时间
2. 记录人工确认的操作（哪些内容被用户确认/修改）
3. 记录排除的论文及排除理由
4. 报告头部增加元数据块（类似 PRISMA 流程图）
```

对应文件：

```text
src/agents_v3/research_workspace/models.py  -> Report 模型增加透明元数据字段
src/agents_v3/research_workspace/report_service.py  -> 记录生成过程
```

#### 17.2.7 Evidence Table 增强（Phase 2）

借鉴来源：Consensus Claims & Evidence Table + Elicit

实现步骤：

```text
1. EvidenceRecord 增加 evidence_direction 字段：supporting / contrasting / mentioning
2. 增加 consensus_level 字段：strong_agreement / agreement / mixed / disagreement / insufficient
3. 按 topic × method × year 构建 Evidence Matrix 视图
4. 支持从证据表直接生成 Gap Matrix（哪些 cell 为空）
```

对应文件：

```text
src/agents_v3/research_workspace/models.py         -> EvidenceRecord 增加字段
src/agents_v3/research_workspace/evidence_table.py -> 增加 matrix 构建
```
