# 当前产品方案：论文知识库分析 Agent

更新日期：2026-06-01

本文档融合本目录下原有产品方案、模块拆解和开发计划，形成当前产品定义。原始资料保留为调研和设计来源。详细模块级开发计划见 `docs/research/14-细致开发计划/模块级开发计划/`。

## 1. 产品定位

产品名称：

```text
论文知识库分析 Agent
```

一句话定义：

> 用户上传、检索或导入一批论文后，系统自动解析论文、生成论文卡片、证据表和知识图谱；用户可以选择论文、主题或图谱子图进行问答，并基于选定范围生成可追溯的文献综述和创新点报告。

产品不是“论文代写工具”，而是“论文知识库分析工具”。

核心主线：

```text
研究项目
  -> 论文库
  -> 论文解析
  -> 论文卡片
  -> 证据表
  -> 知识图谱
  -> 范围选择 QA
  -> 文献综述
  -> 创新点报告
```

## 2. 目标用户

| 用户 | 核心需求 |
| --- | --- |
| 本科生 | 快速理解一批论文，形成选题依据和综述初稿。 |
| 硕士生 | 管理项目论文库，分析研究空白，沉淀创新点。 |
| 早期研究者 | 对多个方向做证据聚合、主题比较和研究机会发现。 |
| 指导者或课程使用者 | 检查学生是否基于真实文献形成研究判断。 |

## 3. 解决的问题

当前用户面对一批论文时，常见问题是：

- 论文太多，难以形成结构化认识。
- QA 工具只能回答单篇或全库，缺少可控回答范围。
- 文献综述容易变成泛泛总结，缺少证据表和来源追溯。
- 创新点容易变成灵感列表，缺少文献基础、空白来源和可行性判断。
- 论文关系、主题、方法、局限和 gap 不可视化，难以发现研究机会。

本产品的解决方式：

- 用项目论文库沉淀资料。
- 用论文卡片和证据表把论文结构化。
- 用知识图谱表示论文之间的主题、方法、发现、局限和 gap。
- 用 Retrieval Scope 控制 QA 和报告生成范围。
- 用文献综述和创新点报告作为正式输出。
- 用分层质量控制（幻觉检测、声明验证、反证搜索）保证输出可信度。

## 4. 产品边界

### 要做

| 功能 | 说明 |
| --- | --- |
| 研究项目 | 每个研究主题创建一个项目。 |
| 论文库 | 支持上传 PDF、检索论文、导入 DOI/BibTeX/RIS。 |
| 论文解析 | 抽取元数据、全文、章节、参考文献和文本块。Parent-Child Chunking。 |
| 论文卡片 | 抽取研究问题、方法、数据、发现、局限、未来工作。 |
| 证据表 | 将论文卡片转成项目级 evidence records。含 evidence_direction 和 consensus_level。 |
| 知识图谱 | 构建 Paper、Topic、Method、Dataset、Finding、Limitation、Gap、GhostPaper 等节点和关系。含 Gap Detection 增强。 |
| Retrieval Scope | 允许用户选择论文、主题、方法、年份或图谱子图作为回答范围。 |
| Scope-based QA | 基于选定范围回答问题，答案带范围声明、证据来源和幻觉风险标记。Contextual Retrieval + BM25 混合检索。 |
| 文献综述 | 基于选定范围生成正式综述。含 Review-Revise 循环和上下文压缩。 |
| 创新点报告 | 基于证据表、图谱 gap、共同局限和 future work 生成创新点。含反证检测和 Chain of Verification。 |
| 来源追溯 | QA、综述、创新点都能追溯到论文、证据记录和图谱节点。 |
| 质量控制 | 分层质量控制：检索质量、生成约束、幻觉检测（LettuceDetect）、声明验证、人工确认、报告透明元数据。 |

### 暂不做

| 不做 | 原因 |
| --- | --- |
| 全文论文代写 | 产品边界过大，且合规风险高。 |
| 论文润色和降重 | 会偏离研究分析主线。 |
| 复杂 Word 排版 | MVP 阶段用 Markdown 导出即可。 |
| 答辩 PPT | 可作为后续扩展。 |
| 多人协作 | 先打通单用户研究项目闭环。 |
| 重型 Neo4j/复杂 GraphRAG | MVP 先用轻量图谱和可追溯证据验证价值。 |

## 5. 核心概念

### Research Project

研究项目是所有资料和成果的容器。

字段：

```text
project_id
name
description
discipline
education_level
research_goal
created_at
updated_at
metadata
```

### Paper Library

项目论文库保存论文元数据、来源、解析状态和纳入排除状态。

论文来源：

```text
上传 PDF
关键词检索
DOI / BibTeX / RIS 导入
```

### Paper Card

论文卡片是单篇论文的结构化摘要。

字段：

```text
研究问题
研究方法
数据或样本
核心发现
局限
未来工作
主题
可能 gap
来源片段
置信度
```

### Evidence Table

证据表是文献综述和 QA 的核心中间层。借鉴 Elicit 的数据提取工作流（99.4% 准确率）和 Consensus 的 Claims & Evidence Table 模式。

字段：

```text
evidence_id
paper_id
project_id
research_question
method
data_or_sample
finding
limitation
future_work
topic
evidence_strength
evidence_direction      # supporting / contrasting / mentioning（借鉴 Scite）
consensus_level         # strong_agreement / agreement / mixed / disagreement / insufficient（借鉴 Consensus）
citation_context
source_chunk_id
source_quote
```

### Knowledge Graph

知识图谱表达论文库中的学术关系。节点和关系设计借鉴 Connected Papers、ResearchRabbit、Literature Mapper（typed nodes/edges + ghost paper detection）和 Inciteful（链接预测算法找 gap）。

节点：

```text
Paper
Author
Topic
Task
Method
Dataset
Finding
Limitation
Gap
InnovationPoint
GhostPaper              # 被引用但不在库中的论文（借鉴 Literature Mapper）
```

关系：

```text
Paper -> BELONGS_TO_TOPIC -> Topic
Paper -> STUDIES_TASK -> Task
Paper -> USES_METHOD -> Method
Paper -> USES_DATASET -> Dataset
Paper -> REPORTS_FINDING -> Finding
Paper -> HAS_LIMITATION -> Limitation
Limitation -> SUGGESTS_GAP -> Gap
Gap -> SUPPORTS_INNOVATION -> InnovationPoint
Paper -> CITES -> Paper
Paper -> CONTRADICTS -> Paper          # 引用立场（借鉴 Scite）
Paper -> EXTENDS -> Paper              # 扩展关系（借鉴 Literature Mapper）
Finding -> SUPPORTS -> Finding         # 支持关系
Finding -> CONTRADICTS -> Finding      # 矛盾关系
```

Gap Detection 增强（借鉴 Literature Mapper + Inciteful）：

```text
1. 识别 GhostPaper：被引用但不在库中的论文
2. 分析图谱稀疏区域：连接数低于阈值的节点/子图
3. 聚合多篇论文的共同 Limitation 节点
4. 聚合 Future Work 节点的交集
5. 链接预测：Adamic-Adar、Jaccard 算法预测潜在连接
```

### Retrieval Scope

Retrieval Scope 是用户当前选择的回答范围。

范围类型：

```text
全项目论文库
选中的论文
主题分组
方法分组
年份范围
知识图谱节点
知识图谱子图
创新点相关论文集合
```

示例：

```json
{
  "project_id": "proj_001",
  "paper_ids": ["p1", "p2", "p3"],
  "topic_ids": ["llm_feedback"],
  "graph_node_ids": ["method_rag", "gap_learning_log"],
  "include_neighbors": true,
  "graph_hops": 2,
  "time_range": ["2021", "2026"]
}
```

### Scope-based QA

QA 不是普通聊天，而是基于范围的研究分析入口。检索采用 Anthropic Contextual Retrieval 方案（上下文嵌入 + BM25 混合检索，减少 67% 失败检索）。

答案必须包含：

```text
回答内容
范围声明
支撑论文
证据记录
图谱路径
不确定性说明
建议动作
幻觉风险标记                    # 使用 LettuceDetect token-level 检测（F1=79.22%）
```

### Literature Review

文献综述是正式成果物之一，基于选定 Scope、论文卡片、证据表和图谱上下文生成。借鉴 GPT-Researcher 的 Review-Revise 循环（Writer→Reviewer→Revisor）和上下文压缩（按主题分组摘要）。

默认结构：

```text
1. 研究背景
2. 主题划分
3. 代表性文献和研究脉络
4. 主要研究方法
5. 主要研究结论
6. 现有研究不足（含争议点标记）
7. 未来研究趋势
8. 参考文献
```

生成流程（借鉴 GPT-Researcher Review-Revise）：

```text
WriterAgent 生成初稿
  -> ReviewerAgent 审查（结构完整性、证据覆盖、引用准确性、逻辑连贯性）
  -> RevisorAgent 根据审查意见修订
  -> 可配置迭代轮数（默认 1 轮）
```

大范围论文处理（借鉴 GPT-Researcher 上下文压缩）：

```text
论文数 > 阈值时：
  1. 按主题分组
  2. 每组生成摘要
  3. 基于摘要生成综述各节
  4. 统一审校
```

### Innovation Report

创新点报告是正式成果物之一，基于证据表和图谱 gap 生成。借鉴 GPT-Researcher 的树状图谱探索（递归遍历找 gap）、PapersFlow 的 Critic Agent 反证检测和 Chain of Verification、Consensus 的 Research Gap Matrix。

创新点来源（7 种信号类型）：

```text
图谱稀疏关系                        # 图谱中连接稀疏的区域
多篇论文共同局限                    # Limitation 节点聚合
future work 聚合                    # Future Work 交集
方法迁移空间                        # 方法跨场景应用
数据集或场景空白                    # Research Gap Matrix 空 cell
争议点和证据不足                    # Finding 中的 CONTRADICTS 关系
近年趋势                            # Temporal Analysis（借鉴 Literature Mapper）
```

每个创新点输出：

```text
创新点名称
创新点描述
为什么是创新
已有研究基础
研究空白
支撑文献
限制或反对证据                      # 必须列出（借鉴 PapersFlow 反证检测）
反对证据搜索结果                    # 自动搜索反证（借鉴 PapersFlow Critic Agent）
验证状态                            # supported / contradicted / unverified（借鉴 Chain of Verification）
可行性
风险
可转化论文题目
评分
```

评分维度：

| 维度 | 含义 |
| --- | --- |
| Novelty | 是否存在明确空白。 |
| Evidence | 是否有足够文献基础。 |
| Feasibility | 数据、方法、时间是否可行。 |
| Risk | 风险是否可控。 |
| Fit | 是否匹配用户学科和学历层次。 |

质量控制指标（借鉴 Atlas）：

```text
H/V ratio = 幻觉断言数 / 总断言数（目标 < 0.1）
evidence_coverage = 有来源支撑的要点数 / 总要点数
counter_evidence_ratio = 有反证的创新点数 / 总创新点数
```

### 质量控制体系

质量控制贯穿 QA 和报告生成全流程，借鉴 LettuceDetect（token-level 幻觉检测）、Atlas（H/V ratio）、PapersFlow（Chain of Verification）和 PRISMA-trAIce（透明报告检查清单）。

分层质量控制：

```text
第 1 层 - 检索质量
  Anthropic Contextual Retrieval + BM25 混合检索
  减少 67% 失败检索

第 2 层 - 生成约束
  Scope 限制 + 范围声明 + 未知标记
  不允许引用 Scope 外论文

第 3 层 - 幻觉检测
  LettuceDetect token-level 检测（MIT 开源，17-68M 参数）
  计算 H/V ratio（目标 < 0.1）

第 4 层 - 声明验证
  Chain of Verification：提取关键声明 -> 逐一验证 -> 标记状态
  反证检测：自动搜索反对证据

第 5 层 - 人工确认
  用户确认关键断言
  记录人工操作（借鉴 PRISMA-trAIce）

第 6 层 - 报告透明元数据
  记录使用的论文、Scope、LLM 版本、生成时间
  记录排除的论文及排除理由
  记录人工确认的操作
```

## 6. 用户流程

### 6.1 创建项目

用户输入：

```text
项目名称
研究方向
学科
学历层次
研究目标
```

### 6.2 构建论文库

用户通过上传、检索或导入方式添加论文。

系统处理：

```text
保存论文元数据
保存 PDF
解析全文
切分 chunks
生成论文卡片
生成 evidence records
构建知识图谱
更新项目统计
```

### 6.3 选择范围

用户可以从论文列表、主题筛选、方法筛选、年份筛选或知识图谱中选择范围。

### 6.4 进行 QA

示例问题：

```text
这些论文共同研究了什么？
这些论文主要不足是什么？
这个主题下常用方法有哪些？
这些文献能否支撑我的选题？
基于当前子图找 3 个创新点。
```

回答后提供动作：

```text
加入文献综述素材
加入创新点报告素材
基于当前范围生成完整综述
基于当前范围生成创新点
扩大到全项目再分析
查看证据来源
```

### 6.5 生成成果

正式成果只有两类：

```text
文献综述
创新点报告
```

报告必须记录：

```text
版本号
生成范围
使用论文数量
使用证据记录
使用图谱节点
生成时间
导出格式
```

## 7. 页面结构

MVP 保留四个主页面。

### 项目论文库

用途：管理项目和论文。

能力：

```text
创建项目
上传 PDF
检索论文
导入引用
查看解析状态
查看论文卡片
标记纳入/排除
按主题、方法、年份筛选
选择论文进入 QA 或报告生成
```

### 知识图谱

用途：展示和选择学术关系。

能力：

```text
查看节点和关系
筛选节点类型
查看节点证据来源
选择节点或子图
基于子图 QA
基于子图生成创新点
```

### 研究 QA

用途：基于选择范围进行研究分析。

能力：

```text
选择 QA 范围
提问
查看来源
保存回答为综述素材
保存回答为创新点素材
调整范围继续分析
```

### 成果报告

用途：管理文献综述和创新点报告。

能力：

```text
生成报告
查看报告版本
查看使用范围和来源
导出 Markdown
后续扩展 Word 导出
```

## 8. MVP 范围

第一版必须打通：

```text
1. 创建研究项目
2. 上传或检索 20 到 30 篇论文
3. 解析论文并生成论文卡片
4. 抽取证据表
5. 构建简单知识图谱
6. 支持选择论文、主题或子图 QA
7. 一键生成文献综述
8. 一键生成创新点报告
9. 报告和回答可追溯来源
10. Markdown 导出
```

MVP 演示路径：

```text
1. 创建项目：大语言模型与自主学习
2. 上传 10 篇 PDF，检索补充 20 篇论文
3. 系统解析论文，生成论文卡片和证据表
4. 系统构建简单知识图谱
5. 用户选择“实证研究”主题子图
6. 用户提问：这些研究共同不足是什么？
7. 系统基于子图回答，并展示证据来源
8. 用户点击：基于当前范围生成创新点报告
9. 用户选择全项目论文库
10. 用户点击：生成文献综述
11. 系统输出文献综述和创新点报告，并支持 Markdown 导出
```

## 10. 成功标准

产品第一版成功的标准：

- 用户能把一批论文变成项目论文库。
- 系统能把论文转成论文卡片和证据表。
- 用户能选择范围提问，回答不越界。
- 文献综述不是凭空生成，而是基于证据表和论文来源。
- 创新点不是泛泛建议，而是来自图谱 gap、共同局限和 future work。
- 所有正式输出都能追溯到论文、证据记录和范围。
- 演示路径能稳定跑通。

## 12. 最终对外描述

> 论文知识库分析 Agent 是一个面向学生和早期研究者的学术研究分析工具。用户可以上传或检索论文，系统会自动解析论文、构建证据表和知识图谱。用户可以选择论文、主题或图谱子图进行问答，并基于选定范围生成文献综述和创新点报告。所有回答和报告都能追溯到具体论文和知识图谱关系。

一句话卖点：

> 不是帮你直接写论文，而是帮你把一批论文变成可问、可查、可追溯的文献综述和创新点。
