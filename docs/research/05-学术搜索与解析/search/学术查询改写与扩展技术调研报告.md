## 1. 核心概念与定义

### 1.1 查询改写（Query Reformulation）

查询改写是指对用户提交的原始查询进行优化、扩展或重组，以提高检索系统返回结果的相关性和召回率。核心目标是弥合**用户查询语言**与**文档集合语言**之间的"语义鸿沟"（semantic gap）。

### 1.2 查询扩展（Query Expansion, QE）

查询扩展是查询改写的一个子集，特指向原始查询中**添加**相关术语、同义词或语义相关的短语。例如：

- 原始查询：`"sparse functional data"`
- 扩展查询：`"sparse functional data" OR "sparse functional analysis" OR "irregular functional data" OR "functional data with sparsity"`

### 1.3 关键术语

| 术语 | 定义 |
|------|------|
| **词汇不匹配（Vocabulary Mismatch）** | 用户查询与文档使用不同术语描述同一概念 |
| **多义性（Polysemy）** | 同一术语在不同领域有不同含义（如 "cell" 可指生物细胞、电池、牢房） |
| **同义性（Synonymy）** | 不同术语表达相同概念（如 "heart attack" 与 "myocardial infarction"） |
| **伪相关反馈（PRF）** | 假设初次检索的Top-K文档为相关文档，从中提取扩展词 |
| **受控词表（Controlled Vocabulary）** | 由人工维护的规范化术语系统（如 MeSH、UMLS） |
| **HyDE** | 假设文档嵌入，用LLM生成假设性回答文档，用其嵌入进行检索 |

### 1.4 查询改写的分类体系

```
查询改写
├── 查询扩展（Query Expansion）
│   ├── 同义词扩展
│   ├── 相关术语扩展
│   ├── 伪相关反馈（PRF）
│   └── LLM生成扩展
├── 查询缩减（Query Reduction）
│   ├── 去除停用词
│   └── 关键词提取
├── 查询重写（Query Rewriting）
│   ├── 多查询生成（Multi-Query）
│   ├── 问题分解（Decomposition）
│   └── 回退策略（Step-Back）
└── 文档扩展（Document Expansion）
    ├── Doc2Query / DocTTTTTQuery
    └── SPLADE 隐式扩展
```

## 2. 技术原理深度解析

### 2.1 学术搜索引擎的查询处理机制

#### 2.1.1 PubMed 的自动术语映射（ATM）

PubMed 是查询扩展最成熟的学术搜索系统之一。其核心机制 **Automatic Term Mapping (ATM)** 工作流程：

1. 用户输入查询词
2. 系统在"翻译表"（Translation Tables）中查找该词
3. 将查询词映射到对应的 MeSH 术语
4. 自动生成包含 MeSH 术语、文本词和所有字段的复合查询

**示例**：用户搜索 `hay fever`，ATM 自动转换为：
```
"hay fever"[MeSH Terms] OR hay fever[Text Word]
```

**MeSH 爆炸（MeSH Explosion）**：搜索一个 MeSH 术语时，自动包含其所有下位术语。例如搜索 "Neoplasms" 会自动包含所有类型的肿瘤。

**关键数据**：MeSH 词汇表包含 30,000+ 个规范术语，由 NLM 的专业索引员为每篇文章标注 10-15 个 MeSH 术语。

> 来源：PubMed ATM 技术文档；NLM Technical Bulletin 2004

#### 2.1.2 Semantic Scholar 的搜索架构

Semantic Scholar API 提供以下搜索能力：

- **基础搜索**：`/graph/v1/paper/search?query={query}` — 纯文本搜索，不支持特殊查询语法
- **批量搜索**：`/graph/v1/paper/search/bulk` — 大规模检索
- **自动补全**：`/graph/v1/paper/autocomplete?query={query}`
- **过滤能力**：支持 `publicationDateOrYear`、`minCitationCount`、`fieldsOfStudy` 等过滤

**重要特性**：连字符查询词不匹配（需替换为空格）；支持引号精确短语搜索。

> 来源：Semantic Scholar API Documentation（api.semanticscholar.org）

#### 2.1.3 arXiv 搜索系统

arXiv 提供基于 Lucene 的搜索 API：
```
http://export.arxiv.org/api/query?search_query=all:query+rewriting+AND+cat:cs.IR&max_results=10
```

arXiv 的搜索相对简单，主要依赖关键词匹配，不内置复杂的查询扩展机制。

### 2.2 传统查询扩展技术

#### 2.2.1 伪相关反馈（Pseudo-Relevance Feedback, PRF）

PRF 是最经典的查询扩展方法，核心流程：

```
原始查询 → 初次检索 → 取Top-K文档 → 提取扩展词 → 扩展查询 → 二次检索
```

**Rocchio 算法**（1971）是 PRF 的理论基础：

```
q_new = α · q_original + β · (1/|Dr|) · Σ d_relevant - γ · (1/|Dnr|) · Σ d_non_relevant
```

**RM3 模型**（Lavrenko & Croft, 2001）：基于相关性语言模型的 PRF 方法，使用 KL 散度度量查询与文档模型的差异。

**最新进展 — LLM-VPRF**（2025）：将 PRF 与向量空间结合，不扩展查询文本，而是修改查询向量：
- **Average 方法**：计算反馈文档嵌入的平均值作为新查询向量
- **Rocchio 方法**：在向量空间中应用 Rocchio 公式

> 来源：Stanford IR Book Ch.9；arXiv:2504.01448（LLM-VPRF）

#### 2.2.2 词嵌入查询扩展（Word Embeddings QE）

Microsoft Research 的关键研究（Diaz et al., ACL 2016）发现：

- **全局词嵌入**（如在 Wikipedia/Gigaword 上训练的 GloVe、Google News 上训练的 Word2Vec）在检索任务上**表现不佳**
- **局部词嵌入**（在目标语料库或查询结果文档上训练的嵌入）**显著优于**全局嵌入
- 原因：局部嵌入能更好地捕捉领域特定的词汇语义关系

**实现方式**：
```python
# 基于Word2Vec的查询扩展示例
from gensim.models import Word2Vec

# 在目标语料库上训练局部嵌入
model = Word2Vec(corpus_sentences, vector_size=200, window=10, sg=1)

# 获取查询词的K个最近邻
expanded_terms = []
for term in query_terms:
    similar = model.wv.most_similar(term, topn=5)
    expanded_terms.extend([w for w, _ in similar])

expanded_query = original_query + " " + " ".join(expanded_terms)
```

> 来源：Microsoft Research, ACL 2016 "Query Expansion with Locally-Trained Word Embeddings"

#### 2.2.3 知识图谱查询扩展

知识图谱（KG）通过实体关系扩展查询。典型工作流：

1. 从查询中提取实体
2. 在 KG 中查找实体的邻居节点
3. 利用关系信息扩展查询

**示例**：查询 "KFC" → KG 扩展 → 包含 `fried_chicken_tag`、`wings_tag`、`chicken_cat`

**学术搜索中的 KG 扩展**（Xia et al., NAACL 2025）：
- 从查询中提取论文实体
- 在学术 KG 中查找引用、合著者、研究领域关系
- 将文档三元组转化为文本，与原始查询一起输入 LLM

> 来源：NAACL 2025 "Knowledge-Aware Query Expansion with LLMs"；Eugene Yan's Blog

### 2.3 LLM-based 查询扩展方法

#### 2.3.1 HyDE（Hypothetical Document Embeddings）

**论文**：Gao et al., "Precise Zero-Shot Dense Retrieval without Relevance Labels"（2022）

**核心思想**：不直接用查询嵌入检索，而是用 LLM 生成一个"假设性文档"，用该文档的嵌入进行检索。

**流程**：
```
用户查询 → LLM生成假设性回答文档 → 编码器(Contriever)编码文档 → 向量相似度检索
```

**关键优势**：
- 零样本密集检索，无需标注数据
- 弥合查询与文档之间的嵌入空间差距
- 支持多语言（已在韩语、日语、斯瓦希里语等验证）

**实现示例**：
```python
# HyDE 实现伪代码
from langchain.prompts import ChatPromptTemplate

hyde_prompt = ChatPromptTemplate.from_template(
    "Please write a passage to answer the question: {question}"
)
# 1. 生成假设文档
hypothetical_doc = llm.invoke(hyde_prompt.format(question=query))
# 2. 编码假设文档
query_embedding = embedder.embed(hypothetical_doc)
# 3. 检索
results = vector_store.similarity_search_by_vector(query_embedding, k=10)
```

**局限性**：
- 增加延迟（需要 LLM 生成步骤）
- 可能引入幻觉
- 对于已微调的编码器，效果提升有限

> 来源：arXiv:2212.10496；emergentmind.com/topics/hypothetical-document-embeddings-hyde

#### 2.3.2 Query2Doc

**论文**：Wang et al., EMNLP 2023

**方法**：用少样本提示让 LLM 生成伪文档，然后与原始查询拼接。

```python
# Query2Doc 核心逻辑
prompt = f"Write a passage that answers the question: {query}"
pseudo_doc = llm.generate(prompt)

# 对于BM25稀疏检索：重复原始查询n次（通常n=5）
expanded_query = (query + " ") * 5 + pseudo_doc

# 对于密集检索：使用[SEP]分隔
expanded_query = query + " [SEP] " + pseudo_doc
```

**效果**：在 MS MARCO 和 TREC DL 上，BM25 性能提升 3%-15%。

#### 2.3.3 CSQE（Corpus-Steered Query Expansion）

**论文**：Lei et al., 2024

**核心创新**：用语料库分布统计引导 LLM 生成扩展。

**流程**：
1. 用 BM25 初次检索
2. 从 Top-10 文档中提取关键句子（LLM 做相关性判断）
3. LLM 生成两个段落（受语料库统计引导）
4. 拼接：`q_expanded = q + Σ S_i + Σ H_j`

**在 DL-HARD（困难查询集）上表现最佳**，说明语料库锚定对模糊查询有稳定效果。

#### 2.3.4 GenQR 和 GenQR-Ensemble

- **GenQR**：用 LLM 生成关键词扩展
- **GenQR-Ensemble**：使用 10 个不同的指令变体生成多样化关键词扩展

**注意**：在 DL-HARD 上，GenQREnsemble 的 nDCG@10 低于原始查询，说明无差别地添加关键词可能引入噪声。

#### 2.3.5 ThinkQE（2025 最新）

**论文**：Lei et al., 2025

**核心创新**：
1. **思维增强扩展**：引入"思考"阶段，鼓励更深入的语义探索
2. **语料库交互**：多轮迭代，每轮基于检索反馈更新扩展

**与 DeepSeek-R1 思维链的结合**：使用 Rank1-32B 和 Rank-K-32B（从 DeepSeek-R1-685B 蒸馏）进行对比。

#### 2.3.6 ExpandR（EMNLP 2025）

**核心思想**：同时优化 LLM 扩展生成器和密集检索器。

**两个奖励信号**：
- **检索器奖励**：扩展查询的检索效果
- **自奖励**：扩展与 LLM 生成答案的 BLEU 分数

**效果**：ExpandR 同时微调扩展器和检索器时，查询-文档嵌入对齐效果最佳。

#### 2.3.7 SoftQE（2024）

**核心思想**：将 LLM 生成的扩展知识蒸馏到标准查询编码器中。

**流程**：
1. 用 LLM 生成伪文档（如 Query2Doc）
2. 训练教师编码器使用扩展查询
3. 训练 SoftQE 编码器对齐教师编码器的表示

**关键优势**：推理时不需要 LLM，零延迟增加。

#### 2.3.8 AQE（Aligned Query Expansion, Spotify 2025）

**方法**：使用 DPO（Direct Preference Optimization）对齐 LLM 生成的扩展。

**流程**：
1. 零样本生成多个扩展候选
2. 对每个候选计算检索效果排名
3. 用 RSFT + DPO 训练模型偏好好的扩展

**效果**：处理时间减少约 70%，Top-1 检索准确率提升。

> 来源：Spotify Research Blog 2025；arXiv 各论文

### 3.2 传统方法 vs LLM方法对比

| 维度 | 传统方法（PRF/词嵌入） | LLM-based 方法 |
|------|----------------------|---------------|
| **语义理解** | 词级相似 | 句子/段落级理解 |
| **上下文感知** | 有限 | 强 |
| **领域适应** | 需要领域语料库训练 | 通过提示即可适应 |
| **延迟** | 低 | 高（需要LLM推理） |
| **成本** | 低 | 高（API调用费用） |
| **幻觉风险** | 无 | 存在 |
| **可控性** | 高 | 中等 |
| **多义性处理** | 差（局部嵌入可改善） | 好（上下文消歧） |

**"LLM-based Personalized Query Expansion for User-Centric Retrieval"**
- 考虑用户画像和交互日志

**"BMQExpander: Ontology-Guided Query Expansion for Biomedical Document Retrieval using Large Language Models"**

- NDCG@10 比 BM25 提升 22.1%
- 幻觉率低于其他 LLM-based 方法

#### 4.1.6 大语言模型和知识图谱协同的查询扩展（CCL 2025）

**论文**：CCL 2025 第二十四届中国计算语言学大会
- 引入知识图谱与 LLM 协同完成查询扩展
- 解决伪相关文档语义连贯性差、冗余信息和噪声问题
- 在 DL19 上，扩展长度 K=14 时 nDCG@10 达到 66.23%

#### 4.1.7 基于ChatGPT查询改写的文档检索方法（CCL 2024）

**论文**：华中师范大学，CCL 2024
- 用 ChatGPT 生成新查询，与原始查询分别重排后融合
- nDCG@10 平均提升约 4.5 个百分点
- 不依赖伪相关文档，避免了低质量问题

### 5.5 WordNet 查询扩展示例

```python
from nltk.corpus import wordnet

def expand_with_wordnet(query_terms, max_synonyms=3):
    expanded = set(query_terms)
    for term in query_terms:
        for syn in wordnet.synsets(term):
            for lemma in syn.lemmas()[:max_synonyms]:
                if lemma.name() != term:
                    expanded.add(lemma.name().replace('_', ' '))
    return list(expanded)

# 示例
expand_with_wordnet(["heart", "attack"])
# 可能输出: ['heart', 'attack', 'cardiac', 'assault', 'onslot', ...]
```

## 6. 实际应用案例

### 6.1 案例一：PubMed 医学文献搜索

**场景**：医生搜索 "heart attack treatment"

**ATM 自动扩展**：
```
"heart attack"[MeSH Terms] OR "heart attack"[Text Word]
→ 自动包含 "myocardial infarction" 及其所有下位MeSH术语
→ 自动包含治疗相关的副主题词
```

**效果**：自动术语映射使得即使用户不了解 MeSH 术语，也能检索到规范索引的文献。

**局限**：最新文献可能尚未标注 MeSH 术语。

### 6.2 案例二：学术论文推荐系统（Khalid et al., 2020）

**场景**：研究人员搜索相关论文

**方法**：
1. 用户提交查询 → BM25 初次检索
2. 从 Top-K 结果中提取高 TF-IDF 术语
3. 结合引用网络分析（被引次数、引用关系）
4. 扩展查询后二次检索

**效果**：在 ACL 数据集上，nDCG、precision、recall 均有显著提升。

### 6.3 案例三：RAG 系统中的查询扩展（Haystack）

**场景**：基于维基百科的能源主题问答

**流程**：
```
用户查询: "What are the environmental benefits of electric vehicles?"
↓
QueryExpander 生成4个变体:
  - "environmental advantages of EVs"
  - "ecological impact of electric cars"
  - "green benefits of battery-powered vehicles"
  - "sustainability of electric transportation"
↓
MultiQueryBM25Retriever 并行检索所有5个查询
↓
合并去重后送入LLM生成回答
```

**效果**：相比单查询检索，召回率显著提升。

### 6.4 案例四：生物医学文档检索（BMQExpander, 2025）

**场景**：生物医学QA系统

**方法**：
1. 从查询中提取医学概念
2. 在 UMLS Metathesaurus 中查找定义和关系
3. 用 LLM 生成扩展（以本体知识为约束）

**效果**：NDCG@10 比 BM25 提升 22.1%，且幻觉率低于纯 LLM 扩展方法。

## 7. 技术难点与解决方案

### 7.1 多义性（Polysemy）问题

**问题**：同一术语在不同领域有不同含义。

**示例**：
- "cell" → 生物细胞 / 电池 / 牢房 / 电池
- "Python" → 编程语言 / 蛇
- "Apple" → 公司 / 水果

**解决方案**：

| 方法 | 原理 | 效果 |
|------|------|------|
| 局部词嵌入 | 在目标语料库上训练嵌入，自动消歧 | 好 |
| 编码器消歧 | BERT等双向编码器理解上下文 | 好 |
| LLM上下文理解 | 通过提示让LLM判断语义 | 很好 |
| 领域限定词 | 添加领域关键词缩小范围 | 好（人工） |
| 知识图谱 | 利用实体关系消歧 | 好 |

### 7.2 术语特异性（Term Specificity）

**问题**：学术领域存在大量专业术语，通用模型难以理解。

**示例**：`"sparse functional data"` 是统计学概念，指稀疏采样的函数型数据。

**解决方案**：
- **领域特定微调**：使用 SciBERT、BioBERT 等领域预训练模型
- **本体引导**：使用领域本体（如 UMLS、MeSH）约束扩展
- **受控词表**：使用叙词表（Thesaurus）映射规范术语
- **引用上下文**：利用引用该论文的其他论文中的描述来理解术语含义

### 7.3 概念级 vs 词级匹配

**问题**：传统方法（BM25）只能做词级匹配，无法理解概念。

**示例**：
- 查询 "deep learning in radiology"
- 文档使用 "automated image analysis" 或 "computer-aided diagnosis"

**解决方案**：
- **密集检索**：使用 BERT/Contriever 等编码器做语义匹配
- **混合检索**：BM25（词级）+ Dense（概念级）+ RRF 融合
- **SPLADE**：学习稀疏表示，隐式包含术语扩展

### 7.4 查询漂移（Query Drift）

**问题**：扩展后的查询偏离原始意图。

**解决方案**：

| 策略 | 实现 |
|------|------|
| 权重控制 | 原始查询词权重 > 扩展词权重 |
| 选择性扩展 | 用置信度分数筛选扩展词 |
| 重排序 | 对原始查询和扩展查询的结果分别重排后融合 |
| 语料库锚定 | 如CSQE，用语料库统计约束LLM生成 |
| 迭代反馈 | 如ThinkQE，多轮迭代修正扩展方向 |

### 7.5 缩写处理

**问题**：同一缩写在不同领域有不同含义。

**示例**：
- SB → Segmental bronchi / Sodium Bicarbonate / Spontaneous breath
- CT → Computerized Tomography / Computed Tomography / CT scan

**解决方案**：
- 添加领域限定词：`SB AND Inflammation`
- 使用缩写展开库
- 利用查询日志中用户后续查询推断缩写含义

### 7.6 跨语言查询扩展

**问题**：用户使用一种语言查询，需要检索另一种语言的文档。

**技术方案**：
- **预翻译扩展**：先扩展查询，再翻译（利用同源词 cognates）
- **后翻译扩展**：先翻译，再在目标语言中扩展
- **多语言嵌入**：使用 mBERT、XLM-R 等模型将查询和文档映射到同一向量空间
- **Multilingual PLMs**：如 mT5，支持跨语言QE而无需平行语料

## 8. 未来发展趋势

### 8.1 自适应查询扩展

**趋势**：根据查询特性动态选择是否扩展、如何扩展。

- **知识充分性预评分**：判断LLM是否已具备足够知识回答该查询
- **模糊度检测**：对模糊查询主动扩展，对明确查询保持原样
- **风险评估**：评估扩展可能引入噪声的风险

> 代表工作：Abe et al., 2025 "Hypothetical Documents or Knowledge Leakage?"

## 附录：核心发现总结

### 对本项目的启示

基于本次调研，对学术论文知识库分析 Agent 的查询改写模块，建议：

1. **优先实现 Multi-Query 策略**：用 LLM 从不同角度重写查询，提升召回率。LangChain 的 `MultiQueryRetriever` 可直接集成。

2. **考虑 HyDE 作为零样本方案**：当缺乏领域训练数据时，HyDE 是提升密集检索效果的低成本方案。

3. **利用引用上下文做查询扩展**：对于学术搜索，引用关系和引用上下文是独特的扩展信号源。

4. **混合检索（BM25 + Dense）是最佳实践**：BEIR 基准测试表明，单一检索器在不同数据集上表现差异大，混合方案更稳健。

5. **评估至关重要**：使用 pytrec_eval 计算 nDCG@10、Recall@100、MAP 等指标，A/B 测试不同扩展策略。

6. **控制扩展质量**：避免无差别扩展（GenQR-Ensemble 在困难查询上可能退化），优先使用语料库锚定方法（CSQE）或本体引导方法。

7. **关注 QueryGym 工具包**：作为标准化的查询改写基准，可用于快速实验和对比不同方法。
