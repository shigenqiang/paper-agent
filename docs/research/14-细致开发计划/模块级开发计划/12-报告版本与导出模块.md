# 报告版本与导出模块专项开发计划

更新时间：2026-06-05

本文档基于 `docs/research` 下的产品方案、当前开发计划、综述生成计划、创新点报告计划、RetrievalScope 计划、评估日志计划、API 联调计划和当前代码实现，重新细化报告版本与导出模块的开发方案。

报告版本与导出模块负责把综述报告、创新点报告以及后续选题方案转化为可管理、可追溯、可迭代、可校验、可导出的成果物。它不是简单把 Markdown 字符串保存到 JSON 文件，而是成果管理层：统一承接报告生成模块输出的内容、Scope、来源索引、质量校验、版本快照和导出格式。

## 1. 模块定位

### 1.1 在产品链路中的位置

报告版本与导出模块位于所有生成模块之后，是研究工作区的成果层：

```text
Paper Search / PDF Parse
  -> PaperCard
  -> EvidenceRecord
  -> KnowledgeGraph
  -> RetrievalScope
  -> ScopeQA
  -> Literature Review / Innovation Report
  -> ReportService
  -> Version / Validation / Export
  -> Frontend Report Workspace
```

它要承接：

| 上游模块 | 提供内容 | 本模块职责 |
| --- | --- | --- |
| 08 RetrievalScope | scope、paper_ids、evidence_ids、graph_node_ids | 保存范围快照，校验来源是否越界 |
| 09 ScopeQA/RAG | 可保存为 report material 的 QA 回答 | 作为报告草稿素材或附录 |
| 10 综述生成 | review content、section_sources、validation_result | 保存、版本化、导出综述 |
| 11 创新点报告 | innovation content、candidate sources、scores | 保存、版本化、导出创新报告 |
| 13 LLM 结构化输出 | prompt/schema 版本、模型调用信息 | 写入生成元数据，便于复现 |
| 15 评估日志 | report_traceability_check、质量指标 | 作为保存前后质量门禁 |
| 14 API/前端 | 报告列表、详情、版本、导出接口 | 提供稳定响应结构 |

### 1.2 模块边界

本模块负责：

```text
报告保存
报告列表和详情
报告更新
版本创建、列表、恢复和对比
来源索引构建
Traceability 校验
Markdown 导出
JSON 导出
引用格式化
Evidence appendix 导出
归档和删除
前端报告页数据契约
```

本模块不负责：

```text
生成综述正文
生成创新点正文
重新检索论文
重新解析 PDF
判断 LLM 输出是否学术上完全正确
复杂 Word/PDF 排版
多人协作权限系统
```

### 1.3 核心原则

```text
1. 报告是成果物，不只是 content 字符串。
2. 每份报告必须保留 scope snapshot。
3. 每份报告必须能追溯到 paper、evidence、graph node。
4. 版本必须记录内容变化和来源快照。
5. 导出必须包含元信息、正文和来源索引。
6. 保存前可以宽松，最终导出前必须可校验。
7. 综述和创新点报告共用同一套报告基础设施。
8. 当前 JSONStorage 是 MVP 存储，模型设计要能迁移到数据库。
```

## 2. 本地调研结论落地

### 2.1 模块总览对本模块的要求

`00-模块总览与依赖关系.md` 明确报告层需要：

```text
section_sources

export
version
```

落地为：

| 要求 | 开发落点 |
| --- | --- |
| section_sources | `ReportSourceIndex` 和 `SectionSource` |
| traceability | `ReportTraceabilityValidator` |
| export | `MarkdownExporter`、`JsonExporter`、`ExportPackage` |
| version | `ReportVersionManager`、`ReportVersion` 增强 |

### 2.2 综述生成模块对本模块的要求

10 综述生成模块要求每个主要章节能追溯到证据：

```text
Review sections
  -> section_id
  -> paper_ids
  -> evidence_ids
  -> graph_node_ids
  -> citations
```

本模块必须提供：

```text
save_report(report, source_index, validation_result)
export_markdown(report_id, include_sources=True)
validate_report_traceability(report_id)
create_version(report_id, content, source_index, reason)
```

综述模块不应自己拼接最终导出来源索引，而应把结构化来源交给 ReportService。

### 2.3 创新点报告模块对本模块的要求

11 创新点报告模块强调：

```text
source_signal_ids
supporting_evidence_ids
limiting_evidence_ids
scores
validation_result
```

本模块需要兼容创新报告的来源索引：

```text
candidate_sources
gap_signals
supporting_evidence
limiting_evidence
graph_node_ids
scoring_version
```

这些暂时可放在：

```text
Report.scope.innovation_metadata
ReportSourceIndex.sections
ReportSourceIndex.custom
```

后续模型增强后再迁移到正式 metadata 字段。

### 2.4 RetrievalScope 对本模块的要求

08 RetrievalScope 模块要求报告不能越界引用：

```text
report.paper_ids subset resolved_scope.paper_ids
report.evidence_ids subset resolved_scope.evidence_ids
report.graph_node_ids subset resolved_scope.graph_node_ids
```

现实中可能存在例外：

```text
系统综述报告引用筛选流程中的 excluded paper。
参考文献列表展示未纳入但被引用的背景文献。
用户手动添加外部参考。
```

因此 traceability 校验需要支持策略：

```text
strict_scope=true：越界即 error。
allow_external_references=true：外部来源必须出现在 external_sources，不能混入 evidence_ids。
appendix_only=true：附录材料可不进入正文证据。
```

### 2.5 评估日志模块对本模块的要求

15 评估日志监控模块已经定义：

```text
report_traceability_rate
section_source_coverage
structure_completeness
scope_guard_pass_rate
```

本模块需要产生可计算数据：

```text
report.saved
report.version.created
report.validated
report.exported
report.archived
report.deleted
```

并在 validation result 中提供：

```text
source_coverage
section_source_coverage
scope_violation_count
missing_source_count
unresolved_reference_count
```

### 2.6 API 和前端模块对本模块的要求

14 API/前端联调模块要求成果报告页支持：

```text
报告列表
报告详情
版本列表
正文预览
来源索引
质量校验结果
导出按钮
```

因此 ReportService 不能只返回 Markdown 字符串。它需要能返回前端可直接渲染的结构：

```text
ReportDetailDTO
ReportVersionDTO
ReportSourceIndexDTO
ReportValidationResultDTO
ExportResultDTO
```

### 3.2 Git / diff 工作流

可借鉴：

```text

```

落地到本项目：

```text

```

```text

```

### 3.3 Pandoc / Quarto 导出链路

Markdown 是适合作为中间格式的成果文档。MVP 应先保证 Markdown 完整、干净、可复现，再考虑 DOCX/PDF。

落地策略：

```text
P0: export_markdown + export_json
P1: export_markdown_package，包含 markdown、metadata、source_index、references
P2: export_docx/export_pdf，内部可走 Pandoc 或 Python 库
```

### 3.4 Zotero / CSL 引用体系

引用和正文应分离。报告正文里可以使用简短 citation key，导出阶段根据 style 生成参考文献。

MVP 支持：

```text
inline citation: [paper_1]
reference list: Authors. (Year). Title. Venue. DOI/URL.
styles: simple / apa / gbt7714 / bibtex
```

P0 不强求完整 CSL 引擎，但要预留 `citation_style` 参数。

### 3.5 系统综述工具

系统综述的成果输出不只是正文，还包括：

```text
纳入论文列表
排除原因
证据表
质量评价
检索策略
PRISMA flow
```

本项目 P0 先做通用来源索引，P1 支持：

```text
evidence appendix

search strategy appendix
```


### 4.5 当前关键缺口

| 问题 | 当前表现 | 影响 | 优先级 |
| --- | --- | --- | --- |
| ReportVersion 信息太少 | 只有 content/reason | 不能知道第几版、来源是否变化 | P0 |
| 版本创建语义不完整 | version.content 是新内容，但没有 old snapshot | 无法对比和恢复 | P0 |
| 无 source index | 只有报告级 paper_ids/evidence_ids | 前端不能展示章节来源 | P0 |
| 无 traceability 校验 | 保存和导出前不检查来源 | 可能导出缺失或越界引用 | P0 |
| Markdown 导出过简单 | 元信息附在文末 | 不利于机器读取和二次转换 | P0 |
| 无 JSON 导出 | 无结构化成果包 | 前端/调试/迁移不方便 | P0 |
| 无归档状态 | list_reports 无法隐藏旧报告 | 报告列表会混乱 | P1 |
| 无删除策略 | 只能 storage.delete_item，未定义版本处理 | 容易留下孤儿版本 | P1 |
| 无引用格式化 | 不能输出参考文献 | 综述导出不完整 | P1 |
| 无导出选项 | 不能控制是否包含 sources/appendix | 不同场景复用差 | P1 |
| 无导出文件管理 | export_markdown 只返回字符串 | API 下载和导出历史缺基础 | P1 |
| 无恢复版本 | create_version 后不能 restore | 版本历史价值不足 | P1 |
| 无 diff | 不能查看改动摘要 | 用户难以判断版本差异 | P1 |
| 无并发/覆盖保护 | 直接覆盖 report | 前端编辑可能丢内容 | P2 |

## 5. 目标与边界

### 5.1 一句话目标

让综述和创新点报告都能以统一方式保存、版本化、校验来源、导出 Markdown/JSON，并在前端展示版本、来源索引和质量状态。

### 5.2 MVP 成功标准

```text
1. save_report 支持保存 validation_result 和 source_index。
2. create_version 生成 version_number、diff_summary、scope_snapshot、source_snapshot。
3. list_reports 支持 report_type、status、include_archived 过滤。
4. validate_report_traceability 能发现缺失 paper/evidence、scope 越界和正文引用不可解析。
5. export_markdown 输出 YAML front matter。
6. export_markdown 包含来源索引和可选 evidence appendix。
7. export_json 输出 report、versions、source_index、validation、export_metadata。
8. archive_report 和 delete_report 行为明确。
9. 综述报告和创新点报告都能通过同一逻辑导出。
10. 单元测试覆盖版本、导出、校验、归档和删除。
```

### 5.3 非目标

MVP 不做：

```text
1. 完整多人协同编辑。
2. 实时评论和批注。
3. 完整 DOCX/PDF 排版。
4. 完整 CSL 引擎。
5. 云端文件管理。
6. 权限和审计合规系统。
7. 复杂三方文献管理器同步。
```

P2 可扩展：

```text
Pandoc DOCX/PDF
CSL style engine
comment/review workflow
export history files
report templates
database migration
```

## 8. 来源索引设计

### 8.1 来源索引的目标

来源索引用来回答：

```text
报告用了哪些论文？
每条证据来自哪篇论文？
每个章节用了哪些来源？
正文中出现的引用 ID 是否都能解析？
导出时如何生成参考文献？
前端点击来源时如何定位到 evidence/source_quote？
```

### 8.2 来源层级

```text
L1 Report-level source
  报告整体 paper_ids/evidence_ids/graph_node_ids。

L2 Section-level source
  每个章节绑定 paper/evidence/graph。

L3 Claim-level source
  P2 支持句子或 claim 级 citation。

L4 Source quote / chunk
  精确到 PDF chunk 和 quote。
```

P0 至少实现 L1 + L2。

### 8.3 section_sources 输入契约

综述和创新报告生成模块应传入：

```json
{
  "intro": {
    "section_title": "研究背景",
    "paper_ids": ["p1", "p2"],
    "evidence_ids": ["e1", "e2"],
    "graph_node_ids": ["topic_feedback"]
  },
  "innovation_1": {
    "section_title": "创新点一",
    "paper_ids": ["p3"],
    "evidence_ids": ["e5", "e6"],
    "graph_node_ids": ["gap_external_validity"]
  }
}
```

如果生成模块暂时没有 section_sources：

```text
ReportSourceIndexBuilder 可以把 report.paper_ids/evidence_ids 作为 __report__ section。
validation_result 增加 warning: missing_section_sources。
```

### 8.4 来源索引构建规则

```text
1. 从 report.paper_ids 加载 papers。
2. 从 report.evidence_ids 加载 evidence_records。
3. 从 report.graph_node_ids 加载 graph nodes。
4. 合并 section_sources 中额外提到的 ID。
5. 校验 ID 是否存在、是否属于 project。
6. 生成 used_in_sections 反向索引。
7. 生成 citation_key。
8. 截断 source_quote，避免导出过长。
```

### 8.5 source_quote 策略

默认导出：

```text
quote_max_chars = 240
超过长度截断。
Markdown 中只显示短 quote。
JSON 导出可保留完整 quote 或设置 include_full_quotes=true。
```

原因：

```text
导出 Markdown 需要可读。
避免把大量 PDF 原文塞入报告正文。
降低版权和隐私风险。
```

## 9. Traceability 校验

### 9.1 校验入口

```python
validate_report_traceability(
    report_id: str,
    *,
    strict_scope: bool = True,
    allow_external_references: bool = False,
) -> ReportValidationResult
```

也支持：

```python
validate_report(report: Report, source_index: ReportSourceIndex | None = None) -> ReportValidationResult
```

### 9.2 基础校验

```text
Report 存在。
Project 存在。
Report.project_id 等于 Project.project_id。
Report.type 是支持类型。
Report.title 非空。
Report.content 非空。
Report.version >= 1。
```

### 9.3 来源存在性校验

```text
paper_ids 都能在 papers 集合中找到。
paper.project_id == report.project_id。
evidence_ids 都能在 evidence_records 集合中找到。
evidence.project_id == report.project_id。
evidence.paper_id 对应 paper 存在。
graph_node_ids 存在于项目图谱。
section_sources 中的 ID 也必须通过上述校验。
```

### 9.4 Scope 校验

如果 `report.scope` 中存在：

```text
paper_ids
evidence_ids
graph_node_ids
```

则检查：

```text
report.paper_ids subset scope.paper_ids
report.evidence_ids subset scope.evidence_ids
report.graph_node_ids subset scope.graph_node_ids
section_sources.paper_ids subset scope.paper_ids
section_sources.evidence_ids subset scope.evidence_ids
```

例外：

```text
external_sources 中声明的外部引用不算 scope violation。
appendix_only 的材料不进入正文覆盖率，但仍需存在。
```

### 9.5 正文引用校验

P0 支持简单模式：

```text
[paper_id]
[evidence_id]
paper_...
ev_...
e...
p...
```

校验：

```text
正文中出现的 paper/evidence 引用是否在 ReportSourceIndex 中。
Report.evidence_ids 中存在但正文和 section_sources 都不用的 ID 给 warning。
正文出现无法解析的引用给 warning 或 error。
```

注意：

```text
不要只靠正文正则判断来源。
结构化 section_sources 才是主依据。
正文引用校验是补充防线。
```

### 9.6 覆盖率计算

```text
source_coverage =
  referenced_source_count / required_source_count

section_source_coverage =
  sections_with_sources / sections_total

traceability_score =
  0.4 * source_coverage
+ 0.3 * section_source_coverage
+ 0.2 * scope_pass
+ 0.1 * no_unresolved_references
```

默认门禁：

```text
traceability_score >= 0.8
scope_violation_count == 0
missing_evidence_count == 0
```

## 10. 版本策略

### 10.1 版本创建语义

当前 `create_version(report_id, content, reason)` 的语义是“创建一个新版本并更新当前报告”。建议保留这个行为，但补齐快照。

推荐流程：

```text
1. 读取当前 Report。
2. previous_content = report.content。
3. next_version_number = report.version + 1。
4. 计算 previous_content_hash 和 content_hash。
5. 生成 diff_summary。
6. 保存 ReportVersion，内容为新版本 content。
7. 更新 Report.content、Report.version、Report.updated_at。
8. 更新 source_index 和 validation_result。
```

### 10.2 是否保存旧版本

为了能恢复最初版本，需要两种策略之一：

方案 A：

```text
save_report 时自动创建 version 1。
create_version 创建 version 2、3、4。
```

方案 B：

```text
Report 当前内容是 latest。
ReportVersion 只保存历史版本。
```

推荐方案 A。原因：

```text
版本列表完整。
恢复 version 1 简单。
导出历史版本简单。
```

### 10.3 diff_summary

P0 规则：

```text
old_length
new_length
added_chars
removed_chars
old_headings
new_headings
added_headings
removed_headings
paper_ids_added
paper_ids_removed
evidence_ids_added
evidence_ids_removed
reason
```

示例：

```json
{
  "summary": "正文增加 312 字，新增 1 个章节，新增 2 条证据引用。",
  "added_chars": 312,
  "removed_chars": 44,
  "added_headings": ["研究趋势"],
  "removed_headings": [],
  "evidence_ids_added": ["e9", "e10"],
  "evidence_ids_removed": []
}
```

P1 可用 `difflib` 生成段落级差异：

```text
changed_paragraphs
changed_sections
unified_diff
html_diff
```

### 10.4 恢复版本

```python
restore_version(report_id: str, version_id: str, reason: str = "restore") -> Report | None
```

行为：

```text
1. 读取目标版本。
2. 调用 create_version，把目标版本 content/source_snapshot 作为新 latest。
3. reason 标记 restore。
4. 不直接把 Report.version 回退，避免版本号倒退。
```

### 10.5 版本列表

```python
list_versions(report_id: str) -> list[ReportVersion]
```

排序：

```text
version_number desc
created_at desc
```

前端展示：

```text
version_number
created_at
reason
diff_summary.summary
validation_result.valid
```

### 10.6 并发和覆盖保护

P0 可以不实现复杂并发，但 API 应预留：

```text
expected_version
```

更新时：

```text
如果 expected_version != report.version，返回 version_conflict。
```

P1 实现：

```python
create_version(report_id, content, reason, expected_version=3)
```

## 12. 引用格式化

### 12.1 CitationFormatter 职责

```text
把 Paper 元数据转为参考文献字符串。
生成 citation_key。
支持不同 citation_style。
避免正文生成模块自己拼引用。
```

### 12.2 支持格式

P0：

```text
simple
apa_basic
gbt7714_basic
bibtex_basic
```

P1：

```text
CSL adapter
Zotero style import
```

### 12.3 simple 格式

```text
Authors. (Year). Title. Venue. DOI/URL
```

字段缺失处理：

```text
authors 空 -> Unknown authors
year 空 -> n.d.
title 空 -> Untitled paper
venue 空 -> 省略
doi/url 空 -> 省略
```

### 12.4 APA basic

```text
Author, A. A., & Author, B. B. (2024). Title. Venue. https://doi.org/...
```

P0 不强制完全符合 APA 细节，但要比 simple 更接近正式引用。

### 12.5 GB/T 7714 basic

```text
[1] 作者. 题名[J]. 刊名, 年份.
```

规则：

```text
按 source_index.paper_sources 顺序编号。
同一 paper_id 只出现一次。
正文仍可保留 [p1]，参考文献区显示 [1]。
```

### 12.6 BibTeX basic

```bibtex
@article{p1,
  title = {Title},
  author = {Author A and Author B},
  year = {2024},
  journal = {Venue},
  doi = {10.xxxx/xxxx},
  url = {https://...}
}
```

## 13. 保存与更新策略

### 13.1 save_report

推荐签名：

```python
def save_report(
    self,
    report: Report,
    *,
    source_index: ReportSourceIndex | None = None,
    validation_result: ReportValidationResult | None = None,
    create_initial_version: bool = True,
) -> Report:
    ...
```

P0 可以先保持原签名，新增可选参数不破坏旧测试。

行为：

```text
1. 标准化 report.status，默认 draft。
2. 标准化 report.version，默认 1。
3. 如果 source_index 为空，根据 report 字段构建基础来源索引。
4. 如果 validation_result 为空，运行基础 traceability 校验。
5. 把 validation/source_index 摘要写入 report.scope.report_metadata 或 report.metadata。
6. 保存 report。
7. 如果 create_initial_version 且没有 version 1，创建初始版本。
```

### 13.2 update_report

建议新增：

```python
def update_report(
    self,
    report_id: str,
    *,
    title: str | None = None,
    content: str | None = None,
    status: str | None = None,
    source_index: ReportSourceIndex | None = None,
    reason: str = "",
    expected_version: int | None = None,
) -> Report | None:
    ...
```

语义：

```text
内容变化 -> create_version。
只改 status/title -> 更新 report，必要时也可 create metadata version。
```

### 13.3 归档与删除

归档：

```python
archive_report(report_id: str, reason: str = "") -> bool
unarchive_report(report_id: str) -> bool
```

行为：

```text
设置 status=archived。
不删除版本。
list_reports 默认不返回 archived。
```

删除：

```python
delete_report(report_id: str, hard: bool = False) -> bool
```

默认 soft delete：

```text
status=deleted
保留 versions 和 source index
list_reports 默认不返回 deleted
```

hard delete：

```text
删除 reports。
删除 report_versions。
删除 report_source_indexes。
只有明确传 hard=True 才执行。
```

状态流转：


## 23. 风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 新模型破坏旧报告 | 旧 JSON 缺新增字段 | Pydantic 默认值 + 兼容 metadata |
| source_index 太大 | Report.scope 被塞满证据全文 | source_quote 截断，P1 独立集合 |
| traceability 误报 | 旧报告没有 section_sources | warning 而非 error |
| scope 校验过严 | 外部参考被误判越界 | external_sources 策略 |
| Markdown 导出不规范 | 元信息不可解析 | 固定 YAML front matter 字段 |
| 版本恢复混乱 | 版本号回退 | restore 创建新版本，不倒退版本号 |
| hard delete 残留数据 | report_versions 孤儿记录 | hard delete 批量清理相关集合 |
| 引用格式不完整 | APA/GB/T 不完全合规 | P0 标记 basic，P1 接 CSL |
| 图谱存储 ID 不一致 | graphs 集合 id 字段映射混乱 | traceability 对 graph 做容错读取，并修正 storage 映射 |

### 25.1 综述生成模块 → ReportService
