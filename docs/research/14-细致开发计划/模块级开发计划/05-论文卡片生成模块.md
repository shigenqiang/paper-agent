### 新增模型

- `ExtractedClaim` — LLM 输出的单条 claim（text + quote + chunk_id）
- `PaperCardExtractionResult` — LLM 结构化输出的完整 schema
- `CardQualityReport` — 卡片质量报告（completeness/traceability/specificity）
- `PaperCard` 新增字段：`version`/`active`/`extraction_method`/`input_chunk_ids`/`quality_score`/`quality_flags`/`validation_errors`/`updated_at`
- `SourceSpan` 新增字段：`section_type`

论文卡片是从单篇论文到项目级证据表的中间层。它不应只是“摘要”，而应是面向后续证据抽取、QA、综述、创新点生成的结构化论文档案：字段要稳定、信息要具体、每个关键结论要尽量能追溯到 chunk 和 quote。

## 1. 当前实现分析

### 1.1 当前已有能力

`PaperCardGenerator` 已有方法：

```text
generate(paper_id)
batch_generate(project_id, only_missing=True)
_extract_card_with_llm(...)
_extract_card_fallback(...)
_extract_list_from_text(text, keywords)
```

当前优点：

| 能力 | 状态 |
| --- | --- |
| LLM 结构化抽取 | 已有 `invoke_json` 入口 |
| fallback | LLM 失败时可用关键词规则抽取 |
| 状态流转 | 生成成功后写 `CARD_READY` |
| 卡片字段 | 覆盖研究问题、方法、样本、发现、局限、未来工作、主题、gap、来源片段、置信度 |
| 批量生成 | 已支持项目级批量 |

### 1.2 当前主要缺口

| 领域 | 当前状态 | 问题 |
| --- | --- | --- |
| 输入上下文 | 直接拼接所有 chunks，截断前 8000 字符 | 长论文后半部分结果/局限可能被截掉 |
| 结构化输出 | 依赖 LLM 返回 JSON | 缺少 schema repair、字段级校验、类型归一 |
| source_spans | 用 finding index 绑定前几个 chunks | quote 不一定来自对应 chunk，局限/未来工作缺来源 |
| 幻觉校验 | 无 | 卡片可能包含 chunks 中不存在的信息 |
| 章节权重 | 无 | Abstract 的泛化摘要可能被当成强证据 |
| 置信度 | 直接使用 LLM confidence | 没有结合字段完整度、来源覆盖、quote 匹配 |
| fallback | 关键词句子抽取 | 可能产生低质量卡片，缺少 extraction_method 标记 |
| 版本策略 | 每次生成新 card_id | 重复生成会产生多张卡片，关系不清 |
| token 预算 | 粗暴截断 | 无 map-reduce、章节摘要、关键 chunk 选择 |
| 质量报告 | 无 | 用户不知道卡片缺什么、哪些字段待复核 |

## 2. 主流产品做法

### 2.1 调研参考

| 来源 | 可借鉴做法 |
| --- | --- |
| Elicit Columns | 把论文表格化抽取；每列有名称、说明、答案格式、选择题/Yes-No-Maybe；抽取规则要像给人工标注员的说明 |
| Scholarcy | 使用 flashcard summary 组织论文核心信息，突出 key findings、important points、figures/tables、references，并支持导出 |
| Consensus Study Snapshot | 抽取 population、sample size、methods、outcomes、results 等结构化研究快照 |
| Semantic Scholar TLDR | 用极短摘要承载论文核心贡献，但不替代完整证据来源 |
| Covidence/DistillerSR | 系统综述抽取表单强调字段定义、标准答案、人工确认和审计 |
| OpenAI Structured Outputs / JSON Schema 实践 | LLM 输出应受 schema 约束，并通过模型校验，不合格结果要 repair 或拒绝 |

### 2.2 对本项目的落地结论

论文卡片应采用“结构化快照 + 来源索引 + 质量分”的设计：

```text
PaperChunk[] -> ContextSelector -> LLM structured extraction
             -> schema validation -> source grounding validation
             -> PaperCard + CardQualityReport
```

关键原则：

```text
1. 卡片不是最终证据，EvidenceRecord 才是项目事实层。
2. 卡片字段必须足够稳定，方便证据表逐字段展开。
3. 每个 key finding/limitation/future_work 尽量有 source_span。
4. unknown 比编造更好。
5. fallback 卡片必须低置信并标记来源。
6. 重复生成必须有覆盖/版本策略，不能无限堆新卡片。
```

## 3. 模块目标

### 3.1 一句话目标

把已解析论文的 chunks 转换为一张可信、精炼、可追溯、可校验的 `PaperCard`。

### 3.2 MVP 成功标准

```text
1. 每篇已解析论文默认最多有 1 张 active PaperCard。
2. LLM 输出通过 Pydantic schema 校验。
3. 字段缺失时写 unknown 或空列表，不编造。
4. key_findings、limitations、future_work、possible_gaps 的条目必须尽量绑定 source_span。
5. source_span.chunk_id 必须存在，quote 要能在 chunk.text 中匹配或标记失败。
6. confidence 由字段完整度、来源覆盖、quote 匹配、抽取方式共同计算。
7. fallback 生成的卡片 confidence 不高于 0.5，并标记 extraction_method=fallback。
8. 长论文使用章节选择或分阶段摘要，不能只截断前 8000 字符。
9. 生成后输出 CardQualityReport。
10. batch_generate 只处理 parsed 或有可用 chunks 的论文。
```

## 4. 数据模型

### 4.1 PaperCard 增强

保留当前字段，新增：

```text
version
active
extraction_method          # llm / fallback / manual / imported
model_name
prompt_version
input_chunk_ids
quality_score
quality_flags
validation_errors

```

建议结构：

```python
class PaperCard(BaseModel):
    card_id: str
    paper_id: str
    project_id: str
    version: int = 1
    active: bool = True

    research_question: str = "unknown"
    method: str = "unknown"
    data_or_sample: str = "unknown"
    key_findings: list[str] = Field(default_factory=list)
    limitations: list[str] = Field(default_factory=list)
    future_work: list[str] = Field(default_factory=list)
    topics: list[str] = Field(default_factory=list)
    possible_gaps: list[str] = Field(default_factory=list)

    source_spans: list[SourceSpan] = Field(default_factory=list)
    input_chunk_ids: list[str] = Field(default_factory=list)

    extraction_method: str = "llm"
    model_name: str = ""
    prompt_version: str = "paper_card_v1"
    confidence: float = 0.0
    quality_score: float = 0.0
    quality_flags: list[str] = Field(default_factory=list)
    validation_errors: list[str] = Field(default_factory=list)

    created_at: str = Field(default_factory=lambda: datetime.now().isoformat())
    updated_at: str = Field(default_factory=lambda: datetime.now().isoformat())
```

### 4.2 PaperCardExtractionResult

LLM 原始输出先进入临时 schema：

```python
class ExtractedClaim(BaseModel):
    text: str
    quote: str = ""
    chunk_id: str = ""
    section_type: str = ""


class PaperCardExtractionResult(BaseModel):
    research_question: str = "unknown"
    method: str = "unknown"
    data_or_sample: str = "unknown"
    key_findings: list[ExtractedClaim] = Field(default_factory=list)
    limitations: list[ExtractedClaim] = Field(default_factory=list)
    future_work: list[ExtractedClaim] = Field(default_factory=list)
    topics: list[str] = Field(default_factory=list)
    possible_gaps: list[ExtractedClaim] = Field(default_factory=list)
    confidence: float = 0.0
```

转换为 `PaperCard` 时：

```text
ExtractedClaim.text -> 对应列表字段
ExtractedClaim.quote/chunk_id -> SourceSpan
```

### 4.3 CardQualityReport

```python
class CardQualityReport(BaseModel):
    card_id: str
    paper_id: str
    completeness: float = 0.0
    traceability: float = 0.0
    specificity: float = 0.0
    quote_match_rate: float = 0.0
    missing_fields: list[str] = Field(default_factory=list)
    weak_fields: list[str] = Field(default_factory=list)
    validation_errors: list[str] = Field(default_factory=list)
    recommended_action: str = ""
```

## 5. 输入上下文选择

### 5.1 当前问题

当前：

```text
full_text = " ".join(all chunks)
text_for_llm = full_text[:8000]
```

风险：

```text
1. 只读到前半篇论文。
2. Results/Limitations/Future Work 常在后部，被截掉。
3. chunk_id 和 quote 难以对应。
4. token 超预算时不可控。
```

### 5.2 P0 ContextSelector

按章节选择：

| 字段 | 优先 chunk |
| --- | --- |
| research_question | abstract、introduction |
| method | method、experiment、study_design |
| data_or_sample | method、dataset、participants、experiment |
| key_findings | result、discussion、conclusion |
| limitations | limitation、discussion |
| future_work | conclusion、future_work、discussion |
| possible_gaps | introduction、limitation、future_work、discussion |

预算建议：

```text
abstract: 800 tokens
introduction: 1200 tokens
method: 1200 tokens
result: 1800 tokens
discussion: 1500 tokens
conclusion/limitation/future: 1000 tokens
total: 7000-9000 tokens
```

### 5.3 P1 长论文 map-reduce

```text
1. 每个章节先生成 SectionSummary。
2. 合并 SectionSummary 生成 PaperCard。
3. SourceSpan 回指原始 chunk，而不是中间摘要。
4. 如果字段无来源，不进入高置信卡片。
```

## 6. Prompt 和结构化输出

### 6.1 System Prompt 要求

必须包含：

```text
角色：学术论文结构化信息抽取器。
边界：只能使用输入 chunks，不使用外部知识。
来源：每条 finding/limitation/future_work/gap 必须给 quote 和 chunk_id。
缺失：无明确依据填 unknown 或空列表。
禁止：禁止编造 DOI、作者、年份、数据、效果大小。
格式：严格 JSON schema。
质量：优先具体方法、样本、指标、结果，不要泛泛总结。
```

### 6.2 User Prompt 输入格式

```text
论文元数据：
title
authors
year
venue

Chunks:
[chunk_id=..., section=..., page=...]
文本...

请输出 JSON，字段为...
```

### 6.3 输出修复策略

```text
1. invoke_json 返回 dict。
2. PaperCardExtractionResult.model_validate。
3. ValidationError 时进行一次 schema repair prompt。
4. repair 仍失败时 fallback。
5. fallback 必须低置信。
```

## 7. 来源校验

### 7.1 validate_card(card)

校验项：

| 项 | 规则 |
| --- | --- |
| chunk 存在 | 每个 SourceSpan.chunk_id 必须在该 paper 的 chunks 中 |
| quote 匹配 | quote 应在 chunk.text 中 exact 或 fuzzy match |
| 字段为空 | 标记 missing_fields |
| unknown | 允许，但降低 completeness |
| 泛化套话 | 标记 weak_fields |
| 条目过多 | 每字段最多 5-8 条，超出截断或标记 |

### 7.2 幻觉检测

最小规则：

```text
claim 中的关键数字、数据集名、方法名应在相关 chunk 或 quote 中出现。
如果 finding 的主要实体在输入 chunks 中完全找不到，标记 unsupported_claim。
unsupported_claim 不进入 evidence high strength。
```

### 7.3 source_span 覆盖率

```text
traceability = 有有效 source_span 的关键条目数 / 关键条目总数
```

关键条目包括：

```text
key_findings
limitations
future_work
possible_gaps
method
data_or_sample
```

## 8. 置信度和质量分

### 8.1 confidence 规则

```text
base = LLM 给出的 confidence 或默认 0.5
+0.1 字段完整度高
+0.1 source span 覆盖率 >= 0.8
+0.1 quote match rate >= 0.8
-0.2 fallback
-0.2 unsupported_claim 存在
-0.1 关键字段 unknown 过多
-0.1 只使用 abstract 生成
```

约束：

```text
fallback confidence <= 0.5
quote_match_rate < 0.5 时 confidence <= 0.6
无 chunks 时不生成 card
```

### 8.2 quality_score

```text
quality_score = 0.4 * completeness + 0.4 * traceability + 0.2 * specificity
```

字段定义：

| 指标 | 含义 |
| --- | --- |
| completeness | 研究问题、方法、样本、发现、局限、未来工作是否齐全 |
| traceability | 关键条目是否有 source span 和 quote |
| specificity | 是否包含具体方法、样本、指标、结果，而非空泛套话 |

## 当前代码对齐深化（2026-05-29）

### 当前实现确认


### 下一步深化任务

```text
1. PaperCardGenerator 全面迁移到 LLMService.invoke_structured，并绑定 prompt name/version/schema。
```
