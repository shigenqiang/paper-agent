### 1.2 当前主要缺口

| 领域 | 当前状态 | 问题 |
| --- | --- | --- |
| 输入上下文 | ContextSelector 按章节选择，总预算 8000 tokens | 长论文多章节时仍可能截断，无 map-reduce |
| 结构化输出 | `invoke_json` + Pydantic 校验 + 一次 repair | 未接入 `invoke_structured` 流水线，缺少结构化日志和 repair 计数 |
| Prompt 版本化 | `PromptRegistry` 已定义 `PAPER_CARD_PROMPT` 但未接入 | generator 使用内联 `SYSTEM_PROMPT`，prompt 版本不可追踪 |
| source_spans | ExtractedClaim→SourceSpan 转换已实现 | `_compute_traceability` 按 field 而非按条目计分，多条目少 span 时虚高 |
| 幻觉校验 | `_validate_card` 检查 quote 匹配和泛化短语 | 缺少 unsupported_claim 级别检测（关键实体在 chunks 中完全找不到） |

| 置信度 | 规则化计算已实现 | 缺少 quote_match_rate 约束（当前 <0.5 时不降 confidence） |
| fallback | 关键词句子抽取 | 按 `.` 分句不适用于中文，3 条上限硬编码 |
| 下游对接 | 无显式对接代码 | 卡片→证据表、图谱、QA 的字段映射未文档化 |
| 测试覆盖 | 21 个测试全走 fallback 路径 | LLM 成功路径、repair、fuzzy_match、specificity 等未覆盖 |

## 2. 主流产品做法

### 2.1 调研参考

| 来源 | 可借鉴做法 |
| --- | --- |
| Elicit Columns | 把论文表格化抽取；每列有名称、说明、答案格式、选择题/Yes-No-Maybe；抽取规则要像给人工标注员的说明 |
| Scholarcy | 使用 flashcard summary 组织论文核心信息，突出 key findings、important points、figures/tables、references，并支持导出 |
| Consensus Study Snapshot | 抽取 population、sample size、methods、outcomes、results 等结构化研究快照 |
| Semantic Scholar TLDR | 用极短摘要承载论文核心贡献，但不替代完整证据来源 |
| Covidence/DistillerSR | 系统综述抽取表单强调字段定义、标准答案、人工确认和审计 |
| OpenAI Structured Outputs / JSON Schema 实践 | LLM 输出应受 schema 约束，并通过模型校验，不合格结果要 repair 或拒绝 |
| Consensus Claims & Evidence Table | evidence_direction（supporting/contrasting/mentioning）+ consensus_level |
| Scite | 引用意图分类，卡片需保留引用立场信息 |

### 2.2 对本项目的落地结论

论文卡片应采用"结构化快照 + 来源索引 + 质量分"的设计：

```text
PaperChunk[] -> ContextSelector -> LLM structured extraction
             -> schema validation -> source grounding validation
             -> PaperCard + CardQualityReport
```

关键原则：

```text
1. 卡片不是最终证据，EvidenceRecord 才是项目事实层。
2. 卡片字段必须足够稳定，方便证据表逐字段展开。
3. 每个 key finding/limitation/future_work 尽量有 source_span。
4. unknown 比编造更好。
5. fallback 卡片必须低置信并标记来源。
6. 重复生成必须有覆盖/版本策略，不能无限堆新卡片。
7. 卡片是知识图谱节点的种子来源（Topic/Method/Finding/Limitation/Gap）。
8. 卡片质量直接影响下游综述和创新点报告的可信度。
```

## 3. 模块目标

### 3.1 一句话目标

把已解析论文的 chunks 转换为一张可信、精炼、可追溯、可校验的 `PaperCard`。

### 3.2 MVP 成功标准

```text
1. 每篇已解析论文默认最多有 1 张 active PaperCard。
2. LLM 输出通过 Pydantic schema 校验。
3. 字段缺失时写 unknown 或空列表，不编造。
4. key_findings、limitations、future_work、possible_gaps 的条目必须尽量绑定 source_span。
5. source_span.chunk_id 必须存在，quote 要能在 chunk.text 中匹配或标记失败。
6. confidence 由字段完整度、来源覆盖、quote 匹配、抽取方式共同计算。
7. fallback 生成的卡片 confidence 不高于 0.5，并标记 extraction_method=fallback。
8. 长论文使用章节选择或分阶段摘要，不能只截断前 8000 字符。
9. 生成后输出 CardQualityReport。
10. batch_generate 只处理 parsed 或有可用 chunks 的论文。
11. 卡片字段能稳定映射到 EvidenceRecord 和 KnowledgeGraph 节点。
12. prompt 版本可追踪，测试和线上使用相同 prompt。
```

## 5. 输入上下文选择

### 5.1 当前问题

当前实现（ContextSelector）：

```text
按 section_type 分组，每组有 token 预算，按优先级填充，总预算 8000 tokens。
```

当前已解决的问题：

```text
1. 不再粗暴截断前 8000 字符。✅
2. 按章节优先级选择，Results/Discussion 不会被无条件截掉。✅
3. chunk 保留 section_type 和 chunk_index，可追溯。✅
```

剩余风险：

```text
1. 超长论文（>30 chunks）单轮选择仍可能遗漏重要章节。
2. 每个 section_type 的 token 预算是固定的，不随论文结构调整。
3. Abstract 泛化内容可能占用过多预算。
```

### 5.2 P0 ContextSelector（已实现）

按章节选择：

| 字段 | 优先 chunk |
| --- | --- |
| research_question | abstract、introduction |
| method | method、experiment、study_design |
| data_or_sample | method、dataset、participants、experiment |
| key_findings | result、discussion、conclusion |
| limitations | limitation、discussion |
| future_work | conclusion、future_work、discussion |
| possible_gaps | introduction、limitation、future_work、discussion |

当前 token 预算（`_SECTION_BUDGETS`）：

```text
abstract: 800 tokens
introduction: 1200 tokens
method: 1200 tokens
result: 1800 tokens
discussion: 1500 tokens
conclusion/limitation/future: 1000 tokens
total: 7000-9000 tokens
```

### 5.3 P1 长论文 map-reduce

```text
1. 每个章节先生成 SectionSummary。
2. 合并 SectionSummary 生成 PaperCard。
3. SourceSpan 回指原始 chunk，而不是中间摘要。
4. 如果字段无来源，不进入高置信卡片。
```

设计要点：

```text
- SectionSummary 包含：section_type, key_claims (list[str]), chunk_ids (list[str])
- 合并时用 SectionSummary 作为 LLM 输入，但 SourceSpan 仍绑定原始 chunk_id
- 章节可信度权重：method/result > discussion/conclusion > abstract/introduction
- 超过 15 chunks 的论文自动走 map-reduce 路径
```

## 6. Prompt 和结构化输出

### 6.1 System Prompt 要求

当前实现（`paper_card.py` 内联 `SYSTEM_PROMPT`）已覆盖：

```text
角色：学术论文结构化信息抽取器。✅
边界：只能使用输入 chunks，不使用外部知识。✅
来源：每条 finding/limitation/future_work/gap 必须给 quote 和 chunk_id。✅
缺失：无明确依据填 unknown 或空列表。✅
禁止：禁止编造 DOI、作者、年份、数据、效果大小。✅
格式：严格 JSON schema。✅
质量：优先具体方法、样本、指标、结果，不要泛泛总结。✅
```

### 6.2 User Prompt 输入格式

```text
论文元数据：
title
authors
year
venue

Chunks:
[chunk_id=..., section=..., page=...]
文本...

请输出 JSON，字段为...
```

### 6.3 输出修复策略

当前实现：

```text
1. invoke_json 返回 dict。                     ✅
2. PaperCardExtractionResult.model_validate。   ✅
3. _repair_extraction 修复 string→ExtractedClaim。 ✅
4. repair 仍失败时 fallback。                    ✅
5. fallback 必须低置信（confidence=0.3）。        ✅
```

### 6.4 P1：迁移到 invoke_structured + PromptRegistry

目标：将 `_extract_card` 从 `invoke_json` 迁移到 `invoke_structured`，接入 `PromptRegistry`。

```text
改造步骤：
1. 将内联 SYSTEM_PROMPT 移入 PromptRegistry 的 PAPER_CARD_PROMPT.spec.system_prompt
2. _extract_card 调用 self.llm.invoke_structured(
       system_prompt=prompt_spec.system_prompt,
       user_prompt=user_prompt,
       schema=PaperCardExtractionResult,
       prompt_name="paper_card_extraction",
       prompt_version="v1"
   )
3. invoke_structured 返回的 dict 包含 success/data/raw_response/request_id/latency_ms
4. 失败时利用 invoke_structured 内置的 repair 流水线（repair_json_with_llm）
5. 将 request_id 和 latency_ms 写入卡片 metadata 用于追溯
6. prompt 版本变更时 bump version（v1→v2），旧卡片的 prompt_version 保留不变
```

收益：

```text
- 结构化日志自动记录（prompt_name/version/model/latency/tokens）
- schema 校验和 repair 在 LLM 层统一处理
- 测试可通过 FakeLLMService.set_response() 按 prompt key 返回不同响应
- prompt 版本可追踪，线上报告可复现
```

## 7. 来源校验

### 7.1 validate_card(card)

校验项：

| 项 | 规则 | 当前状态 |
| --- | --- | --- |
| chunk 存在 | 每个 SourceSpan.chunk_id 必须在该 paper 的 chunks 中 | ✅ 已实现 |
| quote 匹配 | quote 应在 chunk.text 中 exact 或 fuzzy match | ✅ 已实现（threshold=0.6） |
| 字段为空 | 标记 missing_fields | ✅ 已实现 |
| unknown | 允许，但降低 completeness | ✅ 已实现 |
| 泛化套话 | 标记 weak_fields | ✅ 已实现（`_is_generic`） |
| 条目过多 | 每字段最多 5-8 条，超出截断或标记 | ❌ 未实现 |

### 7.2 幻觉检测

当前最小规则（已实现）：

```text
quote 匹配校验：chunk_id 存在 + quote 在 chunk.text 中。     ✅
泛化套话检测：_GENERIC_PHRASES 列表。                        ✅
```

P1 增强：

```text
claim 中的关键数字、数据集名、方法名应在相关 chunk 或 quote 中出现。
如果 finding 的主要实体在输入 chunks 中完全找不到，标记 unsupported_claim。
unsupported_claim 不进入 evidence high strength。
```

实现方案：

```text
1. 提取 claim 中的实体（数字、专有名词、方法名）
2. 在相关 chunk.text 和 quote 中搜索
3. 匹配率 < 0.3 的标记 unsupported_claim
4. unsupported_claim 写入 card.quality_flags
5. 下游 EvidenceRecord 对 unsupported_claim 降级 evidence_strength
```

### 7.3 source_span 覆盖率

当前实现（`_compute_traceability`）：

```text
traceability = 有有效 source_span 的关键字段数 / 关键字段总数
```

已知缺陷：按 field 而非按条目计分。多条 findings 只要有一个 span 就算 field 覆盖。

P1 修复：

```text
traceability = 有有效 source_span 的关键条目数 / 关键条目总数
```

关键条目包括：

```text
key_findings（逐条）
limitations（逐条）
future_work（逐条）
possible_gaps（逐条）
method
data_or_sample
```

## 8. 置信度和质量分

### 8.1 confidence 规则

当前实现：

```text
base = LLM 给出的 confidence 或默认 0.5
+0.1 字段完整度 >= 0.8
+0.1 source span 覆盖率 >= 0.8
-0.2 fallback（cap at 0.5）
-0.1 research_question 为 unknown
```

P1 增强：

```text
base = LLM 给出的 confidence 或默认 0.5
+0.1 字段完整度高
+0.1 source span 覆盖率 >= 0.8
+0.1 quote match rate >= 0.8
-0.2 fallback
-0.2 unsupported_claim 存在
-0.1 关键字段 unknown 过多
-0.1 只使用 abstract 生成
```

约束：

```text
fallback confidence <= 0.5                    ✅ 已实现
quote_match_rate < 0.5 时 confidence <= 0.6   ❌ 未实现
无 chunks 时不生成 card                        ✅ 已实现
```

### 8.2 quality_score

```text
quality_score = 0.4 * completeness + 0.4 * traceability + 0.2 * specificity
```

字段定义：

| 指标 | 含义 | 当前状态 |
| --- | --- | --- |
| completeness | 研究问题、方法、样本、发现、局限、未来工作是否齐全 | ✅ 已实现（6 字段布尔比） |
| traceability | 关键条目是否有 source span 和 quote | ⚠️ 已实现但计分有缺陷 |
| specificity | 是否包含具体方法、样本、指标、结果，而非空泛套话 | ✅ 已实现（`_is_generic` 计数） |

## 10. 下游对接

### 10.1 卡片→证据表字段映射

PaperCard 是 EvidenceRecord 的唯一默认上游。字段映射：

| PaperCard 字段 | EvidenceRecord 字段 | 转换规则 |
| --- | --- | --- |
| paper_id | paper_id | 直传 |
| project_id | project_id | 直传 |
| research_question | research_question | 直传 |
| method | method | 直传 |
| data_or_sample | data_or_sample | 直传 |
| key_findings[i] | finding | 逐条展开为独立 EvidenceRecord |
| limitations[i] | limitation | 逐条展开 |
| future_work[i] | future_work | 逐条展开 |
| topics | topic | 直传 |
| source_spans 对应条目 | source_chunk_id + source_quote | 按 field+text 匹配 |
| confidence | evidence_strength | 映射到 high/medium/low |
| quality_flags | metadata.quality_flags | 直传 |

evidence_direction 和 consensus_level 由 EvidenceTableService 根据多论文聚合计算，不由卡片直接提供。

### 10.2 卡片→知识图谱节点映射

卡片字段生成图谱节点：

| 卡片字段 | 生成节点 | 关系 |
| --- | --- | --- |
| topics | Topic 节点 | Paper -> BELONGS_TO_TOPIC -> Topic |
| method | Method 节点 | Paper -> USES_METHOD -> Method |
| key_findings | Finding 节点 | Paper -> REPORTS_FINDING -> Finding |
| limitations | Limitation 节点 | Paper -> HAS_LIMITATION -> Limitation |
| possible_gaps | Gap 节点 | Limitation -> SUGGESTS_GAP -> Gap |
| data_or_sample | Dataset 节点（如可识别） | Paper -> USES_DATASET -> Dataset |

### 10.3 卡片→QA 上下文

ScopeQAService 检索时：

```text
1. 根据 RetrievalScope 筛选 paper_ids
2. 获取这些 paper 的 active PaperCard
3. 卡片的 key_findings/limitations/future_work 作为检索上下文
4. source_spans 用于定位原始 chunk 给 LLM
5. confidence 和 quality_flags 用于答案置信度标记
```

### 10.4 卡片→综述和创新点

```text
LiteratureReviewGenerator：
  - 卡片的 key_findings → 综述"主要研究结论"节
  - 卡片的 method → 综述"主要研究方法"节
  - 卡片的 limitations → 综述"现有研究不足"节
  - 卡片的 future_work → 综述"未来研究趋势"节

InnovationReportGenerator：
  - 卡片的 possible_gaps → 创新点"研究空白"
  - 卡片的 limitations → 聚合为"共同局限"创新信号
  - 卡片的 future_work → 聚合为"未来方向"创新信号
  - 卡片的 method → 创新点"方法迁移空间"
```

### 12.2 与 Evidence Table 的接口

```text
EvidenceTableService 消费 PaperCard 的方式：

def generate_from_card(self, card: PaperCard) -> list[EvidenceRecord]:
    """将一张 PaperCard 展开为多条 EvidenceRecord。"""
    records = []
    for finding in card.key_findings:
        span = self._find_span(card.source_spans, "key_findings", finding)
        records.append(EvidenceRecord(
            paper_id=card.paper_id,
            project_id=card.project_id,
            finding=finding,
            source_chunk_id=span.chunk_id if span else "",
            source_quote=span.quote if span else "",
            evidence_strength=self._map_strength(card.confidence),
            ...
        ))
    # limitations, future_work 同理
    return records
```
