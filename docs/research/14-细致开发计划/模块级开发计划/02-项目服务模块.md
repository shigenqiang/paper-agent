# 项目服务模块专项开发计划

更新时间：2026-05-28

项目服务是研究工作区的入口层，负责项目生命周期、项目配置、项目统计、健康检查、演示数据和级联删除策略。它不直接做搜索、解析或生成，但必须能告诉用户“这个项目目前到了哪一步、缺什么、下一步该做什么”。

对应代码：

```text
src/agents_v3/research_workspace/project_service.py
tests/agents_v3/research_workspace/test_project_service.py
```

相关依赖：

```text
src/agents_v3/research_workspace/models.py
src/agents_v3/research_workspace/storage.py
src/agents_v3/research_workspace/paper_library.py
src/agents_v3/research_workspace/parser_service.py
src/agents_v3/research_workspace/paper_card.py
src/agents_v3/research_workspace/evidence_table.py
```

## 1. 当前实现分析

### 1.1 当前已有能力

`ProjectService` 已有方法：

```text
create_project()
list_projects()
get_project()
update_project()
delete_project()
get_project_stats()
```

当前优点：

| 能力 | 状态 |
| --- | --- |
| 项目 CRUD | 已可用 |
| storage 注入 | 构造函数已支持 `storage=None` 注入 |
| 项目统计 | 已统计 papers/cards/evidence/reports |
| updated_at | update_project 已更新 |
| 研究目标字段 | `discipline`、`education_level`、`research_goal` 已存在 |

### 1.2 当前主要缺口

| 领域 | 当前状态 | 问题 |
| --- | --- | --- |
| 删除策略 | `delete_project()` 只删项目本身 | 关联 papers/chunks/cards/evidence/reports 残留 |
| 项目状态 | 无 | 不能表达 importing/parsing/analyzing/ready/failed |
| 项目配置 | 无 | 默认搜索源、模型、报告语言、引用格式无法按项目控制 |
| 健康检查 | 无 | 用户不知道下一步该搜索、解析、生成卡片还是建证据 |
| 统计维度 | 基础计数 | 缺少 imported/parsed/card_ready/evidence_ready、失败数、待审核数 |
| 活动记录 | 无 | 无法显示最近操作、最近任务、失败原因 |
| 演示项目 | 无 | 缺少可重复的端到端 smoke test 数据入口 |
| 归档/恢复 | 无 | 项目列表长期膨胀，无法隐藏历史项目 |
| 导入/导出 | 无 | 无法把一个项目打包备份或迁移 |

## 2. 主流产品做法

### 2.1 调研参考

| 来源 | 可借鉴做法 |
| --- | --- |
| Zotero | library/collection/tag 分层管理；删除 collection 不等于删除 item；trash 可恢复 |
| Notion | database 有属性、视图、过滤、排序；页面有最近更新时间和属性配置 |
| Rayyan/Covidence | review 项目有筛选进度、决策统计、排除理由、协作/审核状态 |
| DistillerSR | 项目级配置、表单、工作流、审计记录和导出是系统综述平台核心 |
| GitHub Projects | 项目状态、任务进度、视图和 activity feed 帮助用户理解当前工作 |

### 2.2 对本项目的落地结论

项目服务应承担三个职责：

```text
1. 生命周期：创建、更新、归档、删除、导入、导出。
2. 状态面板：统计论文、解析、卡片、证据、图谱、报告、任务。
3. 行动建议：基于项目健康检查告诉用户下一步该做什么。
```

不应承担：

```text
1. 直接实现搜索适配器。
2. 直接解析 PDF。
3. 直接调用 LLM 生成卡片或报告。
4. 直接修改证据内容。
```

## 3. 模块目标

### 3.1 一句话目标

让 ProjectService 成为研究工作区的稳定入口：管理项目元数据、配置、状态、统计、健康检查和清理策略。

### 3.2 MVP 成功标准

```text
1. 项目 CRUD 行为稳定且测试隔离。
2. delete_project 支持 cascade=false/true 两种明确策略。
3. get_project_stats 覆盖论文、解析、卡片、证据、图谱、报告、任务。
4. get_project_health 能返回缺口、阻塞原因和下一步建议。
5. ProjectSettings 支持默认搜索源、LLM 模型、报告语言和引用格式。
6. archive_project / restore_project 可隐藏和恢复项目。
7. create_demo_project 可生成端到端 smoke test 所需数据。
8. export_project/import_project 有明确数据包结构。
```

## 4. 项目生命周期设计

### 4.1 ProjectStatus

建议新增：

```python
class ProjectStatus(str, Enum):
    ACTIVE = "active"
    IMPORTING = "importing"
    PARSING = "parsing"
    ANALYZING = "analyzing"
    READY = "ready"
    ARCHIVED = "archived"
    FAILED = "failed"
```

状态不是强约束流程，而是面板展示和任务聚合结果。

### 4.2 状态推导规则

```text
无论文 -> active
有 running search/import task -> importing
有 running parse task -> parsing
有 running card/evidence/graph/report task -> analyzing
有论文且主要产物齐全 -> ready
用户归档 -> archived
关键任务失败且无可用结果 -> failed
```

### 4.3 删除策略

方法签名：

```python
def delete_project(self, project_id: str, cascade: bool = False) -> bool:
    ...
```

行为：

| 参数 | 行为 |
| --- | --- |
| `cascade=False` | 只删除项目记录；如果存在关联数据，默认拒绝或返回明确错误 |
| `cascade=True` | 删除项目及关联 papers/chunks/cards/evidence/graphs/reports/tasks/logs |

建议第一阶段采用更安全行为：

```text
cascade=False 且有关联数据 -> 不删除，返回 False 或抛 ProjectHasChildrenError。
```

### 4.4 归档策略

```python
archive_project(project_id: str) -> Project | None
restore_project(project_id: str) -> Project | None
```

归档只改状态：

```text
archived = true
status = archived
```

不删除任何关联数据。

## 5. ProjectSettings

项目配置建议：

```python
class ProjectSettings(BaseModel):
    default_search_sources: list[str] = Field(default_factory=lambda: ["openalex", "arxiv", "crossref"])
    default_llm_model: str = ""
    default_embedding_model: str = ""
    default_report_language: str = "zh"
    default_citation_style: str = "apa"
    default_scope: dict[str, Any] = Field(default_factory=dict)
    report_template: str = "literature_review"
    evidence_review_required: bool = False
    enable_graph: bool = True
    enable_innovation_report: bool = True
    max_search_results: int = 50
    max_papers: int = 500
```

配置使用规则：

```text
1. 搜索模块读取 default_search_sources 和 max_search_results。
2. LLM 模块读取 default_llm_model。
3. 报告模块读取 default_report_language/default_citation_style/report_template。
4. QA 模块读取 default_scope。
5. 证据表读取 evidence_review_required。
```

## 7. 项目健康检查

### 7.1 get_project_health

新增方法：

```python
def get_project_health(self, project_id: str) -> dict[str, Any]:
    ...
```

输出：

```json
{
  "project_id": "proj_x",
  "status": "active",
  "health": "needs_action",
  "blockers": [],
  "warnings": [],
  "next_actions": [],
  "coverage": {
    "papers_with_pdf": 0.8,
    "papers_parsed": 0.6,
    "papers_with_card": 0.4,
    "papers_with_evidence": 0.2
  }
}
```

### 7.2 规则

| 条件 | health | next_action |
| --- | --- | --- |
| 无论文 | needs_action | 搜索或导入论文 |
| 有论文但无 PDF | needs_action | 下载或上传 PDF |
| 有 PDF 未解析 | needs_action | 运行 PDF 解析 |
| 有 chunks 无 cards | needs_action | 生成论文卡片 |
| 有 cards 无 evidence | needs_action | 构建证据表 |
| 有 evidence 但大量 pending | warning | 审核证据 |
| 有 evidence 无 graph | optional | 构建知识图谱 |
| 有证据无报告 | ready_for_report | 生成综述 |
| 所有主链路齐全 | healthy | 可进行 QA/综述/创新点 |

## 8. 演示项目

### 8.1 create_demo_project

目标：为开发和验收提供固定样例，不依赖外部 API。

方法：

```python
def create_demo_project(self, topic: str = "大语言模型与自主学习") -> Project:
    ...
```

应创建：

```text
1 个 Project
3-5 篇 Paper metadata
每篇 2-4 个 PaperChunk
每篇 1 张 PaperCard
若干 EvidenceRecord
1 个 RetrievalScope 示例
1 个 Report 草稿
```

约束：

```text
演示数据必须标记 metadata.demo = true。
演示数据不可混入真实搜索结果。
```

### 8.2 smoke test

演示项目要支持：

```text
创建项目 -> 列表展示 -> 统计 -> 健康检查 -> QA smoke -> 报告 smoke
```

## 9. 项目导入导出

### 9.1 导出包结构

```text
project_export_{project_id}.json
```

内容：

```json
{
  "format_version": 1,
  "exported_at": "...",
  "project": {},
  "papers": [],
  "paper_chunks": [],
  "paper_cards": [],
  "evidence_records": [],
  "graphs": [],
  "reports": [],
  "report_versions": []
}
```

### 9.2 导入策略

```text
1. 默认生成新的 project_id，避免覆盖现有项目。
2. 可选 preserve_ids=true，用于备份恢复。
3. 如果 ID 冲突，生成 import report。
4. 文件路径只导入元数据，不默认复制 PDF 文件。
```
