## 0. 与产品方案的关联

搜索模块是产品主线的第一环：

```text
论文入库（搜索/上传/导入）
  -> 论文解析（PDF 分块）
  -> 论文卡片
  -> 证据表
  -> 知识图谱
  -> Scope QA
  -> 文献综述
  -> 创新点报告
```

搜索模块的质量直接影响下游所有环节。借鉴产品方案中的以下技术：

| 借鉴来源 | 在搜索模块的应用 |
| --- | --- |
| Anthropic Contextual Retrieval | 搜索结果的 chunk 需携带上下文摘要，供下游 embedding 使用 |
| RAGFlow Parent-Child Chunking | 搜索结果入库后，解析阶段采用 parent-child 分块 |
| Literature Mapper | 跟踪论文引用关系，识别 ghost papers（被引用但不在库中的论文） |
| Inciteful | 引用网络分析，为知识图谱 gap detection 提供输入 |
| Consensus Claims Table | 搜索结果应支持 evidence_direction 标记 |
| PRISMA-trAIce | 搜索决策应可追溯（哪些论文被纳入/排除/为什么） |

### 1.2 当前实现的主要缺口

| 领域 | 当前状态 | 问题 |
| --- | --- | --- |
| 搜索源 | 已有 OpenAlex、arXiv、Semantic Scholar、CrossRef adapter；默认 factory 暂接 OpenAlex/arXiv/Semantic Scholar | CrossRef 尚未进入默认源；PubMed、Europe PMC、CORE、Unpaywall、DataCite 等增强源未实现。 |
| 编排 | 已有 `SearchOrchestrator`，支持多源并发、缓存、限流、合并、排序 | API 当前仍走 `PaperLibraryService.search_candidates()` 内部顺序搜索，尚未统一复用 orchestrator。 |

| 缓存 | 已有 `SearchCache`；`PaperLibraryService` 也有一套 search_cache | 存在两套路由；缓存 key 需要统一包含 offset/field/require_pdf 等参数。 |
| 去重 | 已有 DOI、arXiv ID、标题+年份+作者、标题相似度和合并器 | `duplicate_groups` 还未完整暴露给 API/前端。 |
| 排序 | 已有 BM25 相关性 + 质量分 + 来源优先级 + HyDE + HybridRanker | RRF 多源融合函数存在但主流程未使用；`require_pdf`、field search 尚未参与排序/过滤。HybridRanker 和 HyDERanker 未接入主流程。 |
| 查询优化 | 已有 `QueryOptimizer`（LLM 搜索词优化） | 未接入搜索主流程；搜索前未自动优化学术关键词。 |
| 质量过滤 | 已有 `quality_filter.py` | 两阶段过滤（相关性 + 质量）已接入搜索主流程。 |
| 导入 | 已有 search session 暂存和 commit 入库 | DOI 导入仍是占位元数据，未通过 CrossRef/OpenAlex 补全。 |
| 错误 | `SearchErrorInfo` 和 orchestrator errors 已有 | adapter 仍会吞异常并返回空列表，API 响应未返回 source_stats/errors。 |
| API | 已接入 `/api/rw/projects/{project_ref}/papers/search` 和 `/search/commit` | 缺 search session 查询、source health、source list；搜索响应缺错误和统计字段。 |
| PDF | `Paper.open_access.pdf_url` 与 `pdf_path` 已有 | 仍缺下载校验、失败记录、解析队列衔接和批量下载策略。 |
| 引用网络 | 搜索结果含 `citations` 和 `references` | 未跟踪 ghost papers（被引用但不在库中的论文）；未构建引用网络供 gap detection 使用。 |
| 上下文摘要 | 搜索结果有 title + abstract | 未为下游 Contextual Retrieval 生成 chunk 上下文摘要。 |
| 纳入/排除追溯 | Paper 有 `included` 和 `exclude_reason` | 搜索阶段未记录纳入/排除决策的来源和理由（PRISMA-trAIce 要求）。 |

## 2. 搜索模块目标

### 2.1 一句话目标

把“关键词、DOI、BibTeX、RIS、PDF 上传”等输入统一转换为可去重、可排序、可确认入库的项目论文候选集。

### 2.2 MVP 成功标准

搜索模块第一阶段完成后，必须满足：

```text
1. 支持 OpenAlex + CrossRef + arXiv + Semantic Scholar 四个默认源。
2. 支持 DOI 列表导入并用 CrossRef 补全元数据。
3. 支持搜索结果暂存，用户确认后再入库。
4. 支持 DOI、arXiv ID、标题+年份+作者的去重和合并。
5. 支持每个 source 独立限流、超时、重试、错误分类。
6. 支持 query cache，重复搜索不重复打外部 API。
7. 支持 RRF 或简化融合排序，多源结果有稳定顺序。
8. 搜索失败不破坏项目，错误可追踪。
9. 搜索结果能进入 ParserService 后续解析流程。
```

### 2.3 暂不做

```text
1. 商业数据库订阅源，如 Web of Science、Scopus。
2. 复杂 Learning to Rank 训练。
3. 大规模向量缓存和 ChromaDB 强依赖。
4. 全自动筛选最终文献，不经过用户确认。
5. PDF 批量下载的复杂代理池。
```

## 3. 调研结论落地

### 3.1 搜索源选型

来自 `学术论文搜索开发报告.md` 和 2026-05-29 补充调研的平台矩阵，搜索源分为默认自动接入源、按学科启用源、元数据/PDF 增强源和人工/商业增强源。

默认自动接入组合：

```text
OpenAlex + CrossRef + arXiv + Semantic Scholar
```

生物医学方向增强：

```text
PubMed + Europe PMC
```

开放全文和 PDF 增强：

```text
CORE + Unpaywall
```

数据集、软件和研究对象 DOI 增强：

```text
DataCite
```

| 优先级 | 来源 | 作用 | MVP 处理 |
| --- | --- | --- | --- |
| P0 | OpenAlex | 主力全学科搜索，覆盖论文、作者、机构、引用和开放获取信息 | 默认主搜索源，已接入，需加强过滤和错误上报。 |
| P0 | CrossRef | DOI 权威元数据、期刊/会议/图书章节信息 | 默认补全源；需接入 factory，并用于 DOI 导入。 |
| P0 | arXiv | CS/物理/数学等预印本和前沿论文 | 默认源，已接入；需解决本地 SSL/HTTP、Retry-After、id_list。 |
| P0 | Semantic Scholar | AI/CS、生物医学、引用网络、TLDR、推荐 | 默认增强源，已接入；需修正不支持字段，API key 可选但推荐。 |
| P1 | PubMed | 医学、生物、健康方向权威文献 | 按 discipline 或用户选择启用。 |
| P1 | Europe PMC | 生命科学开放全文、PMC 链接、补充 PubMed | 生物医学项目增强源，适合补全文/PDF。 |
| P1 | CORE | 开放获取论文、仓储论文、PDF/全文 | 有 API key 后用于 PDF/全文补充。 |
| P1 | Unpaywall | DOI 到开放获取状态、PDF URL、landing page | 不作主搜索源；在 DOI 已知时补 open_access 字段。 |
| P2 | DataCite | 数据集、软件、预印本、非传统 DOI 资源 | 用于数据集/软件引用和研究对象扩展。 |
| P2 | The Lens | 学术论文 + 专利关联 | API 需申请，适合后续专利引用分析。 |
| P3 | Scopus | 商业高质量索引和引用分析 | 机构授权/付费增强，不进入默认链路。 |
| P3 | Web of Science | 商业高质量索引、正式综述检索 | 机构授权/付费增强，不进入默认链路。 |
| P3 | IEEE Xplore | 计算机、电气、电子、通信方向工程文献 | 有 key 后按学科增强。 |
| 手工 | Google Scholar | 覆盖广，适合人工补查 | 不建议后端自动抓取；不进入自动搜索链路。 |

平台接入原则：

```text
1. 默认免费链路优先：OpenAlex、CrossRef、arXiv、Semantic Scholar。
2. 学科增强按需启用：PubMed/Europe PMC 面向生物医学，IEEE 面向工程。
3. 元数据补全和 PDF 补全分层：CrossRef/DataCite/Unpaywall/CORE 不必都参与关键词搜索。
4. 商业源和 Google Scholar 不作为默认自动源，避免许可、反爬和可重复性问题。
5. 每个新源必须先定义字段映射、限流、错误分类、测试 fixture，再进入 factory。
```

### 3.2 限流策略

来自 `arxiv_rate_limit_solutions.md` 和搜索开发报告：

| 来源 | 建议频率 | 处理 |
| --- | --- | --- |
| arXiv | 1 次 / 3 秒 | 强制串行，尊重 Retry-After。 |
| OpenAlex | 合理使用，建议 0.5 到 1 秒 | 每源独立限流，缓存优先。 |
| CrossRef | 约 50 次 / 秒，但仍需礼貌请求 | 设置邮箱 User-Agent，失败退避。 |
| Semantic Scholar | 无 key 受限，约 5 次 / 秒 | 429 退避，API key 可选。 |
| PubMed | 无 key 3 次 / 秒，有 key 10 次 / 秒 | 按 key 状态配置。 |

### 3.3 去重和缓存策略

来自 `论文搜索去重优化方案.md`：

- 先查本地，再查外部。
- 批量查重优先，避免 O(n²)。
- 去重 key 使用 Map/set，优先精确 ID。
- 支持 query cache 和结果 cache。
- 高频查询可减少 30% 到 50% 外部 API 调用。
- 后续可做增量搜索。

### 3.4 排序和选取策略

来自 `学术文献选取机制调研报告.md`：

- 第一阶段使用关键词/BM25 类相关性 + 来源优先级 + 年份/引用数。
- 多源融合可使用 RRF，避免某一来源分数不可比。
- 新论文引用数低，不应被简单引用数排序压低。
- 搜索流程应先宽召回，再严格筛选。

### 4.3 关键边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| Adapter | 调用单个外部源并映射字段 | 去重、全局排序、入库。 |
| Orchestrator | 选择源、并发、缓存、降级、融合 | 项目业务状态。 |
| QueryOptimizer | LLM 优化学术关键词 | 搜索执行。 |
| HybridRanker | Dense + Sparse + RRF 融合排序 | 持久化。 |
| DedupService | 判断重复、生成合并建议 | 外部 API 请求。 |
| RankingService | 排序和质量分 | 持久化。 |
| QualityFilter | 两阶段过滤（relevance + quality） | 排序。 |
| PaperLibraryService | 暂存/入库/纳入排除/引用索引 | 外部源细节。 |
| API 层 | 请求响应和任务状态 | 业务算法。 |

## 5. 数据模型和契约

当前 `SearchQuery`、`SearchResult`、`SearchResponse`、`SearchSession` 均已是 Pydantic 模型。论文正式入库使用 `models.py` 中的子模型结构，搜索阶段仍使用轻量 `SearchResult`，提交入库时再转换为 `Paper`。

### 5.0 Paper 正式入库模型

当前 `Paper` 采用子模型结构，不再把 DOI、年份、venue、pdf_url 等字段平铺在顶层：

## 6. 去重与合并设计

### 6.1 规范化函数

必须实现：

```text
normalize_doi()
normalize_arxiv_id()
normalize_title()
normalize_author()
normalize_author_list()
normalize_venue()
```

规则：

- DOI 去掉 `https://doi.org/`、`doi:` 前缀，转小写。
- arXiv ID 去掉版本号时保留 `base_id`，同时保存原始版本。
- 标题转小写、去标点、合并空白、去常见尾部句点。
- 作者保留姓氏和首字母简化键。

### 6.2 去重优先级

```text
1. DOI 精确相同：duplicate，confidence=1.0
2. arXiv ID base 相同：duplicate，confidence=0.98
3. PubMed ID / Semantic Scholar ID / OpenAlex ID 相同：duplicate
4. normalized title + year + first_author 相同：duplicate，confidence=0.9
5. normalized title 相似度 >= 0.95 且 year 相差 <= 1：possible_duplicate
6. title 相似但作者完全不同：possible_duplicate，不自动合并
```

### 6.3 合并策略

字段优先级：

| 字段 | 优先来源 |
| --- | --- |
| DOI | CrossRef > publisher > OpenAlex > Semantic Scholar > arXiv |
| title | CrossRef/OpenAlex 标准标题优先 |
| abstract | Semantic Scholar/OpenAlex/arXiv 中更完整者 |
| pdf_url | arXiv > OpenAlex best_oa_location > source payload |
| citations | Semantic Scholar/OpenAlex 较新值 |
| venue | CrossRef > OpenAlex > Semantic Scholar |

合并后保留：

```text
sources: ["openalex", "arxiv"]
source_ids: {openalex: "...", arxiv: "..."}
raw_by_source: {...}
```

## 21. 研究借鉴增强（2026-06-01）

基于产品方案调研（见 `docs/research/00-综合调研报告/学术报告生成系统产品借鉴与技术方案调研.md`），搜索模块需增强以下能力，为下游 Contextual Retrieval、知识图谱和 Gap Detection 提供高质量输入。

### 21.1 Contextual Retrieval 准备（Phase S7）

借鉴来源：Anthropic Contextual Retrieval

目标：搜索结果入库后，为每个 chunk 生成上下文摘要，供下游 embedding 和 BM25 混合检索使用。

实现步骤：

```text
1. Paper 入库后，解析阶段为每个 chunk 生成上下文摘要
2. 上下文摘要格式："[论文标题] [章节名] [前后文概述]"
3. 将上下文摘要存储在 PaperChunk.context_summary 字段
4. 下游 embedding 时，将 context_summary prepend 到 chunk 文本前
5. 同时维护 BM25 索引（基于原始文本）
6. 检索时融合向量检索和 BM25 结果
```

对应代码：

```text
src/agents_v3/research_workspace/parser_service.py  -> 增加 generate_context_summary()
src/agents_v3/research_workspace/retrieval.py       -> 新增混合检索
```

效果预期：减少 49-67% 失败检索。

与 PDF 解析模块的关系：

```text
04-PDF解析与分块模块.md 中 T4.26 "Contextual Retrieval（chunk 上下文增强）"是本任务的下游。
搜索模块负责提供高质量的 Paper metadata（title、abstract、authors、venue），
解析模块负责基于这些 metadata 生成 chunk 上下文摘要。
```

### 21.2 引用网络与 Ghost Paper 检测（Phase S8）

借鉴来源：Literature Mapper + Inciteful

目标：跟踪论文引用关系，识别被引用但不在库中的论文（ghost papers），为知识图谱 gap detection 提供输入。

实现步骤：

```text
1. 搜索结果入库时，保存 Paper.identifiers 和 Paper.citation.references
2. 构建项目级引用索引：paper_id -> list[referenced_doi]
3. 检测 ghost papers：被引用但 DOI 不在项目论文库中的论文
4. 将 ghost papers 存储为 GhostPaper 节点（借鉴 Literature Mapper）
5. 统计 ghost paper 被引用频次，高频 ghost papers 可能表示重要遗漏
6. 提供 API：GET /api/rw/projects/{project_id}/ghost-papers
```

对应代码：

```text
src/agents_v3/research_workspace/paper_library.py  -> 增加 build_citation_index()
src/agents_v3/research_workspace/graph_service.py  -> 增加 detect_ghost_papers()
```

Ghost Paper 数据结构：

```python
class GhostPaper(BaseModel):
    doi: str = ""
    title: str = ""
    cited_by: list[str] = Field(default_factory=list)  # paper_ids that cite this
    citation_count: int = 0  # how many papers in the project cite this
    suggested_import: bool = True  # should user import this paper?
```

### 21.3 纳入/排除追溯（Phase S4 增强）
