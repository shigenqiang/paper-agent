### 1.2 当前实现的主要缺口

| 领域 | 当前状态 | 问题 |
| --- | --- | --- |
| 搜索源 | 只有基础 arXiv adapter | 缺 OpenAlex、CrossRef、Semantic Scholar、PubMed。 |
| 编排 | `PaperLibraryService` 顺序调用 adapters | 缺 source selection、并发、降级、熔断、结果融合。 |
| 限流 | arXiv 内部简单 sleep | 缺统一 RateManager、Retry-After、指数退避。 |
| 缓存 | 无 | 重复查询会反复打外部 API。 |
| 去重 | DOI > arXiv ID > title/year | 缺 DOI/arXiv 规范化、作者参与、模糊去重、合并策略。 |
| 排序 | adapter 返回什么就是什么 | 缺 BM25/关键词评分、RRF 多源融合、质量评分。 |
| 导入 | search_and_import 直接入库 | 缺搜索结果暂存、用户确认、批量选择、冲突提示。 |
| 错误 | adapter 异常吞掉并返回空 | 缺错误分类、降级源、可观测错误报告。 |
| API | 尚未接入 `/api/rw` | 前端无法完成搜索、预览、选择入库。 |
| PDF | 只保存 `pdf_url` | 缺 PDF 下载、文件校验、解析队列衔接。 |

## 2. 搜索模块目标

### 2.1 一句话目标

把“关键词、DOI、BibTeX、RIS、PDF 上传”等输入统一转换为可去重、可排序、可确认入库的项目论文候选集。

### 2.2 MVP 成功标准

搜索模块第一阶段完成后，必须满足：

```text
1. 支持 OpenAlex + arXiv + CrossRef 三个核心源。
2. 支持 DOI 列表导入并用 CrossRef 补全元数据。
3. 支持搜索结果暂存，用户确认后再入库。
4. 支持 DOI、arXiv ID、标题+年份+作者的去重和合并。
5. 支持每个 source 独立限流、超时、重试、错误分类。
6. 支持 query cache，重复搜索不重复打外部 API。
7. 支持 RRF 或简化融合排序，多源结果有稳定顺序。
8. 搜索失败不破坏项目，错误可追踪。
9. 搜索结果能进入 ParserService 后续解析流程。
```

### 2.3 暂不做

```text
1. 商业数据库订阅源，如 Web of Science、Scopus。
2. 复杂 Learning to Rank 训练。
3. 大规模向量缓存和 ChromaDB 强依赖。
4. 全自动筛选最终文献，不经过用户确认。
5. PDF 批量下载的复杂代理池。
```

## 3. 调研结论落地

### 3.1 搜索源选型

来自 `学术论文搜索开发报告.md` 的平台矩阵，MVP 推荐组合：

| 优先级 | 来源 | 作用 | MVP 处理 |
| --- | --- | --- | --- |
| P0 | OpenAlex | 主力全学科搜索，覆盖广，免费 | 第一优先接入。 |
| P0 | arXiv | CS/物理/数学预印本 | 已有基础实现，需要限流和错误增强。 |
| P0 | CrossRef | DOI 和出版元数据补全 | 用于 DOI 导入和结果补全。 |
| P1 | Semantic Scholar | 引用数、影响力、论文详情 | 作为增强源。 |
| P1 | PubMed | 生物医学场景 | 按学科启用。 |

### 3.2 限流策略

来自 `arxiv_rate_limit_solutions.md` 和搜索开发报告：

| 来源 | 建议频率 | 处理 |
| --- | --- | --- |
| arXiv | 1 次 / 3 秒 | 强制串行，尊重 Retry-After。 |
| OpenAlex | 合理使用，建议 0.5 到 1 秒 | 每源独立限流，缓存优先。 |
| CrossRef | 约 50 次 / 秒，但仍需礼貌请求 | 设置邮箱 User-Agent，失败退避。 |
| Semantic Scholar | 无 key 受限，约 5 次 / 秒 | 429 退避，API key 可选。 |
| PubMed | 无 key 3 次 / 秒，有 key 10 次 / 秒 | 按 key 状态配置。 |

### 3.3 去重和缓存策略

来自 `论文搜索去重优化方案.md`：

- 先查本地，再查外部。
- 批量查重优先，避免 O(n²)。
- 去重 key 使用 Map/set，优先精确 ID。
- 支持 query cache 和结果 cache。
- 高频查询可减少 30% 到 50% 外部 API 调用。
- 后续可做增量搜索。

### 3.4 排序和选取策略

来自 `学术文献选取机制调研报告.md`：

- 第一阶段使用关键词/BM25 类相关性 + 来源优先级 + 年份/引用数。
- 多源融合可使用 RRF，避免某一来源分数不可比。
- 新论文引用数低，不应被简单引用数排序压低。
- 搜索流程应先宽召回，再严格筛选。


`PaperLibraryService` 只负责项目论文库操作，不应继续承载全部搜索编排。

### 4.2 调用链路

```text
API / 前端
  -> PaperLibraryService.search_candidates()
  -> SearchOrchestrator.search()
  -> SearchStrategy 选择 sources
  -> SearchCache 查询缓存
  -> RateManager 控制各 source
  -> SourceAdapter 搜索
  -> SearchResultMerger 去重合并
  -> RankingService 排序
  -> SearchSession 暂存结果
  -> PaperLibraryService.commit_search_results()
  -> Paper 入库
```

### 4.3 关键边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| Adapter | 调用单个外部源并映射字段 | 去重、全局排序、入库。 |
| Orchestrator | 选择源、并发、缓存、降级、融合 | 项目业务状态。 |
| DedupService | 判断重复、生成合并建议 | 外部 API 请求。 |
| RankingService | 排序和质量分 | 持久化。 |
| PaperLibraryService | 暂存/入库/纳入排除 | 外部源细节。 |
| API 层 | 请求响应和任务状态 | 业务算法。 |

## 6. 去重与合并设计

### 6.1 规范化函数

必须实现：

```text
normalize_doi()
normalize_arxiv_id()
normalize_title()
normalize_author()
normalize_author_list()
normalize_venue()
```

规则：

- DOI 去掉 `https://doi.org/`、`doi:` 前缀，转小写。
- arXiv ID 去掉版本号时保留 `base_id`，同时保存原始版本。
- 标题转小写、去标点、合并空白、去常见尾部句点。
- 作者保留姓氏和首字母简化键。

### 6.2 去重优先级

```text
1. DOI 精确相同：duplicate，confidence=1.0
2. arXiv ID base 相同：duplicate，confidence=0.98
3. PubMed ID / Semantic Scholar ID / OpenAlex ID 相同：duplicate
4. normalized title + year + first_author 相同：duplicate，confidence=0.9
5. normalized title 相似度 >= 0.95 且 year 相差 <= 1：possible_duplicate
6. title 相似但作者完全不同：possible_duplicate，不自动合并
```

### 6.3 合并策略

字段优先级：

| 字段 | 优先来源 |
| --- | --- |
| DOI | CrossRef > publisher > OpenAlex > Semantic Scholar > arXiv |
| title | CrossRef/OpenAlex 标准标题优先 |
| abstract | Semantic Scholar/OpenAlex/arXiv 中更完整者 |
| pdf_url | arXiv > OpenAlex best_oa_location > source payload |
| citations | Semantic Scholar/OpenAlex 较新值 |
| venue | CrossRef > OpenAlex > Semantic Scholar |

合并后保留：

```text
sources: ["openalex", "arxiv"]
source_ids: {openalex: "...", arxiv: "..."}
raw_by_source: {...}
```

## 7. 搜索源 Adapter 计划

### 7.1 BaseSearchAdapter

P0 改造：

```python
class BaseSearchAdapter(ABC):
    source_name: str
    supports: set[str]  # keyword, doi, title, author
    default_limit: int

    def search(self, query: SearchQuery) -> list[SearchResult]: ...
    def search_by_doi(self, doi: str) -> SearchResult | None: ...
    def health_check(self) -> SourceHealth: ...
```

适配器必须：

- 不直接写入 storage。
- 不吞掉错误，统一抛 `SearchError` 或返回 `SearchSourceResult`。
- 映射字段时保留 raw payload。
- 单源内部只做必要字段清洗，不做全局去重。

### 7.2 OpenAlexClient

优先实现，因为覆盖广、免费、适合作为主搜索引擎。

接口：

```text
GET https://api.openalex.org/works?search=...
```

字段映射：

| OpenAlex | SearchResult |
| --- | --- |
| `id` | `openalex_id` |
| `doi` | `doi` |
| `title` | `title` |
| `publication_year` | `year` |
| `authorships[].author.display_name` | `authors` |
| `primary_location.source.display_name` | `venue` |
| `abstract_inverted_index` | `abstract` |
| `cited_by_count` | `citations` |
| `best_oa_location.pdf_url` | `pdf_url` |

| 查询类型 | TTL |
| --- | --- |
| 普通关键词 | 24 小时 |
| DOI 查询 | 7 天 |
| arXiv 最新论文 | 6 小时 |

### 9.4 缓存命中策略

```text

```

P0 先做完全 key 命中；P1 再做语义缓存和增量搜索。

## 10. 排序与融合

### 10.1 单源内分数

基础分：

```text
title_match_score
abstract_match_score
year_score
citation_score
source_priority_score
has_pdf_score
```

P0 简化公式：

```text
final_score =
  0.45 * relevance_score +
  0.20 * source_priority_score +
  0.15 * recency_score +
  0.10 * citation_score +
  0.10 * metadata_completeness
```

### 10.2 多源融合

使用 RRF：

```text
RRF(d) = sum(1 / (k + rank_i))
k = 60
```

P0 可实现简化 RRF：

- 按 `source_rank` 计算融合分。
- 同一 dedup group 合并后取最高质量字段。
- 合并后的 result 保留所有来源。

### 10.3 质量门槛

入库候选至少满足：

```text
title 非空
authors 非空或 source 为 DOI/CrossRef
year 合法或可为空但标记 incomplete
doi/arxiv_id/url 至少一个存在，或者 title+authors 足够完整
```

## 13. 开发阶段

### Phase S0：稳定现有搜索基础

目标：把现有基础搜索代码整理成可继续扩展的骨架。

任务：

```text
S0.1 SearchQuery/SearchResult 从 dataclass 改为 Pydantic。
S0.2 为 SearchResult 增加 result_id、source_rank、source_payload、dedup_key、score 字段。
S0.3 PaperLibraryService 保持 storage/search_adapters 注入。
S0.4 修正 import_doi_list：add_paper_metadata 返回 None 时不追加。
S0.5 修正 import_bibtex：重复项不追加 None。
S0.6 为 search 模块补 README 或模块 docstring。
```

验收：

```text
test_search_dedup.py 通过。
test_search_integration.py 通过。
PaperLibraryService 搜索测试不写真实 data。
```

### Phase S1：强去重与结果合并

目标：搜索结果不会重复入库，多源结果能合并。

任务：

```text
S1.1 实现 normalize_doi。
S1.2 实现 normalize_arxiv_id，去除 v1/v2 版本。
S1.3 实现 normalize_author / first_author_key。
S1.4 实现 DedupService。
S1.5 实现 SearchResultMerger。
S1.6 支持 duplicate / possible_duplicate / merge 三类决策。
S1.7 Paper 入库 metadata 记录 source_ids 和 raw_by_source。
```

验收：

```text
同一 DOI 多源返回只出现一个候选。
同一 arXiv ID v1/v2 能合并。
标题相同、年份相同、第一作者相同能合并。
possible_duplicate 不自动入库覆盖，前端可提示。
```

### Phase S2：OpenAlex + arXiv + CrossRef 三源可用

目标：P0 搜索源完整。

任务：

```text
S2.1 新增 openalex_client.py。
S2.2 增强 arxiv_client.py：URL 编码、Retry-After、year filter、id_list。
S2.3 新增 crossref_client.py。
S2.4 新增 factory.py 注册 sources。
S2.5 每个 adapter 增加 health_check。
S2.6 每个 adapter 有 mock response 测试。
```

验收：

```text
OpenAlex keyword search 可返回标准 SearchResult。
arXiv 搜索不会高于 1 次 / 3 秒。
CrossRef DOI 查询能补全 metadata。
三个源任一失败不会导致整个搜索失败。
```

### Phase S3：限流、重试、缓存、错误降级

目标：搜索对外部 API 友好，对失败可恢复。

任务：

```text
S3.1 新增 errors.py。
S3.2 新增 rate_limit.py。
S3.3 新增 cache.py。
S3.4 adapter 请求统一走 RateManager。
S3.5 429 使用 Retry-After。
S3.6 timeout/network/api error 按策略重试。
S3.7 达到失败阈值后短时熔断 source。
S3.8 SearchResponse 返回 source_stats 和 errors。
```

验收：

```text
重复 query 命中 cache。
429 会等待 Retry-After 或退避。
超时最多重试配置次数。
某 source 熔断后其他 source 仍可返回结果。
错误信息可用于前端展示。
```

### Phase S4：编排、排序、暂存和提交

目标：形成正式产品流程。

任务：

```text
S4.1 新增 orchestrator.py。
S4.2 新增 strategies.py。
S4.3 新增 ranking.py，支持简化相关性和 RRF。
S4.4 PaperLibraryService.search_candidates 创建 SearchSession。
S4.5 commit_search_results 根据 result_ids 入库。
S4.6 list/get search session。
S4.7 搜索结果支持 include/exclude 预选状态。
```

验收：

```text
搜索不会自动入库。
用户选择结果后才创建 Paper。
多源结果按 final_score 稳定排序。
重复结果在 session 中展示为 duplicate_groups。
```

### Phase S5：导入和 PDF 下载衔接

目标：搜索结果进入后续解析链路。

任务：

```text
S5.1 DOI 导入通过 CrossRef/OpenAlex 补全。
S5.2 BibTeX 解析增强，支持 journal/booktitle/url/abstract/arxiv/eprint。
S5.3 新增 RIS 导入。
S5.4 支持从 pdf_url 下载 PDF 到项目 files 目录。
S5.5 下载 PDF 后更新 Paper.status=UPLOADED。
S5.6 下载失败记录 error_message，不影响入库。
```

验收：

```text
DOI 列表可以生成完整 Paper metadata。
BibTeX 多条记录可导入且去重。
RIS 可导入。
有 pdf_url 的搜索结果可选择下载 PDF。
下载后的论文可进入 ParserService.parse_paper。
```

### Phase S6：P1 搜索增强源

目标：提高覆盖率和质量。

任务：

```text
S6.1 新增 semantic_scholar_client.py。
S6.2 新增 pubmed_client.py。
S6.3 策略根据 discipline 自动启用 PubMed。
S6.4 citation/influential citation 进入 ranking。
S6.5 支持 source health 页面。
```

验收：

```text
Semantic Scholar 可补充 citation 信息。
```


## 15. 质量门禁

搜索模块合入前必须满足：

```text
1. 所有默认测试不访问真实外部 API。
2. 外部 API 调用必须有 timeout。
3. 每个 source 必须有 rate limit 配置。
4. 每个 source 必须有字段映射测试。
5. DOI 和 arXiv ID 去重必须有测试。
6. search_candidates 不直接入库。
7. commit_search_results 可重复调用且幂等。
8. 错误不会被静默吞掉，SearchResponse 必须记录 errors。
9. 日志不记录完整 raw payload，只记录 source、query hash、count、elapsed_ms。
```

```text

```

## 20. 验收标准

```text
1. 搜索模块至少支持 OpenAlex、arXiv、CrossRef 三个核心来源。
2. DOI、arXiv ID、标题+年份+作者去重规则稳定可测试。
3. 多源搜索结果有融合排序和来源标记。
4. 搜索失败、限流、超时不会破坏项目数据。
5. 重复搜索能命中缓存或复用 search session。
6. 用户确认前不直接污染正式论文库。
7. commit 后论文能进入 ParserService 后续流程。
8. 搜索、去重、缓存、限流、导入均有单元测试或 mock 集成测试。
```
