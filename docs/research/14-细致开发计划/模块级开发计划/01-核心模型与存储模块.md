# 核心模型与存储模块专项开发计划

更新时间：2026-05-29

本计划聚焦 `models.py`、`storage.py`、`storage_backend.py`、`postgres_storage.py` 与 `vector_storage.py`。目标是先把研究工作区的数据契约和持久化后端打稳，使搜索、PDF 解析、论文卡片、证据表、Scope QA、知识图谱、报告生成都能围绕同一套模型协作。

对应代码：

```text
src/agents_v3/research_workspace/vector_storage.py
tests/agents_v3/research_workspace/test_models.py
```

### 1.3 当前主要缺口

| 领域 | 当前状态 | 问题 |
| --- | --- | --- |
| collection 契约 | 依赖 `_guess_id_field()` 猜测 | 新集合容易漏配，错误不明显 |
| 写入安全 | 直接覆盖 JSON 文件 | API 并发或进程中断可能写坏文件 |
| 事务性 | 单 collection 写入 | 跨集合状态更新可能一半成功一半失败 |
| schema version | 无 | 模型字段扩展后旧数据迁移困难 |
| 查询能力 | 只支持精确等值匹配 | 不支持范围、列表、关键词、排序和分页 |
| 索引 | 每次全量加载 | 论文、证据数量上来后性能下降 |
| 全局 storage | `get_storage()` singleton | 测试隔离和多工作区切换不稳定 |
| 多后端一致性 | JSONStorage/PostgresStorage 并存 | ProjectService、API deps 和测试需要统一语义 |
| 后端配置 | `config.yaml` 支持 postgres/chromadb | 本地无数据库时需要明确降级和健康检查 |
| 向量存储 | `VectorStorage` 已封装 | 尚未接入 Parser/RAG，不应影响 P0 默认链路 |
| PaperChunk | 缺少页码、chunk index、chunk 类型、parser 信息 | 证据追溯和 PDF 定位不足 |
| EvidenceRecord | 缺少 `evidence_type`、`claim`、source span 列表、审核状态 | 下游 QA/图谱/综述无法稳定复用 |
| RetrievalScope | 缺少 resolved 状态、过滤条件、空范围原因 | Scope QA 难以解释“为什么没有结果” |
| ReportVersion | 缺少版本号、diff summary、来源记录 | 报告迭代不可追溯 |
| Task 模型 | 无 | 搜索、下载、解析、生成等长任务没有统一状态 |

### 1.4 当前必须警惕的兼容问题

`ParserService` 当前写入 chunk 时已经包含 `page_number`，但 `PaperChunk` 模型没有该字段。Pydantic 默认会忽略未知字段，导致通过 `PaperChunk(**data)` 读取时页码信息可能丢失。

处理原则：

```text
1. 模型字段要先补齐，再让服务稳定依赖。
2. 对旧 JSON 数据保持可读。
3. 新字段必须有默认值，避免旧集合加载失败。
4. 不要让下游通过 metadata 猜关键字段。
```

### 1.5 当前后端边界

P0 默认后端仍应是 JSONStorage，PostgreSQL 和 ChromaDB 作为可选后端：

```text
JSONStorage:
  - 默认测试和本地演示后端。
  - 支持项目目录隔离。
  - 需要补 atomic write 和显式 collection id 映射。

PostgresStorage:
  - 部署增强后端。
  - 需要与 JSONStorage 在 service 层保持同样语义。
  - ProjectService 的 update/delete/stats 不能只走 JSON 路径。

VectorStorage:
  - P1/P2 检索增强后端。
  - 默认关闭。
  - 未安装 chromadb 时不能影响模型、存储、API 基础测试。
```

`config.yaml` 中的后端配置必须可观测：

```text
storage_backend: json | postgres
vector_storage: none | chromadb
database.postgres.enabled
database.chromadb.enabled
```

API health 应返回有效后端状态，而不是只返回 `status=ok`。

## 2. 主流工程做法

### 2.1 调研参考

| 来源 | 可借鉴做法 |
| --- | --- |
| Pydantic | 用模型定义数据契约、校验、默认值和 JSON Schema |
| SQLite WAL | 本地持久化要考虑原子写、并发读写和恢复 |
| Celery / RQ 类任务系统 | 长任务要有 queued/running/succeeded/failed/cancelled 状态、重试和错误记录 |
| JSON Lines | 追加型日志和事件流适合用一行一个 JSON 对象，便于增量写入 |
| Zotero | 论文库项目应有 tags、collections、duplicates、trash/restore 等概念 |
| Notion 数据库 | 每条记录应有明确属性、类型、过滤、排序和视图配置 |

### 2.2 对本项目的落地结论

MVP 不需要马上引入完整数据库，但模型和存储层要按可迁移的方式设计：

```text
1. Pydantic 模型是唯一数据契约。
2. JSONStorage 只是当前 repository 实现，不应绑死业务逻辑。
3. StorageBackend 协议是 service 层迁移数据库的边界。
4. 每个 collection 必须有显式主键、schema version 和迁移策略。
5. 写入必须使用 atomic write，避免 JSON 文件损坏。
6. 长任务、日志、评估、证据审核都要有事件模型。
7. 后续迁移 PostgreSQL/SQLite/DuckDB 时，service 接口不应大改。
```

## 3. 模块目标

### 3.1 一句话目标

建立稳定的数据模型、集合命名、存储接口和迁移规则，让所有研究工作区模块都能安全读写同一套事实数据。

### 3.2 MVP 成功标准

```text
1. 所有核心模型能 model_validate / model_dump 往返。
2. JSONStorage 写入使用原子替换，不产生半写文件。
3. 所有 service 支持显式 storage 注入，测试不写真实 data 目录。
4. collection 主键映射显式可查，不再依赖隐式猜测。
5. JSONStorage 和 PostgresStorage 对 service 层行为一致。
6. API health 能报告 storage_backend、postgres_available、vector_storage。
7. PaperChunk 支持 page_start/page_end/chunk_index/chunk_type/parser_name。
8. EvidenceRecord 支持 evidence_type/claim/source_spans/review_status。
9. RetrievalScope 支持 resolved、filters、empty_reason。
10. WorkspaceTask 支持长任务状态、进度、错误和 checkpoint。
11. 旧 JSON 数据仍可读取。
12. 为 PostgreSQL/SQLite/DuckDB 迁移预留 repository 接口。
```

### 3.3 暂不做

```text
1. 不在第一阶段引入远程数据库。
2. 不做复杂 SQL 查询优化。
3. 不做多用户权限模型。
4. 不做分布式任务队列。
5. 不做跨机器文件锁。
```

## 6. 存储层改造计划

### 6.1 原子写

`save_collection()` 改为：

```text
1. 写入同目录临时文件。
2. flush + fsync。
3. 使用 os.replace 原子替换目标文件。
4. 失败时保留原文件。
```

验收：

```text
中途异常不会留下半截 JSON。
原文件仍可读取。
```

### 6.2 进程内锁

MVP 增加按 collection 的 `threading.RLock`：

```text
load + modify + save 必须在同一锁内完成。
upsert_item/delete_item 必须持锁。
```

不解决跨进程并发，但先避免同进程 API 并发覆盖。

### 6.3 查询增强

新增轻量查询能力：

### 6.4 Repository 接口

为了后续迁移 SQLite/DuckDB，定义接口：

```python
class WorkspaceRepository(Protocol):
    def load_collection(self, name: str) -> list[dict[str, Any]]: ...
    def save_collection(self, name: str, items: list[dict[str, Any]]) -> None: ...
    def upsert_item(self, name: str, item_id: str, item: dict[str, Any]) -> None: ...
    def get_item(self, name: str, item_id: str) -> dict[str, Any] | None: ...
    def delete_item(self, name: str, item_id: str) -> bool: ...
    def query(self, name: str, filters: dict[str, Any]) -> list[dict[str, Any]]: ...
```

`JSONStorage` 实现该接口，service 依赖接口而不是具体类。

关键测试：

```text
atomic write 失败不破坏旧文件。
query 支持 equals/in/keyword/sort/limit。
临时 storage 不污染真实 data/research_workspace。
legacy chunks_{paper_id} 能迁移到 paper_chunks。
```
