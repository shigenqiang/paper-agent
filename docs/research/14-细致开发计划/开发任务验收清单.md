# 开发任务验收清单

本清单用于把细致开发计划拆成可执行任务。建议按 P0、P1、P2 逐层推进。

## P0：必须完成

### 工程稳定化

- [ ] 所有 `research_workspace` service 支持注入 `JSONStorage`。
- [ ] 测试使用临时 storage，不写入真实 `data/research_workspace`。
- [ ] 增加统一测试 fixture：项目、论文、chunks、卡片、证据、图谱。
- [ ] 增加端到端 smoke test：项目 -> 论文 -> 解析 -> 卡片 -> 证据 -> 图谱 -> QA -> 报告。
- [ ] `__init__.py` 明确导出稳定模型和服务。
- [ ] 清理或忽略 `__pycache__` 等运行产物。

### 论文入库

- [ ] 上传 PDF 时校验文件存在、类型和大小。
- [ ] 保存 PDF 到项目目录，只在 JSON 中保存路径。
- [ ] DOI 导入支持标准化和重复检测。
- [ ] BibTeX 导入能解析 title、authors、year、venue、doi。
- [ ] 搜索接口至少接入一个真实 adapter 或稳定 mock adapter。
- [ ] 去重规则按 DOI > arXiv ID > 标准化标题 + 年份 + 作者执行。
- [ ] 论文支持 include/exclude 和 exclude_reason。

### PDF 解析

- [ ] `ParserService` 能批量解析项目论文。
- [ ] chunks 包含 paper_id、section_title、text、start/end、token_count。
- [ ] 解析失败更新 `PaperStatus.FAILED` 和 `error_message`。
- [ ] PDF 解析失败不影响其他论文继续处理。
- [ ] 至少支持摘要、方法、结果、讨论、局限等章节的基础识别。

### 论文卡片

- [ ] `PaperCardGenerator` 使用 Pydantic 校验 LLM JSON 输出。
- [ ] 卡片包含 research_question、method、data_or_sample、findings、limitations、future_work、topics、possible_gaps。
- [ ] 关键字段有 source_spans 或明确 `unknown`。
- [ ] 卡片生成失败返回可读错误，不写入伪造内容。
- [ ] confidence 根据字段完整度和来源覆盖率计算。

### 证据表

- [ ] `EvidenceTableService` 能从卡片生成多条证据。
- [ ] 每条 evidence 绑定 project_id、paper_id。
- [ ] 每条 evidence 尽量绑定 source_chunk_id 或 source_quote。
- [ ] 支持按 project_id、paper_id、topic、method 查询。
- [ ] 增加 evidence traceability 测试。

### 知识图谱

- [ ] 图谱包含 Paper、Topic、Method、Finding、Limitation、Gap 节点。
- [ ] 图谱包含 BELONGS_TO_TOPIC、USES_METHOD、REPORTS_FINDING、HAS_LIMITATION、SUGGESTS_GAP 关系。
- [ ] 非 Paper 节点记录来源 evidence_ids 或 paper_ids。
- [ ] 支持按 node_ids + hops 获取子图。
- [ ] 支持基础 gap 检测。

### Retrieval Scope

- [ ] 支持 all_project、selected_papers、topic_group、method_group、year_range、graph_subgraph。
- [ ] resolve 后返回 paper_ids、evidence_ids、graph_node_ids、summary。
- [ ] 空 Scope 返回明确错误或空范围说明。
- [ ] Scope 组合过滤可用。
- [ ] Scope guard 测试确保不会返回范围外论文。

### Scope QA

- [ ] QA 只能使用 resolved scope 内的 evidence、papers、graph context。
- [ ] QA 返回 answer、intent、scope_summary、supporting_papers、evidence_records、uncertainty、suggested_actions。
- [ ] 证据不足时明确拒答或降级说明。
- [ ] 至少支持 summary、method_compare、limitation_analysis、gap_analysis。
- [ ] 增加 QA 不越界引用测试。

### 综述报告

- [ ] 综述按研究背景、主题划分、研究脉络、方法、结论、不足、趋势、参考文献组织。
- [ ] 综述记录 scope、paper_ids、evidence_ids。
- [ ] 关键段落能追溯 evidence。
- [ ] 支持 Markdown 导出。
- [ ] 增加综述结构和来源覆盖率测试。

### 创新点报告

- [ ] 创新点来自 gap、共同 limitation、future_work、方法迁移或数据/场景空白。
- [ ] 每个创新点包含文献基础、研究空白、支撑论文、限制证据、可行性、风险、评分。
- [ ] 过滤空泛创新点。
- [ ] 至少能生成 3 个候选创新点，证据不足时说明不足。
- [ ] 增加 innovation generic filter 测试。

### API 和演示闭环

- [ ] 提供 `/api/rw` 前缀的项目、论文、解析、图谱、Scope、QA、报告接口。
- [ ] 长任务有 task_id 和状态查询。
- [ ] 前端四页可跑通：项目论文库、知识图谱、研究 QA、成果报告。
- [ ] 演示项目能从导入论文跑到 Markdown 导出。
- [ ] 用户能查看 QA 和报告来源。

## P1：重要增强

- [ ] 接入 arXiv 和 OpenAlex 两个真实搜索源。
- [ ] 实现搜索缓存和 rate limit。
- [ ] 支持 CrossRef DOI 元数据补全。
- [ ] 支持 RIS 导入。
- [ ] 增加 BM25 检索。
- [ ] 增加向量检索接口，但可先用本地或 mock embedding。
- [ ] 增加 rerank 接口。
- [ ] 图谱实体归一化支持同义词和大小写归一。
- [ ] 支持 QA 回答保存为报告素材。
- [ ] 报告支持版本差异摘要。
- [ ] 前端长任务使用 SSE 或轮询进度。
- [ ] 增加 token 用量和模型调用日志。

## P2：后续扩展

- [ ] 接入 Semantic Scholar、PubMed。
- [ ] 使用 GROBID 或 PyMuPDF 作为 PDF 解析增强。
- [ ] 迁移 SQLite 或 DuckDB 管理结构化数据。
- [ ] 接入 ChromaDB 或其他向量库。
- [ ] 接入 Neo4j 或专业图数据库。
- [ ] 实现复杂 GraphRAG。
- [ ] Word 导出。
- [ ] 新论文监控和提醒。
- [ ] 多用户项目和权限管理。
- [ ] MCP 工具边界。

## 质量门禁

每次合入前至少满足：

- [ ] 相关单元测试通过。
- [ ] 新增服务有失败路径测试。
- [ ] 不把 API key、完整 prompt、完整 PDF 文本写入日志。
- [ ] QA 和报告不引用 Scope 外论文。
- [ ] 报告记录 paper_ids 和 evidence_ids。
- [ ] LLM JSON 输出经过 schema 校验。
- [ ] 批处理任务中单篇论文失败不导致整个项目失败。

## 推荐开发顺序

```text
1. storage 注入和测试隔离
2. 端到端 smoke test
3. 论文搜索 / 导入 / 去重
4. PDF 章节分块
5. PaperCard schema 和来源覆盖
6. Evidence traceability
7. Graph gap 和 Scope guard
8. Scope QA 拒答和引用
9. 综述 / 创新点报告来源索引
10. API 聚合层
11. 前端四页联调
12. 评估和监控
```
