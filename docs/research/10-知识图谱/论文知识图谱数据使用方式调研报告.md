# 论文知识图谱数据使用方式调研报告

> 调研时间：2026-06-02
> 调研范围：主流学术知识图谱产品如何使用论文数据，具体数据结构与提取方案
> 前置报告：`学术论文知识图谱构建调研报告.md`、`学术知识图谱构建架构设计调研报告.md`、`学术论文实体抽取方法深度调研报告.md`

---

## 1. 核心问题

本报告聚焦一个关键问题：**知识图谱产品从论文中提取什么数据、用什么数据结构、从论文的哪个部分提取？**

当前项目的问题：
- Paper 模型只存 title + abstract，没有全文
- PaperChunk 是碎片化的 500-900 token 文本
- PaperSection 模型已定义但未持久化
- 知识图谱只从 EvidenceRecord（13字段）构建，不直接使用论文全文

## 3. 论文数据的三个层次

所有知识图谱产品使用的论文数据可分为三个层次：

### 3.1 L0：元数据层（所有产品都用）

```json
{
  "paper_id": "doi:10.48550/arXiv.1706.03762",
  "title": "Attention Is All You Need",
  "authors": [
    {"name": "Ashish Vaswani", "orcid": "0000-0001-5345-...", "affiliation": "Google Brain"}
  ],
  "year": 2017,
  "venue": "NeurIPS",
  "doi": "10.48550/arXiv.1706.03762",
  "abstract": "The dominant sequence transduction models...",
  "citation_count": 90000,
  "references": [
    {"title": "Neural Machine Translation by Jointly Learning...", "doi": "...", "authors": [...]}
  ],
  "keywords": ["attention mechanism", "transformer", "machine translation"],
  "language": "en",
  "publication_type": "conference",
  "is_open_access": true
}
```

**数据来源**：Semantic Scholar API、OpenAlex API、CrossRef API、arXiv API
**使用方式**：构建 Paper/Author/Venue/Institution 节点 + CITES/AUTHORED_BY/PUBLISHED_IN 边

### 3.2 L1：结构化提取层（大部分产品用）

从论文全文中提取的结构化信息：

```json
{

  "research_question": "Can attention mechanisms replace recurrence for sequence transduction?",
  "methodology": "Encoder-decoder architecture with multi-head self-attention and positional encoding",
  "data_or_sample": "WMT 2014 English-German (4.5M sentence pairs), English-French (36M)",
  "key_findings": [
    "BLEU 28.4 on EN-DE, surpassing previous best by 2 BLEU",
    "Training time 3.5 days on 8 GPUs to reach SOTA"
  ],
  "limitations": [
    "Only validated on machine translation tasks",
    "May be less effective at capturing local features than CNNs"
  ],
  "future_work": [
    "Apply Transformer to other sequence tasks (vision, audio)"
  ],
  "topics": ["sequence transduction", "attention mechanism", "machine translation"],
  "methods_used": ["multi-head attention", "positional encoding", "layer normalization"],
  "datasets_used": ["WMT 2014 EN-DE", "WMT 2014 EN-FR"],
  "metrics_reported": ["BLEU", "training time", "perplexity"],
  "key_results": [
    {"description": "BLEU 28.4 on WMT 2014 EN-DE", "evidence_quote": "achieved 28.4 BLEU", "section": "Results"}
  ]
}
```

**数据来源**：LLM 从全文提取（Introduction/Method/Results/Discussion）
**使用方式**：构建 Method/Task/Dataset/Metric/Finding/Limitation/Gap 节点 + 相关边

## 4. 各产品的具体数据结构

### 4.1 Microsoft GraphRAG

**输入**：任意文本（不限于论文）

**处理流程**：
```text
源文档 → 文本分块 → LLM实体+关系抽取 → 实体解析 → Leiden社区检测 → 社区摘要生成
```

**输出数据结构**（Parquet 文件）：

| 文件 | 字段 | 说明 |
|------|------|------|
| `entities.parquet` | title, type, description, text_unit_ids | 实体，type 由 LLM 自动推断 |
| `relationships.parquet` | source, target, description, weight, text_unit_ids | 关系 |
| `communities.parquet` | community, level, parent, children, entity_ids | 层次化社区 |
| `community_reports.parquet` | community, summary, findings, rating | LLM 生成的社区摘要 |
| `text_units.parquet` | text, entity_ids, relationship_ids, document_ids | 原始文本块 |

**关键设计**：
- 实体类型不预设 Schema，由 LLM 自动推断（PERSON, ORGANIZATION, EVENT, CONCEPT 等）
- 每个实体/关系都关联到 source text_unit_ids（可追溯原文）
- 社区检测提供多粒度的全局摘要
- 不存储论文结构信息（章节/图表），只存储纯文本

**对论文的使用**：
- 不区分论文的 Introduction/Method/Results 等章节
- 将论文视为普通文档，按 chunk 切分后抽取
- 适合通用文档，但丢失了学术论文的结构信息

### 4.2 Neo4j llm-graph-builder

**输入**：PDF、YouTube、Wikipedia、URL

**处理流程**：
```text
文档 → 文本分块 → LLM抽取实体+关系 → Neo4j 写入
```

**输出数据结构**（Neo4j）：

```cypher
// 实体节点
(:Entity {id, name, type, description, source_chunk_id})

// 关系
(:Entity)-[:RELATIONSHIP {type, description, source_chunk_id}]->(:Entity)

// 文档节点
(:Document {id, name, type, upload_time})

// Chunk 节点
(:Chunk {id, text, position, source_id})

// Chunk 与 Entity 的关系
(:Chunk)-[:HAS_ENTITY]->(:Entity)
(:Chunk)-[:FROM_DOCUMENT]->(:Document)
```

**关键设计**：
- Entity 节点的 type 由 LLM 自动推断
- 每个 Entity 和 Relationship 都关联到 source Chunk
- Chunk 节点保留原文，支持溯源
- 支持自定义 Schema（可预设实体类型）

**对论文的使用**：
- 将论文 PDF 作为 Document 输入
- 不区分论文结构，按 chunk 切分
- Chunk 与 Entity 的关联支持溯源

### 4.3 Semantic Scholar（学术搜索引擎）

**数据模型**（API 返回）：

```json
{
  "paperId": "...",
  "title": "...",
  "abstract": "...",
  "authors": [{"authorId": "...", "name": "..."}],
  "year": 2017,
  "venue": "NeurIPS",
  "citationCount": 90000,
  "fieldsOfStudy": ["Computer Science"],
  "s2FieldsOfStudy": [
    {"category": "Computer Science", "source": "external"},
    {"category": "Mathematics", "source": "external"}
  ],
  "publicationTypes": ["Conference"],
  "referenceCount": 30,
  "citations": [{"paperId": "...", "title": "..."}],
  "references": [{"paperId": "...", "title": "..."}],
  "tldr": {"model": "...", "text": "We propose the Transformer..."}
}
```

**知识图谱结构**：
- Paper 节点 + Author 节点 + Venue 节点
- CITES 边（Paper → Paper）
- AUTHORED_BY 边（Paper → Author）
- Fields of Study（主题分类）
- TLDR（LLM 生成的单句摘要）

**对论文数据的使用**：
- 主要使用元数据层（L0）
- 引用网络是核心数据资产
- 不存储论文全文，只存 abstract + TLDR
- 通过 API 提供给下游产品

### 4.4 OpenAlex（开源学术数据）

**数据模型**（5种核心实体）：

```json
// Work（论文）
{
  "id": "W2741809807",
  "title": "Attention Is All You Need",
  "abstract_inverted_index": {"The": [0], "dominant": [1], ...},
  "publication_year": 2017,
  "doi": "https://doi.org/10.48550/arXiv.1706.03762",
  "type": "journal-article",
  "authorships": [
    {
      "author": {"id": "A5023888391", "display_name": "Ashish Vaswani"},
      "institutions": [{"id": "I97018004", "display_name": "Google"}]
    }
  ],
  "primary_location": {"source": {"id": "S137371705", "display_name": "NeurIPS"}},
  "referenced_works": ["W21...", "W22..."],
  "concepts": [
    {"id": "C154945302", "display_name": "Artificial intelligence", "score": 0.95},
    {"id": "C119857082", "display_name": "Machine learning", "score": 0.85}
  ],
  "cited_by_count": 90000,
  "counts_by_year": [{"year": 2024, "cited_by_count": 15000}]
}
```

**5种核心实体**：
| 实体 | 说明 | 与论文的关系 |
|------|------|-------------|
| Work | 论文/作品 | 核心实体 |
| Author | 作者 | authorships |
| Source | 期刊/会议/仓库 | primary_location |
| Institution | 机构 | authorships.institutions |
| Concept | 主题/概念 | concepts（带置信度分数） |

**对论文数据的使用**：
- 只使用元数据层（L0），不存全文
- abstract_inverted_index 是倒排索引格式（节省空间）
- Concepts 分类带置信度分数
- referenced_works 构成引用网络
- 完全开放 API + 数据快照

### 4.5 paper2lkg（港科大 KGCP）

**输入**：论文 PDF / XML

**处理流程**：
```text
PDF → 章节识别 → 章节级NER → 章节级RE → 实体归一化 → 知识图谱
```

**关键设计**：
- **章节感知**：不同章节使用不同的 NER 模型和 prompt
  - Introduction：侧重 Task, Theory, Prior Work
  - Method：侧重 Method, Model, Algorithm
  - Results：侧重 Metric, Finding, Dataset
  - Discussion：侧重 Limitation, Future Work, Gap
- **SciERC 兼容**：实体类型遵循 SciERC 标准（6种）
- **关系类型**：USED_FOR, HYPONYM_OF, PART_OF, COMPARE, CONJUNCTION, FEATURE_OF, EVALUATE_FOR

**数据结构**：
```python
# 实体
{
    "entity_id": "ent_001",
    "name": "BERT",
    "type": "Method",  # SciERC 类型
    "normalized_name": "bidirectional encoder representations from transformers",
    "source_section": "Method",
    "source_chunk_id": "chunk_005",
    "source_quote": "We use BERT-base as our encoder...",
    "confidence": 0.92
}

# 关系
{
    "relation_id": "rel_001",
    "source_entity": "ent_001",  # BERT
    "target_entity": "ent_002",  # NER
    "relation_type": "USED_FOR",
    "source_section": "Method",
    "source_chunk_id": "chunk_005",
    "confidence": 0.88
}
```

**对论文数据的使用**：
- 使用全文（L2），但按章节分块处理
- 章节感知是核心创新：不同章节提取不同类型的实体
- 每个实体/关系都关联到 source_section 和 source_chunk_id
- 不使用 LLM，使用传统 NER 模型（SciBERT + CRF）

### 4.6 Scite（引用立场分析）

**核心数据结构**：

```json
{
  "citing_paper_id": "p_001",
  "cited_paper_id": "p_002",
  "citation_context": "Previous work by Smith et al. showed that...",
  "citation_type": "supporting",  // supporting / contrasting / mentioning
  "section": "Related Work",
  "surrounding_text": "...3 sentences before and after the citation..."
}
```

**对论文数据的使用**：
- 核心是引用上下文（citation context）
- 从全文中提取引用句及其前后文
- 分类引用意图（supporting/contradicting/mentioning）
- 存储引用所在的章节类型

### 4.7 Elicit / Consensus（结构化提取）

**Elicit 数据结构**（自定义列提取）：

```json
{
  "paper_id": "p_001",
  "columns": {
    "Research Question": {"value": "...", "confidence": 0.95, "source_quote": "...", "section": "Introduction"},
    "Method": {"value": "...", "confidence": 0.90, "source_quote": "...", "section": "Method"},
    "Sample Size": {"value": "4.5M sentence pairs", "confidence": 0.98, "source_quote": "...", "section": "Method"},
    "Key Finding": {"value": "BLEU 28.4", "confidence": 0.95, "source_quote": "...", "section": "Results"},
    "Limitation": {"value": "...", "confidence": 0.85, "source_quote": "...", "section": "Discussion"}

```

    {
      "paper_id": "p_001",

    },
    {
      "paper_id": "p_003",
      "stance": "supporting",

## 5. 从论文哪个部分提取什么

### 5.1 章节-实体类型映射

基于 paper2lkg、SciERC 和各产品的实践：

| 论文章节 | 主要提取的实体类型 | 主要提取的关系类型 | 提取难度 |
|---------|-------------------|-------------------|---------|
| **Title** | Topic, Method | - | 低 |
| **Abstract** | Task, Method, Dataset, Metric, Finding | USED_FOR, EVALUATED_ON | 低 |
| **Introduction** | Task, Theory, Prior Work, Gap | HYPONYM_OF, CONJUNCTION | 中 |
| **Related Work** | Method, Task, Finding | COMPARE, HYPONYM_OF, EXTENDS | 中 |
| **Method** | Method, Model, Algorithm, Dataset | USED_FOR, TRAINED_WITH, PART_OF | 中 |
| **Experiments** | Dataset, Metric, Finding | EVALUATED_ON, EVALUATED_BY | 中 |
| **Results** | Finding, Metric, Dataset | EVALUATED_BY, COMPARE | 中 |
| **Discussion** | Limitation, Future Work, Gap, Finding | SUGGESTS_GAP, COMPARE | 高 |
| **Conclusion** | Finding, Contribution, Future Work | - | 中 |
| **References** | Paper, Author | CITES | 低 |

### 5.2 各章节的信息密度

| 章节 | 实体密度 | 关系密度 | 噪声水平 | 建议处理方式 |
|------|---------|---------|---------|-------------|
| Abstract | 高（每句3-5个） | 高 | 低 | 必须提取，作为基线 |
| Introduction | 中（每段2-3个） | 中 | 低 | 提取 Task/Gap/Contribution |
| Method | 高（每段3-5个） | 高 | 中 | 提取 Method/Dataset/Model |
| Results | 高（表格密集） | 中 | 中 | 提取 Finding/Metric |
| Discussion | 中（每段2-3个） | 中 | 高 | 提取 Limitation/Gap/FutureWork |
| References | 低 | 低 | 低 | 构建 CITES 网络 |

## 6. 当前项目的差距分析

### 6.1 数据层差距

| 层次 | 主流产品 | 当前项目 | 差距 |
|------|---------|---------|------|
| L0 元数据 | 完整（title/authors/year/doi/abstract/references） | title/authors/year/doi/venue/abstract | 缺 references |
| L1 结构化提取 | 从全文提取（Question/Method/Finding/Limitation） | 从 EvidenceRecord 提取（间接） | 缺直接全文提取 |
| L2 全文内容 | 章节级存储 + 实体标注 | 只有 chunk 碎片 | 缺章节级存储 |

### 6.2 提取流程差距

| 步骤 | 主流做法 | 当前项目 | 差距 |
|------|---------|---------|------|
| PDF解析 | GROBID/pymupdf + 章节识别 | pymupdf4llm + 章节识别 ✅ | 无 |
| 章节级NER | 章节感知的实体抽取 | 无独立NER步骤 | 缺 |
| 全文存储 | 章节级全文存储 | 只有 chunk 碎片 | 缺 PaperSection 持久化 |
| 结构化提取 | 从全文提取 + 来源追踪 | 从 EvidenceRecord 间接获取 | 缺直接提取 |
| 关系抽取 | 章节感知的关系抽取 | 从 EvidenceRecord 字段推导 | 缺独立RE |

### 6.3 知识图谱构建差距

| 方面 | 主流做法 | 当前项目 | 差距 |
|------|---------|---------|------|
| 输入数据 | 全文 chunks 或章节文本 | EvidenceRecord 13字段 | 输入范围窄 |
| 实体抽取 | LLM/NER 从原文抽取 | 从 EvidenceRecord 字段构建 | 无直接抽取 |
| 来源追踪 | 实体→chunk→section→paper | 实体→evidence_record→chunk | 间接 |
| 引用网络 | 从 References 构建 CITES 边 | 未实现 | 缺 |
| 作者网络 | 从 Author 信息构建 | 未实现 | 缺 |

## 7. 推荐方案

### 7.1 短期（P0）：基于现有数据结构增强

不改变现有架构，增强 EvidenceRecord → 图谱的提取：

```text
当前：EvidenceRecord (13字段) → GraphService → KnowledgeGraph
增强：EvidenceRecord + PaperCard + PaperChunk → GraphService → KnowledgeGraph
```

具体：
- GraphService 除了读取 evidence_records，也读取 paper_chunks 的 section_type 信息
- 为每个节点/边增加 source_section_type 属性
- 补充 Task 节点（从 research_question 提取）

### 7.2 中期（P1）：补齐 L1 结构化提取

实现 PaperSection 持久化 + 章节级实体抽取：

```text
Paper PDF → parser_service → PaperChunks
PaperChunks → section_assembler → PaperSections（持久化到 paper_sections collection）
PaperSections → entity_extractor → SectionEntity[]
SectionEntity → GraphService → KnowledgeGraph
```

具体：
- `storage.py` 新增 `paper_sections` collection
- `parser_service.py` 解析完成后自动组装 PaperSection
- 新增 `entity_extractor.py`，使用 LLM 从每个 section 抽取实体
- GraphService 读取 PaperSection 的 entities 和 claims 构建图谱

### 7.3 长期（P2）：全文知识图谱

实现 L2 全文存储 + 章节感知的完整图谱构建：

```text
Paper PDF → parser_service → PaperChunks
PaperChunks → section_assembler → PaperSections
PaperSections → llm_entity_extractor → SectionEntity[] + SectionClaim[]
PaperSections → llm_relation_extractor → RelationTriples[]
Entity[] + Relation[] → EntityNormalizer → NormalizedKG
NormalizedKG → GapDetector → Gap[]
NormalizedKG + Gap[] → KnowledgeGraph
```

## 8. 关键发现

### 8.1 论文数据的使用模式

| 模式 | 代表产品 | 优点 | 缺点 |
|------|---------|------|------|
| **元数据驱动** | OpenAlex, DBLP | 低成本、大规模 | 无法回答内容级问题 |
| **全文驱动** | paper2lkg, Elicit | 信息丰富、可追溯 | 成本高、需要NER/RE |
| **混合驱动** | Semantic Scholar | 平衡成本和质量 | 需要多数据源整合 |
| **Evidence驱动** | 当前项目 | 确定性强、可追溯 | 信息损失大、依赖上游质量 |

### 8.2 章节感知是关键差异

paper2lkg 的核心创新是**章节感知提取**：
- Introduction 提取 Task 和 Gap
- Method 提取 Method 和 Dataset
- Results 提取 Finding 和 Metric
- Discussion 提取 Limitation 和 Future Work

这比全文无差别提取精度高 10-15%（论文报告）。

### 8.3 来源追踪是质量保障

所有高质量产品都强调来源追踪：
- GraphRAG：entity → text_unit_ids
- llm-graph-builder：entity → chunk_id
- paper2lkg：entity → section + chunk_id + source_quote
- Elicit：column value → source_quote + section

当前项目的来源追踪是通过 EvidenceRecord 间接实现的，丢失了章节信息。
