# 代码规范

本文档定义代码编写标准，基于以下官方规范：
- [Google Style Guides](https://github.com/google/styleguide)（JS/C++/Python/Go/TypeScript等）
- [PEP 8](https://pep8.org/) — Python官方编码规范
- [Conventional Commits](https://www.conventionalcommits.org/) — Git提交规范

---

## 1. 通用命名规范

### 1.1 命名基本原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **清晰性** | 名称应清晰表达意图 | `getUserById` 而非 `getUser` |
| **一致性** | 同一概念全程使用相同名称 | 统一用 `id` 而非混用 `id`/`ID`/`Id` |
| **简洁性** | 在保证清晰的前提下简短 | `calcTotal` 而非 `calculateTotalAmount` |
| **可读性** | 使用完整单词或常见缩写 | `calculate` 而非 `calc`（除非是公认缩写） |

### 1.2 变量命名

| 类型 | 命名规范 | 示例 |
|------|----------|------|
| 普通变量 | `snake_case` | `user_name`, `total_count` |
| 常量 | `UPPER_SNAKE_CASE` | `MAX_RETRY_COUNT`, `API_BASE_URL` |
| 布尔变量 | `is/has/can/should` 前缀 | `is_active`, `has_permission` |
| 私有变量 | `_` 前缀（Python） | `_private_method` |
| 类成员变量 | `camelCase`（JS/TS） | `this.userName` |

**避免的无意义命名：**
```python
# 禁止
x, temp, data, info, val, obj

# 推荐
user_index, temporary_file, user_data, file_size
```

### 1.3 函数/方法命名

| 场景 | Python规范 | JavaScript规范 |
|------|------------|----------------|
| 普通方法 | `snake_case` | `camelCase` |
| 类方法 | `snake_case` | `camelCase` |
| 私有方法 | `_snake_case` | `_camelCase` |
| 异步方法 | `async_xxx` 或 `xxx_async` | 同普通方法（用async/await） |
| Getter | `get_xxx` | `getXxx` 或直接用属性 |
| Setter | `set_xxx` | `setXxx` 或直接用属性 |

**动词/动词短语参考：**

| 动作 | 方法名示例 |
|------|------------|
| 获取 | `getUser`, `fetchOrders`, `retrieveData` |
| 创建 | `createUser`, `newOrder`, `generateReport` |
| 更新 | `updateUser`, `modifySettings`, `editProfile` |
| 删除 | `deleteUser`, `removeItem`, `destroyRecord` |
| 检查 | `checkPermission`, `validateInput`, `hasAccess` |
| 处理 | `processPayment`, `handleRequest`, `onClick` |

### 1.4 类/类型命名

| 语言 | 规范 | 示例 |
|------|------|------|
| Python | `PascalCase` | `UserService`, `OrderProcessor` |
| JavaScript/TypeScript | `PascalCase` | `UserService`, `OrderProcessor` |
| 接口（TS） | `PascalCase` + `I` 前缀可选 | `IUser` 或 `User` |
| React组件 | `PascalCase` | `UserProfile`, `OrderList` |

### 1.5 文件命名

| 文件类型 | Python | JavaScript/TypeScript |
|----------|--------|----------------------|
| 普通模块 | `snake_case.py` | `camelCase.js` |
| 测试文件 | `test_xxx.py` | `xxx.test.js` 或 `xxx.spec.js` |
| 配置文件 | `snake_case` 或 `kebab-case` | `camelCase` 或 `kebab-case` |
| 组件文件 | - | `PascalCase.jsx` / `.tsx` |

## 2. 代码格式规范

### 2.1 缩进与空格

| 规范项 | Python | JavaScript/TypeScript |
|--------|--------|----------------------|
| 缩进 | 4空格 | 2空格（前端）/ 4空格（Node.js后端） |
| 行宽 | ≤79字符（PEP 8）/ ≤120字符（宽松） | ≤100字符 |
| 方法定义 | `def func():` | `function func() { }` |
| 条件语句 | `if x > 0:` | `if (x > 0) { }` |
| 循环语句 | `for i in range(n):` | `for (let i = 0; i < n; i++) { }` |

**空格规范：**
```python
# 赋值周围加空格
name = "value"          # 是
name="value"            # 否

# 参数周围加空格
func(param1, param2)    # 是
func(param1,param2)     # 否

# 运算符周围加空格
a + b                   # 是
# 优先级明确时可省略
a+b*c                   # 但 `a + b` 更好
```

```javascript
// 函数调用
func(param1, param2);   // 是
func(param1,param2);    // 否

// 对象字面量（属性简短时可紧凑）
const user = { name: "John", age: 30 };  // 是
const user = {name:"John",age:30};        // 否

// 数组
const arr = [1, 2, 3];   // 是
```

### 2.2 换行规范

**长函数调用/定义换行：**
```python
# 参数对齐换行
def long_function_name(
    param_one,
    param_two,
    param_three,
):
    pass

# 或者4空格缩进
result = some_long_function_name(
    argument_one,
    argument_two,
    argument_three,

```

```javascript
// 参数换行
function longFunctionName(
  paramOne,
  paramTwo,
  paramThree,

  // ...
}

// 链式调用换行
const result = someObject
  .methodOne()
  .methodTwo()
  .methodThree();
```


## 3. 注释规范

### 3.1 注释原则

| 原则 | 说明 |
|------|------|
| **必要性** | 只在需要时写注释，不要为明显的代码加注释 |
| **准确性** | 注释必须与代码一致，过时注释比无注释更危险 |
| **简洁性** | 清晰简洁，避免冗长 |
| **可维护性** | 代码修改时同步更新注释 |

### 3.2 注释类型

#### 文件头注释
```python
"""
模块名称：user_service.py
功能描述：用户服务层，提供用户CRUD操作
作者：团队名
创建日期：2024-01-01
最后更新：2024-06-01
依赖模块：models.user, utils.hash
"""
```

```javascript
/**
 * @file userService.js
 * @description 用户服务层，提供用户CRUD操作
 * @author Team Name
 * @date 2024-01-01
 */
```

#### 类注释
```python
class UserService:
    """
    用户服务类

    提供用户注册、登录、信息更新等功能。
    线程安全：否（单例模式保证）
    """
```

```javascript
/**
 * 用户服务类
 * @class UserService
 * @description 提供用户注册、登录、信息更新等功能
 */
class UserService {
  // ...
}
```

#### 方法注释
```python
def get_user_by_id(user_id: int) -> Optional[User]:
    """
    根据ID获取用户

    Args:
        user_id: 用户ID

    Returns:
        User对象或None（不存在时）

        ValueError: user_id无效
```

```javascript

 * 根据ID获取用户
 * @param {number} userId - 用户ID

 * @throws {Error} userId无效或数据库错误
 * @example
 * const user = await getUserById(123);
 */

  // ...
}
```

#### 行内注释
```python
# 优先使用正则表达式（性能更优）
pattern = r'^[a-zA-Z0-9]+$'

# 不要在明显的代码后添加：
# x = x + 1  # x加1   ← 禁止，浪费时间

# 在复杂或晦涩的代码后添加：

```

```javascript

// 不要在明显代码后添加注释：
// const x = x + 1;  ← 禁止
```

## 4. 函数/方法规范

### 4.1 函数设计原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **单一职责** | 一个函数只做一件事 | `validateEmail()` 只验证邮箱 |
| **参数控制** | 参数≤3个最佳，最多5个 | 超出时使用对象或拆分 |
| **返回值明确** | 返回类型一致，避免混合 | 始终返回同类型或None |
| **避免副作用** | 无不可预期的状态修改 | 纯函数更易测试 |

### 4.2 参数规范

**参数命名：**
```python
# 布尔参数使用关键字参数
create_user(name="John", is_admin=False)

# 可选参数放最后
def func(required, optional1=None, optional2=None):
    pass
```

**参数校验：**
```python
def divide(a, b):
    """除法运算"""
    if b == 0:
        raise ValueError("除数不能为零")
    return a / b
```

```javascript
function divide(a, b) {
  if (b === 0) {
    throw new Error('除数不能为零');
  }
  return a / b;
}
```

### 4.3 返回值规范

```python
# 始终返回一致的错误值
def find_user(user_id):
    if not user_id:
        return None  # 或抛出异常
    user = db.get(user_id)
    return user  # 始终返回User或None

# 不要混用
def bad_example(user_id):
    if not user_id:
        return None
    return db.get(user_id)  # 可能是None或User
    # 当user不存在时，实际返回None，与上面None含义相同但写法混乱
```

```javascript
// Promise返回一致
async function findUser(userId) {
  if (!userId) {
    return null;
  }
  const user = await db.get(userId);
  return user;  // 始终返回User或null
}
```

## 5. 类与模块规范

### 5.1 类设计原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 类的职责应单一，< 300行最佳 |
| **开闭原则** | 对扩展开放，对修改关闭 |
| **依赖注入** | 通过构造函数注入依赖 |
| **避免深层继承** | 优先使用组合，继承层级≤ 2 |

### 5.2 Python类规范

```python
class UserService:
    """用户服务类"""

    def __init__(self, db, cache):
        """
        初始化

        Args:
            db: 数据库实例
            cache: 缓存实例
        """
        self._db = db
        self._cache = cache

    @property
    def db(self):
        """只读访问数据库"""
        return self._db

    def get_user(self, user_id):
        """获取用户"""
        # 先查缓存
        cached = self._cache.get(f"user:{user_id}")
        if cached:
            return cached

        # 查数据库
        user = self._db.query(User, user_id)
        if user:
            self._cache.set(f"user:{user_id}", user)
        return user
```

### 5.3 JavaScript/TypeScript类规范

```typescript
class UserService {
  private db: Database;
  private cache: Cache;

  constructor(db: Database, cache: Cache) {
    this.db = db;
    this.cache = cache;
  }

  public async getUser(userId: number): Promise<User | null> {
    // 先查缓存
    const cached = await this.cache.get(`user:${userId}`);
    if (cached) {
      return cached;
    }

    // 查数据库
    const user = await this.db.query(User, userId);
    if (user) {
      await this.cache.set(`user:${userId}`, user);
    }
    return user;
  }
}
```

## 6. 错误处理规范

### 6.1 异常处理原则

| 原则 | 说明 |
|------|------|
| **具体异常** | 抛出具体异常类型，而非通用Exception |
| **包含上下文** | 异常信息应包含有用的调试信息 |
| **不压制异常** | 不要用空的except块 |
| **记录日志** | 捕获异常后记录日志 |

### 6.2 Python异常处理

```python
# 好：具体异常 + 上下文
try:
    user = User.objects.get(id=user_id)
except User.DoesNotExist:
    logger.warning(f"User not found: {user_id}")
    raise UserNotFoundError(f"User {user_id} not found")

# 好：清理资源
try:
    file = open("data.txt", "r")
    content = file.read()
finally:
    file.close()

# 好：使用with自动管理
with open("data.txt", "r") as file:
    content = file.read()

# 禁止：空的except
try:
    risky_operation()
except:
    pass  # 禁止！会隐藏所有错误
```

### 6.3 JavaScript异常处理

```javascript
// 好：具体错误处理
try {
  const user = await getUser(userId);
  if (!user) {
    throw new UserNotFoundError(`User ${userId} not found`);
  }
  return user;
} catch (error) {
  logger.error(`Failed to get user ${userId}:`, error);
  throw error;
}

// 好：Promise错误处理
fetchData()
  .then(processData)
  .catch(error => {
    logger.error('Data fetch failed:', error);
    throw error;
  });

// 好：async/await错误处理
async function loadUser(userId) {
  try {
    return await getUser(userId);
  } catch (error) {
    logger.error(`Failed to load user ${userId}:`, error);
    throw error;
  }
}
```

## 7. 测试规范

### 7.1 测试文件命名

| 类型 | Python | JavaScript |
|------|--------|------------|
| 单元测试 | `test_xxx.py` | `xxx.test.js` |
| 集成测试 | `test_integration_xxx.py` | `xxx.integration.test.js` |
| 组件测试 | - | `xxx.component.test.js` |

### 7.2 测试结构

```python
import pytest
from user_service import UserService

class TestUserService:
    """用户服务测试"""

    @pytest.fixture
    def service(self):
        """测试fixture"""
        db = MockDatabase()
        cache = MockCache()
        return UserService(db, cache)

    def test_get_user_by_id(self, service):
        """测试获取用户"""
        # Arrange
        user_id = 123

        # Act
        user = service.get_user(user_id)

        # Assert
        assert user is not None
        assert user.id == user_id
        assert user.name == "Test User"

    def test_get_nonexistent_user(self, service):
        """测试获取不存在的用户"""
        user = service.get_user(999)
        assert user is None
```

```javascript
describe('UserService', () => {
  let service;

  beforeEach(() => {
    // Setup
    const db = new MockDatabase();
    const cache = new MockCache();
    service = new UserService(db, cache);
  });

  test('getUserById returns user when exists', async () => {
    // Arrange
    const userId = 123;

    // Act
    const user = await service.getUser(userId);

    // Assert
    expect(user).not.toBeNull();
    expect(user.id).toBe(userId);
    expect(user.name).toBe('Test User');
  });

  test('getUserById returns null when not exists', async () => {
    const user = await service.getUser(999);
    expect(user).toBeNull();
  });
});
```

## 附录：常见错误速查

| 错误类型 | 错误示例 | 正确示例 |
|----------|----------|----------|
| 变量命名过短 | `x = get_data()` | `user_data = get_user_data()` |
| 函数名不清晰 | `process()` | `process_payment()` |
| 魔法数字 | `if score > 60` | `if score >= PASSING_SCORE` |
| 硬编码路径 | `/home/user/file` | `get_config_path("file")` |
| 空except块 | `try: ... except: pass` | `try: ... except SpecificError: ...` |
| 全局变量 | `global_counter += 1` | `self.counter += 1` |
| 过深嵌套 | 5层以上if嵌套 | 提取函数 + 卫语句 |
| 重复代码 | 复制粘贴3次以上 | 提取为公共函数 |
| 不良注释 | 解释"如何做"而非"为什么" | 解释业务背景 |
