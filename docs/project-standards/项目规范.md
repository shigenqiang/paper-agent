# 项目规范

本文档定义项目的基本结构、目录组织、工作流程等工程规范。

---

## 1. 项目结构规范

### 1.1 通用项目结构

```
project_name/
├── src/                          # 源代码
│   └── project_name/
│       ├── __init__.py
│       ├── config.py             # 配置文件
│       ├── core/                 # 核心模块
│       │   ├── __init__.py
│       │   └── ...
│       ├── services/             # 服务层
│       │   ├── __init__.py
│       │   └── ...
│       ├── models/               # 数据模型
│       │   ├── __init__.py
│       │   └── ...
│       └── utils/                # 工具函数
│           ├── __init__.py
│           └── ...
├── tests/                        # 测试代码
│   ├── unit/                     # 单元测试
│   ├── integration/              # 集成测试
│   └── conftest.py               # pytest配置
├── docs/                         # 文档
├── scripts/                      # 脚本（部署、构建等）
├── configs/                      # 配置文件（不含敏感信息）
├── logs/                         # 日志目录
├── data/                         # 数据目录（可选）
├── notebooks/                    # Jupyter notebooks（可选）
├── README.md                     # 项目说明
├── CHANGELOG.md                  # 变更日志
├── LICENSE                       # 许可证
├── .gitignore                    # Git忽略配置
├── .editorconfig                  # 编辑器配置
├── pyproject.toml / package.json # 项目元数据
└── requirements.txt / package-lock.json  # 依赖锁定
```

## 2. Git工作流规范

### 2.1 分支命名规范

| 分支类型 | 命名格式 | 示例 |
|----------|----------|------|
| 主分支 | `main` | `main` |
| 开发分支 | `develop` | `develop` |
| 功能分支 | `feature/<issue-id>-<short-description>` | `feature/123-user-login` |
| 修复分支 | `fix/<issue-id>-<short-description>` | `fix/456-fix-auth-bug` |
| 发布分支 | `release/<version>` | `release/v1.0.0` |
| 热修复分支 | `hotfix/<issue-id>-<short-description>` | `hotfix/789-critical-fix` |

### 2.2 Commit Message规范

采用 **Conventional Commits** 标准：

```
<type>(<scope>): <subject>

[optional body]

[optional footer(s)]
```

**Type 类型：**

| Type | 说明 | 是否需要 |
|------|------|----------|
| `feat` | 新功能 | 是 |
| `fix` | Bug修复 | 是 |
| `docs` | 文档更新 | 否 |
| `style` | 格式调整（不影响运行） | 否 |
| `refactor` | 重构（非新功能非修复） | 否 |
| `perf` | 性能优化 | 否 |
| `test` | 测试相关 | 否 |
| `chore` | 构建/工具变更 | 否 |
| `ci` | CI/CD配置 | 否 |
| `build` | 构建系统变更 | 否 |

**提交示例：**

```
feat(auth): add OAuth2 login support

- implement Google OAuth2 flow
- add user profile sync
- fix token refresh race condition

Closes #123
```

### 2.3 PR合并规范

1. **必须经过Code Review**才能合并
2. **必须通过所有CI检查**（测试、lint、类型检查）
3. **Squash Merge**：将多个commit合并为一个，保持历史整洁
4. **删除源分支**：合并后自动删除

## 4. 开发流程规范

### 4.1 Issue规范

Issue标题格式：
```
[<type>] <short description>

# type: feature/bug/enhancement/documentation/refactor
```

Issue内容模板：
```markdown
## 描述
清晰描述问题或需求

## 复现步骤（Bug）
1.
2.
3.

## 期望行为

## 实际行为

## 环境信息
- OS:
- Version:
```

### 4.2 开发周期

| 阶段 | 时长 | 说明 |
|------|------|------|
| Sprint Planning | 1-2小时 | 规划本期任务 |
| 开发 | 1-2周 | 功能开发 |
| Code Review | 持续 | 同行审查 |
| 测试 | 持续 | 自动化+手动 |
| Sprint Review | 结束时 | 演示评审 |
| Sprint Retrospective | 结束后 | 反思改进 |

### 4.3 发布流程

1. 创建release分支：`release/v1.0.0`
2. 更新版本号和CHANGELOG
3. 执行完整测试
4. 合并到main
5. 打Tag：`v1.0.0`
6. 构建发布产物
7. 发布到仓库/市场

## 5. 环境与配置规范

### 5.1 环境分类

| 环境 | 用途 | 数据特点 |
|------|------|----------|
| local/dev | 本地开发 | 测试数据 |
| staging | 预发布测试 | 脱敏生产数据 |
| production | 正式环境 | 真实数据 |

### 5.2 敏感信息管理

- **禁止硬编码**：敏感信息不允许写在代码中
- **环境变量**：使用`.env`文件管理
- **密钥管理**：生产环境使用专门的密钥管理服务
- **.env.example**：提供环境变量模板（不含真实值）

```bash
# .env.example
DATABASE_URL=postgres://user:password@localhost:5432/db
API_KEY=your-api-key-here
SECRET_KEY=your-secret-key-here
```

## 6. 依赖管理规范

### 6.1 Python依赖

使用 `pyproject.toml`：

```toml
[project]
name = "my-project"
version = "1.0.0"
dependencies = [
    "requests>=2.28.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=7.0.0",
    "black>=23.0.0",
    "mypy>=1.0.0",
]

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"
```

### 6.2 Node.js依赖

使用 `package.json` + `package-lock.json`：

```json
{
  "name": "my-project",
  "version": "1.0.0",
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "test": "jest",

    "format": "prettier --write ."

  "dependencies": {

  },
  "devDependencies": {
    "eslint": "^8.0.0",
    "prettier": "^3.0.0",

  }
}
```
