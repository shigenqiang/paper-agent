# Agent评估方法调研报告

**日期**: 2026-04-26
**调研目的**: 研究Agent评估方法论，为Paper Agent系统优化提供依据

---

## 一、调研背景

随着LLM-based Agent系统在各领域广泛应用，如何有效评估Agent的真实能力成为关键问题。传统的单一任务完成率已不足以判断Agent在复杂环境中的可靠性。本报告系统梳理业界主流Agent评估方法论。

---

## 二、评估维度体系

### 2.1 核心评估维度

根据业界研究，Agent评估主要包含以下维度：

| 维度 | 权重 | 说明 |
|------|------|------|
| **任务完成率** | 25% | Agent成功达成业务目标的比例 |
| **输出质量** | 20% | 生成结果的准确性、完整性、专业性 |
| **工具使用能力** | 15% | 工具选择、参数构造、结果理解 |
| **规划能力** | 10% | 任务分解、多步推理、路径规划 |
| **效率** | 10% | 响应时间、资源消耗 |
| **协作能力** | 8% | 多Agent协作、信息传递 |
| **安全性** | 7% | 错误处理、异常防御 |
| **自主纠错** | 5% | 自我识别、调整、恢复 |

### 2.2 三层评估结构

```
┌─────────────────────────────────────────┐
│         场景任务层 (Scenario-level)      │
│    模拟真实业务：网页搜索、邮件、数据库     │
├─────────────────────────────────────────┤
│         基础能力层 (Micro-skills)        │
│    工具调用、任务分解、状态跟踪           │
├─────────────────────────────────────────┤
│         核心评估层 (Core Metrics)        │
│    任务完成率、质量、效率、安全           │
└─────────────────────────────────────────┘
```

## 三、任务维度评估 (Task-Centric)

### 3.1 任务完成率 (Task Success Rate)

**定义**: 在给定初始状态和目标下，Agent成功达成业务目标的比例

**评估方法**:
- **状态断言**: 验证最终状态是否符合预期
- **目标匹配**: 检查输出是否满足任务要求
- **端到端验证**: 完整流程成功执行

```python
# 示例：状态断言评估
def test_book_flight():
    sandbox.set_state(user_balance=5000, orders=[])
    agent.execute("帮我订一张去北京的机票")
    assert sandbox.get_state("orders") != []
```

### 3.2 任务分解质量 (Task Decomposition)

**定义**: 将复杂目标拆分为稳定可执行子任务的能力

**评估指标**:
- 分解的子任务数量是否合理
- 子任务之间的依赖关系是否正确
- 是否存在冗余或遗漏步骤

## 四、工具使用评估 (Tool Use)

### 4.1 工具调用正确率

| 指标 | 说明 |
|------|------|
| 工具选择准确率 | 能否选择正确的工具 |
| 参数构造正确率 | 参数格式、类型是否正确 |
| 调用时序正确率 | 工具调用顺序是否合理 |
| 结果理解准确率 | 能否正确解析工具返回 |

### 4.2 跨工具协同能力

评估Agent在执行多步骤任务时，能否流畅衔接多个不同工具：
- 信息在工具间的正确传递
- 中间结果的正确处理
- 最终完成闭环操作

## 五、规划能力评估 (Planning)

| 基准 | 说明 |
|------|------|
| PlanBench | 规划任务评估 |
| Blocksworld | PDDL规划任务 |

## 六、质量评估 (Quality)

| 维度 | 指标 |
|------|------|
| 准确性 | 内容正确性、事实核查 |
| 完整性 | 覆盖所有必要信息 |

### 6.2 评估方法

- **自动化指标**: BLEU、ROUGE等

## 十一、MiniMax-M2.7模型Agent评估要点

### 11.1 中文编码问题影响

由于MiniMax-M2.7存在中文编码bug，评估时需注意：
- 英文输出质量不受影响
- 中文输出质量受限，需使用TranslationWrapper
- 评估报告应区分英文/中文场景

### 11.2 建议的评估协议

```python
# 评估协议
test_cases = {
    "english_only": [...],  # 纯英文任务
    "chinese_native": [...],  # 中文任务（使用TranslationWrapper）
    "mixed": [...]  # 中英文混合
}

for agent in agents:
    for case in test_cases["english_only"]:
        score = evaluate(agent, case)  # 基准评分

    for case in test_cases["chinese_native"]:
        score = evaluate_with_translation(agent, case)  # 使用wrapper
```

## 十二、评估实施建议

### 12.1 Paper Agent系统评估方案

| Agent类型 | 核心评估维度 | 测试用例数 |
|----------|--------------|------------|
| TopicAgent | 任务完成率、质量、规划 | 10 |
| LiteratureAgent | 工具使用、效率、协作 | 15 |
| ThesisAgent | 质量、规划、安全性 | 10 |
| DraftWriterAgent | 完整性、连贯性、专业性 | 10 |

### 12.2 评估流程

1. **准备测试用例**: 设计覆盖各场景的测试集
2. **执行评估**: 对每个Agent运行测试
3. **结果分析**: 计算各维度得分
4. **生成报告**: 输出评估报告和优化建议
5. **迭代优化**: 根据报告优化Agent
6. **复评验证**: 验证优化效果

### 12.3 评估频率

- **持续**: 每次提交后自动运行评估
- **定期**: 每周生成评估报告
- **重大版本**: 发布前进行全面评估

---

## 十三、总结

Agent评估是一个多维度的系统工程，需要结合：
- 定量指标（任务完成率、响应时间）
- 定性评估（输出质量、用户体验）
- 安全审查（错误处理、权限控制）
- 协作评估（多Agent配合）

建议Paper Agent系统建立完整的评估框架，持续监控和改进Agent性能。
