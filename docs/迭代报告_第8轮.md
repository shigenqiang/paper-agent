### 1.1 错误处理精细化

#### 问题识别
原有的错误日志存在误导性：
- 所有Agent失败都记录为`error`级别
- 即使有fallback恢复，仍记录`error`级别日志
- 没有区分错误类型（LLM失败、解析失败、外部API失败）

#### 解决方案
新增`ErrorClassifier`和`log_error_with_context`：

```python
# error_handler.py 新增

class ErrorType(str, Enum):
    LLM_FAILURE = "llm_failure"           # LLM调用失败
    PARSING_FAILURE = "parsing_failure"   # JSON解析失败
    EXTERNAL_API_FAILURE = "external_api_failure"  # 外部API失败
    VALIDATION_FAILURE = "validation_failure"  # 验证失败
    SYSTEM_ERROR = "system_error"          # 系统错误

def log_error_with_context(logger, error, context, recovered=True):
    """
    智能日志记录：
    - 有fallback恢复 → warning级别
    - 无fallback → error级别
    """
```

#### 效果
更新后的日志示例：
```
# 之前（误导）
ERROR    TopicAgent execution failed: LLM API Error

# 之后（清晰）
WARNING  [llm_failure] TopicAgent execution: LLM API Error (recovered=True)
```

## 二、架构说明（回应用户问题）

### 问题导向Agent vs PaperAgent

用户提问：问题导向Agent是否会多余？

**回答**：两者设计目的不同，不冗余

| Agent类型 | 用途 | 场景 |
|-----------|------|------|
| **PaperAgent (Pipeline型)** | 从零写完整论文 | 串起完整流程：选题→文献→Thesis→大纲→初稿 |
| **问题导向Agent** | 修复论文局部缺陷 | 单独使用：诊断→定位问题→针对性修复 |

**协作模式**：
```
场景1: 新论文写作
PaperAgent Pipeline (完整流程)
  └─ TopicAgent → LiteratureAgent → ThesisAgent → OutlineAgent → DraftWriterAgent

场景2: 论文局部改进
问题导向Agent (按需调用)
  └─ DiscussionDeepenerAgent (讨论部分不够深入)
  └─ LanguagePolisherAgent (语言需要润色)
  └─ ChartFormatterAgent (图表格式问题)
```
