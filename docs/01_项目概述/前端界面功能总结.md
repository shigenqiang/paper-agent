```
│  │  │ [删除]   │  │                                │  │ 暂无引用     │  │ │
│  │  │          │  │  开始写作...                    │  │              │  │ │
│  │  │ 📄 第1章 │  │  或点击上方「修正格式」         │  │ [添加引用]   │  │ │
│  │  │   ├ 1.1←│  │  让AI帮您生成内容               │  │              │  │ │
│  │  │   ├ 1.2 │  │                                │  │              │  │ │
│  │  │   └ 1.3 │  │  (双栏模式左编辑右预览)          │  │              │  │ │
│  │  │ 📄 第2章 │  │                                │  │              │  │ │

│  │  │ 📚 引用管理 [APA ▼] │ [文献1] [文献2] ...                      [+添加引用] │ │ │
│  │  └───────────────────────────────────────────────────────────────────┘  │ │
│  └────────────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

**功能列表**：
- **顶部工具栏**（三区布局）：
  - 左侧：论文选择下拉、标题编辑、保存状态标签
  - 中间：保存按钮、上传按钮、**修正格式**按钮（蓝紫渐变背景）
  - 右侧：编辑模式切换（编辑/预览/双栏/全文）、全屏按钮
- **四栏编辑模式**：
  - **编辑模式**：纯文本编辑
  - **预览模式**：纯Markdown渲染
  - **双栏模式**：左编辑右预览，同步滚动
  - **全文模式**：编辑全部章节内容
- **三栏布局**：
  - 左侧：论文大纲树形结构（蓝色渐变标题，卡片式设计）
  - 中间：富文本编辑区，标题栏显示章节名和字数
  - 右侧：引用管理面板（紫色渐变标题）
- **底部引用管理**：横条设计，支持引用标签显示、复制、删除
- **快捷键支持**：Ctrl+S 保存、Ctrl+Enter AI修正格式
- **自动保存**：30秒间隔自动保存，状态指示
- **字数统计**：实时显示当前章节和总字数
- **全屏模式**：支持全屏写作
- **文件上传**：支持 PDF、Markdown(.md)、TXT、DOCX 格式（UploadPaperModal 组件）
- **Markdown支持**：支持数学公式（KaTeX）、代码高亮
- **Zustand 持久化**：writingStore 存储编辑状态（selectedSection, sectionContent, paperTitle, editorMode等）

**状态持久化 Store**：
| Store | 存储内容 |
|-------|---------|
| projectStore | 项目信息（sections, citations, status） |
| writingStore | 编辑状态（当前章节、编辑模式、引用格式等） |
| literatureStore | 文献库数据 |
| uiStore | UI状态（侧边栏折叠、主题） |
| chatStore | AI对话历史 |

## 前端持久化机制

### Zustand Store 架构

| Store | 文件 | 持久化 Key | 存储内容 |
|-------|------|-----------|---------|
| projectStore | src/store/projectStore.js | paper-project-storage | 项目信息、章节、引用 |
| writingStore | src/store/writingStore.js | paper-writing-storage | 编辑状态、选中章节、编辑器模式 |
| literatureStore | src/store/literatureStore.js | paper-literature-storage | 文献库数据 |
| uiStore | src/store/uiStore.js | paper-ui-storage | 侧边栏折叠、主题设置 |
| chatStore | src/store/chatStore.js | paper-chat-storage | AI对话消息历史 |

### 持久化策略

1. **projectStore** - 使用 `zustand/middleware` 的 `persist` 中间件
   - 存储：project (sections, citations, title, status)
   - 刷新后恢复当前编辑的论文和章节内容

2. **writingStore** - 独立编辑状态管理
   - 存储：selectedSection, sectionContent, paperTitle, editorMode, citeStyle
   - 刷新后恢复当前编辑位置和模式

3. **literatureStore** - 文献库持久化
   - 存储：添加的文献信息
   - 刷新后保留文献库

4. **uiStore** - UI状态持久化
   - 存储：sidebarCollapsed, theme
   - 刷新后保留导航栏状态和主题选择

5. **chatStore** - 对话历史持久化
   - 存储：messages 数组
   - 限制消息数量避免存储过大

### 数据流转

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  API Server  │────▶│  Zustand     │────▶│  React       │
│  (Backend)   │     │  Stores      │     │  Components  │
└──────────────┘     └──────────────┘     └──────────────┘
                           │
                           ▼
                    ┌──────────────┐
                    │  LocalStorage │
                    │  (persist)   │
                    └──────────────┘
```

- 页面加载时从 LocalStorage 恢复状态
- 用户操作时更新 Zustand Store
- Store 变化自动同步到 LocalStorage
- 切换论文时从 API 拉取新数据并更新 Store

## 三、问题分析

### 3.1 架构层面问题（P0优先级）

#### 问题1：KnowledgeGraphPage 组件过大（1559行）
**严重程度**：P0  
**影响范围**：可维护性、代码复用性

**问题详情**：
- 单一组件承担了图谱渲染、数据处理、交互逻辑、UI状态管理、API调用等多种职责
- D3.js 渲染逻辑与业务逻辑混杂
- 难以进行单元测试和并行开发

**竞品对比**：
- ChatGPT：组件拆分粒度细，单个组件不超过300行
- Claude：Artifacts功能独立组件实现

**改进方案**：
拆分为5个子组件：
```
KnowledgeGraphPage/
├── index.jsx                    # 主入口（~100行）
├── GraphVisualization.jsx        # D3渲染（~400行）
├── GraphControls.jsx             # 控制面板（~200行）
├── GraphSidebar.jsx             # 侧边详情（~300行）
├── GraphFilters.jsx             # 过滤器（~200行）
└── hooks/
    ├── useGraphData.js          # 数据获取
    ├── useGraphLayout.js        # 布局算法
    └── useGraphInteraction.js   # 交互处理
```

#### 问题2：WritingPage 组件过大（1137行）
**严重程度**：P0  
**影响范围**：可维护性、开发效率

**改进方案**：
拆分为4个子组件：
```
WritingPage/
├── index.jsx                    # 主入口
├── Editor/
│   ├── SectionEditor.jsx        # 章节编辑器（~300行）
```

#### 问题3：paperStore 职责过多
**严重程度**：P0  
**影响范围**：状态管理清晰度、持久化策略

**问题详情**：
单一store承担6种职责：
1. 项目管理（project, sections, citations）
2. 消息管理（messages, isStreaming）
3. 文献管理（literature）
4. UI状态（sidebarCollapsed, theme）

拆分为3个独立store：

```javascript
// store/projectStore.js - 项目管理
export const useProjectStore = create(persist(...))

// store/chatStore.js - 对话消息

export const useLiteratureStore = create(persist(...))

// store/uiStore.js - UI状态
export const useUIStore = create(persist(...))
```

### 3.2 代码质量问题（P1优先级）

#### 问题4：DEFAULT_SECTIONS 代码重复
**严重程度**：P1  
**出现位置**：
- `store/paperStore.js:4-16`
- `pages/WritingPage.jsx`（约200行）
- `pages/OutlinePage.jsx`（约30行）

**改进方案**：
```javascript
// constants/paper.js
```

```jsx
// components/common/ErrorBoundary.jsx
class ErrorBoundary extends React.Component {
  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, errorInfo) {
    console.error('ErrorBoundary caught:', error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      return <Result status="error" title="页面出现错误" />;
    }
    return this.props.children;
  }
}
```
